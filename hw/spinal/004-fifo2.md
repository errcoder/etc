특히 이 부분이 잘못되었습니다.

```scala

dut.clockDomain.waitSampling()

```

제가 이 코드를 검증 없이 제시한 것이 잘못입니다. 이번에는 왜 실패했는지 정확히 짚고, **SpinalHDL 1.15.0 / Release 34 기준으로 안전한 테스트벤치**로 고치겠습니다. 

---

# 1. 왜 `write A`가 실제로 수행되지 않았는가?

로그를 다시 보면:

```text
Initial              empty=true full=false readData=0x00
After write A        empty=true full=false readData=0x00
```

`A`를 썼다면 최소한:

```text
empty = false
```

가 되어야 합니다.

그런데 그대로:

```text
empty = true
```

입니다.

즉 FIFO 내부에서 실제로:

```scala
doWrite
```

가 `true`가 되지 않았습니다.

---

# 2. 문제의 핵심은 이 순서입니다

우리가 작성한 테스트벤치는:

```scala
dut.io.write #= true

dut.clockDomain.waitSampling()

dut.io.write #= false
```

였습니다.

여기서 제가 놓친 것이 있습니다.

SpinalSim은 일반적인 "Scala 코드가 clock edge를 정확히 지나간 다음 다음 줄을 실행한다"라고 단순하게 생각하면 안 됩니다.

SpinalSim의 simulation engine은 event-driven 방식으로 동작하고, DUT에 대한 `#=` write도 simulation command buffer를 통해 처리됩니다. 따라서 clock sampling 시점과 testbench의 signal assignment 사이의 **delta-cycle/event ordering**을 고려해야 합니다. [spinalhdl.github.io](https://spinalhdl.github.io/SpinalDoc-RTD/master/SpinalHDL/Simulation/engine.html?utm_source=chatgpt.com)

---

# 3. 특히 `#=`는 즉시 HDL signal을 물리적으로 바꾸는 것처럼 생각하면 안 됩니다

예를 들어:

```scala
dut.io.write #= true
```

를 했다고 해서 Scala 코드 관점에서 즉시 DUT의 `write`가 확정적으로 `1`이 되어 clock edge를 통과했다고 생각하면 위험합니다.

그리고:

```scala
dut.clockDomain.waitSampling()
```

은 문서상 **ClockDomain이 sampling을 수행할 때까지 기다리는 것**입니다. [spinalhdl.github.io](https://spinalhdl.github.io/SpinalDoc-RTD/master/SpinalHDL/Simulation/clock.html?utm_source=chatgpt.com)

문제는 그 sampling event 주변에서:

```scala
dut.io.write #= false
```

를 바로 실행하는 것입니다.

즉 제가 테스트벤치에서:

```text
write = 1
   ↓
waitSampling()
   ↓
write = 0
```

를 너무 낙관적으로 작성했습니다.

---

# 4. 이게 왜 치명적인가?

FIFO의 실제 하드웨어 코드는:

```scala
val doWrite =
  io.write && !io.full

when(doWrite) {
  mem(writePtr) := io.writeData
  ...
}
```

입니다.

우리가 원하는 것은 clock edge에서:

```text
write = 1
full  = 0
```

을 보는 것입니다.

그러면:

```text
doWrite = 1
```

이 되고:

```text
count = count + 1
```

이 되어야 합니다.

그런데 testbench scheduling 때문에 DUT가 해당 sampling에서 `write = 0`을 보게 되면:

```text
doWrite = 0
```

이고:

```text
count = 0
```

그대로입니다.

그러니:

```text
empty = true
```

가 유지됩니다.

---

# 5. 어떻게 고쳐야 하는가?

가장 간단하고 명확한 방법은 **입력 stimulus와 clock edge를 분리해서 생각하는 것**입니다.

예를 들어:

```text
        falling edge
             │
             ▼
write = 1 ──────────────
             │
             │
             ▼
        rising edge
             │
             ▼
        FIFO samples
             │
             ▼
        write 처리
             │
             ▼
        falling edge
             │
             ▼
write = 0
```

즉 **write를 sampling edge까지 확실하게 유지한 후 내려야 합니다.**

---

# 6. 안전한 `writeOne()` helper를 만들겠습니다

이렇게 만들겠습니다.

```scala
def writeOne(data: Int): Unit = {

  dut.io.writeData #= data
  dut.io.write     #= true

  // FIFO가 write=1인 상태로 sampling하도록 한다.
  dut.clockDomain.waitSampling()

  // sampling 이후 충분히 진행시킨다.
  dut.clockDomain.waitFallingEdge()

  // 이제 write를 내린다.
  dut.io.write #= false
}
```

핵심은:

```scala
waitSampling()
```

직후에 바로:

```scala
#= false
```

하지 않는 것입니다.

---

# 7. Read도 같은 방식으로 작성하겠습니다

```scala
def readOne(): Unit = {

  dut.io.read #= true

  dut.clockDomain.waitSampling()

  dut.clockDomain.waitFallingEdge()

  dut.io.read #= false
}
```

이렇게 하면 read도 명확하게 한 sampling 동안 유지됩니다.

---

# 8. 그런데 여기서 또 하나

현재 `readData`는:

```scala
io.readData := mem(readPtr)
```

입니다.

따라서 현재 구조에서는 **read 직전의 `readData`를 검사하고 read를 발생시키는 방식**이 가장 명확합니다.

즉:

```text
현재 readData = A
       │
       ▼
read = 1
       │
       ▼
clock edge
       │
       ▼
readPtr 증가
```

입니다.

# 9. 수정된 기본 FIFO Simulation

이제 처음부터 다시 작성하겠습니다.

```scala
import spinal.core._
import spinal.core.sim._

object SimpleFifoSim extends App {

  SimConfig
    .withWave
    .doSim(
      SimpleFifo(
        dataWidth = 8,
        depth = 4
      )
    ) { dut =>

      // --------------------------------------------------------
      // Initial stimulus
      // --------------------------------------------------------

      dut.io.write     #= false
      dut.io.writeData #= 0
      dut.io.read      #= false

      dut.clockDomain.forkStimulus(10)

      // --------------------------------------------------------
      // Helper functions
      // --------------------------------------------------------

      def printStatus(name: String): Unit = {

        println(
          f"$name%-20s " +
          f"empty=${dut.io.empty.toBoolean} " +
          f"full=${dut.io.full.toBoolean} " +
          f"readData=0x${dut.io.readData.toBigInt}%02X"
        )
      }

      def writeOne(data: Int): Unit = {

        dut.io.writeData #= data
        dut.io.write     #= true

        // Write request is sampled here.
        dut.clockDomain.waitSampling()

        // Allow the sequential logic and
        // combinational outputs to settle.
        dut.clockDomain.waitFallingEdge()

        dut.io.write #= false
      }

      def readOne(): Unit = {

        dut.io.read #= true

        // Read request is sampled here.
        dut.clockDomain.waitSampling()

        // Allow state changes to settle.
        dut.clockDomain.waitFallingEdge()

        dut.io.read #= false
      }

      // --------------------------------------------------------
      // Initial state
      // --------------------------------------------------------

      dut.clockDomain.waitSampling()
      dut.clockDomain.waitFallingEdge()

      printStatus("Initial")

      assert(
        dut.io.empty.toBoolean,
        "FIFO must be empty initially"
      )

      assert(
        !dut.io.full.toBoolean,
        "FIFO must not be full initially"
      )

      // --------------------------------------------------------
      // Write A
      // --------------------------------------------------------

      writeOne(0x41)

      printStatus("After write A")

      assert(
        !dut.io.empty.toBoolean,
        "FIFO should not be empty after writing A"
      )

      // --------------------------------------------------------
      // Write B
      // --------------------------------------------------------

      writeOne(0x42)

      printStatus("After write B")

      // --------------------------------------------------------
      // Write C
      // --------------------------------------------------------

      writeOne(0x43)

      printStatus("After write C")

      // --------------------------------------------------------
      // Read A
      // --------------------------------------------------------

      assert(
        dut.io.readData.toBigInt == 0x41,
        "First FIFO data must be A"
      )

      readOne()

      printStatus("After read A")

      // --------------------------------------------------------
      // Read B
      // --------------------------------------------------------

      assert(
        dut.io.readData.toBigInt == 0x42,
        "Second FIFO data must be B"
      )

      readOne()

      printStatus("After read B")

      // --------------------------------------------------------
      // Read C
      // --------------------------------------------------------

      assert(
        dut.io.readData.toBigInt == 0x43,
        "Third FIFO data must be C"
      )

      readOne()

      printStatus("After read C")

      // --------------------------------------------------------
      // FIFO should be empty
      // --------------------------------------------------------

      assert(
        dut.io.empty.toBoolean,
        "FIFO must be empty after reading all data"
      )

      assert(
        !dut.io.full.toBoolean,
        "FIFO must not be full"
      )

      println()
      println("Basic FIFO test passed.")
    }
}
```

# 11. 그런데 제가 여기서 한 가지 더 개선하겠습니다

이번 문제를 계기로 앞으로 simulation 코드를 작성할 때 다음 원칙을 적용하겠습니다.

### ❌ 피할 패턴

```scala
signal #= true
waitSampling()
signal #= false
```

이것을 **무조건 잘못된 코드라고 할 수는 없지만**, 지금처럼 clocked DUT의 sampling과 결과 관찰을 동시에 다루는 학습용 코드에서는 event ordering을 헷갈리게 만들 수 있습니다.

### ✅ 명확한 패턴

```scala
signal #= true

waitSampling()

waitFallingEdge()

signal #= false
```

그리고 결과 확인도:

```scala
waitSampling()
waitFallingEdge()

assert(...)
```

처럼 **clock edge와 결과 관찰 사이에 명확한 여유를 두겠습니다.**

SpinalHDL 문서에서도 simulation event ordering 때문에 memory read 등의 값이 실제로 사용 가능해지는 시점을 주의해야 한다고 명시하고 있습니다. [spinalhdl.github.io](https://spinalhdl.github.io/SpinalDoc-RTD/master/SpinalHDL/Simulation/signal.html?utm_source=chatgpt.com)

# 12. 그리고 이번 오류는 좋은 오류입니다

오히려 지금 이걸 발견한 것이 좋습니다.

우리는 지금 단순히:

> "FIFO 코드가 컴파일된다."

를 공부하는 게 아닙니다.

다음 세 가지를 같이 공부하고 있습니다.

```text
             FIFO 설계
                 │
       ┌─────────┴─────────┐
       ▼                   ▼
 Hardware logic        Simulation
       │                   │
       │              scheduling
       │                   │
       └─────────┬─────────┘
                 ▼
             Waveform
```

특히 **실제 RTL은 맞는데 testbench가 잘못된 경우**와 **testbench는 맞는데 RTL이 잘못된 경우**를 구분할 수 있어야 합니다.

이번 경우는 전자에 해당합니다.

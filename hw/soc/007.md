# 이제 올바른 방향

여기서 가장 중요한 것은 **VexRiscv의 plugin 시스템 안에서 bus를 연결하는 것**입니다.

`Pipeline.build()`의 순서는:

```text
IBusSimplePlugin.setup()
DBusSimplePlugin.setup()
...
IBusSimplePlugin.build()
DBusSimplePlugin.build()
...
```

이므로, **VexRiscv config의 plugin 목록에 우리 SoC 연결용 Plugin을 추가하고 그 Plugin의 `setup()`에서 IBus/DBus를 얻으면 됩니다.**

특히 현재 config 순서가:

```text

CsrPlugin
Decoder...
...
YamlPlugin
```

이므로 마지막에 우리 `SoCMemoryPlugin`을 넣으면:


이번에는 사용자가 확인해 준 로컬 커밋과 동일한 `baf7dc82f855eddaf5b0a20a6802c526f127e38`의 실제 소스를 기준으로 분석했습니다. 그리고 이전 분석에서 제가 놓친 중요한 차이를 확인했습니다.

IBus와 DBus는 생성 시점이 서로 다릅니다.

| Bus                     | 생성되는 위치                    | 생성 시점           |
| ----------------------- | -------------------------- | --------------- |
| `IBusSimplePlugin.iBus` | `IBusSimplePlugin.setup()` | Plugin setup 단계 |
| `DBusSimplePlugin.dBus` | `DBusSimplePlugin.build()` | Plugin build 단계 |

실제 소스에서 IBus 생성은 `setup()`에 있고, DBus 생성은 `build()`에 있습니다.

`Pipeline.build()`는 먼저 모든 Plugin의 `setup()`을 순서대로 실행한 뒤, 모든 Plugin의 `build()`를 다시 순서대로 실행합니다.

따라서 이번 해결책은 명확합니다.

1. SoC Plugin을 기존 CPU Plugin 목록의 맨 마지막에 추가합니다.
2. SoC Plugin의 `setup()`에서는 CSR interrupt 입력을 처리합니다.
3. SoC Plugin의 `build()`에서 IBus와 DBus를 가져옵니다. 이 시점에는 앞선 Plugin들의 `setup()`과 `build()`가 모두 실행된 상태입니다.
4. 그 안에서 ROM을 생성하고 IBus를 연결합니다.

이제 `rework`, `addPrePopTask`, 외부에서의 Plugin bus 접근은 사용하지 않습니다.

## 1. 이번 단계에서 사용할 Plugin 구조

이번에는 `SoCMemoryPlugin` 하나가 다음 작업을 담당하게 하겠습니다.

- IBus와 DBus Plugin 검색
- IBus와 DBus 방향을 내부 신호로 변경
- Instruction ROM 생성 및 연결
- 아직 구현하지 않은 DBus 메모리 인터페이스는 안전하게 비활성화
- CSR interrupt 입력을 비활성화
- Simulation waveform 관측용 debug 신호 제공

특히 `SoCMemoryPlugin.build()`에서 두 bus를 모두 획득합니다.

`DBusSimplePlugin.build()`에서 `dBus`를 생성하는 사실을 확인했기 때문에, SoC Plugin은 반드시 DBus Plugin 뒤에서 build되어야 합니다.

## 2. `SoCMemoryPlugin.scala`

핵심 구현

```
package myvexsoc

import spinal.core._
import spinal.core.sim._
import vexriscv._
import vexriscv.plugin._

class SoCMemoryPlugin(
    romBaseAddress: BigInt = BigInt("80000000", 16),
    romWordCount: Int = 16
) extends Plugin[VexRiscv] {

  // ------------------------------------------------------------
  // Simulation debug signals
  // ------------------------------------------------------------

  var debugIbusValid: Bool = null
  var debugIbusReady: Bool = null
  var debugIbusPc: UInt = null

  var debugRspValid: Bool = null
  var debugRspInst: Bits = null

  var debugDmemValid: Bool = null
  var debugDmemWr: Bool = null
  var debugDmemAddr: UInt = null
  var debugDmemData: Bits = null

  // ------------------------------------------------------------
  // Setup
  //
  // This plugin must be placed AFTER CsrPlugin.
  // CsrPlugin.setup() has already created these signals.
  // ------------------------------------------------------------

  override def setup(pipeline: VexRiscv): Unit = {

    val csrPlugin = pipeline.plugins.collectFirst {
      case p: CsrPlugin => p
    }.getOrElse {
      throw new IllegalStateException(
        "SoCMemoryPlugin requires CsrPlugin"
      )
    }

    // These are CPU input ports.
    // Convert them into internal signals and tie them low.

    csrPlugin.timerInterrupt.setAsDirectionLess()
    csrPlugin.externalInterrupt.setAsDirectionLess()
    csrPlugin.softwareInterrupt.setAsDirectionLess()

    csrPlugin.timerInterrupt := False
    csrPlugin.externalInterrupt := False
    csrPlugin.softwareInterrupt := False
  }

  // ------------------------------------------------------------
  // Build
  //
  // Pipeline.build() executes plugin builds in list order.
  // This plugin must be LAST in the plugin list.
  //
  // At this point:
  //   IBusSimplePlugin.setup() has created iBus.
  //   DBusSimplePlugin.build() has created dBus.
  // ------------------------------------------------------------

  override def build(pipeline: VexRiscv): Unit = {

    // ----------------------------------------------------------
    // Find bus plugins
    // ----------------------------------------------------------

    val iBusPlugin = pipeline.plugins.collectFirst {
      case p: IBusSimplePlugin => p
    }.getOrElse {
      throw new IllegalStateException(
        "SoCMemoryPlugin requires IBusSimplePlugin"
      )
    }

    val dBusPlugin = pipeline.plugins.collectFirst {
      case p: DBusSimplePlugin => p
    }.getOrElse {
      throw new IllegalStateException(
        "SoCMemoryPlugin requires DBusSimplePlugin"
      )
    }

    // ----------------------------------------------------------
    // Verify lifecycle
    // ----------------------------------------------------------

    require(
      iBusPlugin.iBus != null,
      "IBusSimplePlugin.iBus is null. Check plugin ordering."
    )

    require(
      dBusPlugin.dBus != null,
      "DBusSimplePlugin.dBus is null. SoCMemoryPlugin must be last."
    )

    val iBus = iBusPlugin.iBus
    val dBus = dBusPlugin.dBus

    // ----------------------------------------------------------
    // Convert plugin buses into internal signals
    // ----------------------------------------------------------

    iBus.setAsDirectionLess()
    dBus.setAsDirectionLess()

    // ----------------------------------------------------------
    // Instruction ROM
    // ----------------------------------------------------------

    val rom = new InstructionRom(
      baseAddress = romBaseAddress,
      wordCount = romWordCount
    )

    // ----------------------------------------------------------
    // IBus -> Instruction ROM
    // ----------------------------------------------------------

    rom.io.cmdValid := iBus.cmd.valid
    rom.io.cmdPc := iBus.cmd.pc

    iBus.cmd.ready := rom.io.cmdReady

    iBus.rsp.valid := rom.io.rspValid
    iBus.rsp.error := rom.io.rspError
    iBus.rsp.inst := rom.io.rspInst

    // ----------------------------------------------------------
    // DBus
    //
    // RAM has not been implemented yet.
    //
    // Do not accept data requests and silently discard them.
    // Any load/store will remain stalled until RAM is added.
    // ----------------------------------------------------------

    dBus.cmd.ready := False

    dBus.rsp.ready := False
    dBus.rsp.error := False
    dBus.rsp.data := B(0, 32 bits)

    // ----------------------------------------------------------
    // Debug signals
    // ----------------------------------------------------------

    debugIbusValid = Bool().setName("debugIbusValid").simPublic()
    debugIbusReady = Bool().setName("debugIbusReady").simPublic()
    debugIbusPc = UInt(32 bits).setName("debugIbusPc").simPublic()

    debugRspValid = Bool().setName("debugRspValid").simPublic()
    debugRspInst = Bits(32 bits).setName("debugRspInst").simPublic()

    debugDmemValid = Bool().setName("debugDmemValid").simPublic()
    debugDmemWr = Bool().setName("debugDmemWr").simPublic()
    debugDmemAddr = UInt(32 bits).setName("debugDmemAddr").simPublic()
    debugDmemData = Bits(32 bits).setName("debugDmemData").simPublic()

    debugIbusValid := iBus.cmd.valid
    debugIbusReady := iBus.cmd.ready
    debugIbusPc := iBus.cmd.pc

    debugRspValid := iBus.rsp.valid
    debugRspInst := iBus.rsp.inst

    debugDmemValid := dBus.cmd.valid
    debugDmemWr := dBus.cmd.wr
    debugDmemAddr := dBus.cmd.address
    debugDmemData := dBus.cmd.data
  }
}
```

### DBus response 방향에 관한 중요한 정정

이번에는 실제 `DBusSimpleBus` 정의를 기준으로 처리했습니다.

`DBusSimpleBus.asMaster()`는 `master(cmd)`와 `slave(rsp)`를 사용하고, `DBusSimpleRsp.asMaster()`는 `ready`, `error`, `data`를 출력으로 정의합니다. 따라서 CPU 입장에서 이 response 신호들은 메모리 측에서 CPU로 들어오는 입력입니다.

그러므로 다음 세 신호를 모두 메모리 측에서 구동해야 합니다.

```
dBus.rsp.ready := False
dBus.rsp.error := False
dBus.rsp.data := B(0, 32 bits)
```

특히 `rsp.ready`는 CPU의 출력이 아닙니다. 앞서 제가 반대로 설명했던 부분을 바로잡습니다.

## 3. `InstructionRom.scala`

ROM은 1-cycle synchronous response로 구현합니다.

```
package myvexsoc

import spinal.core._

class InstructionRom(
    baseAddress: BigInt = BigInt("80000000", 16),
    wordCount: Int = 16
) extends Component {

  require(wordCount >= 4)
  require((wordCount & (wordCount - 1)) == 0)
  require(baseAddress >= 0)
  require(
    baseAddress + wordCount * 4 < (BigInt(1) << 32),
    "ROM address range exceeds 32-bit address space"
  )

  val io = new Bundle {
    val cmdValid = in Bool()
    val cmdReady = out Bool()
    val cmdPc = in UInt(32 bits)

    val rspValid = out Bool()
    val rspError = out Bool()
    val rspInst = out Bits(32 bits)
  }

  // ------------------------------------------------------------
  // ROM contents
  // ------------------------------------------------------------

  val rom = Vec(Bits(32 bits), wordCount)

  val program = Seq(
    BigInt("00100093", 16), // ADDI x1, x0, 1
    BigInt("00200113", 16), // ADDI x2, x0, 2
    BigInt("002081B3", 16), // ADD  x3, x1, x2
    BigInt("0000006F", 16)  // JAL  x0, 0
  )

  for (i <- 0 until wordCount) {
    val instruction =
      if (i < program.length) program(i)
      else BigInt("00000013", 16) // NOP

    rom(i) := B(instruction, 32 bits)
  }

  // ------------------------------------------------------------
  // Command
  // ------------------------------------------------------------

  io.cmdReady := True

  val cmdFire = io.cmdValid && io.cmdReady

  // ------------------------------------------------------------
  // Address decode
  // ------------------------------------------------------------

  val base = U(baseAddress, 32 bits)
  val limit = U(baseAddress + wordCount * 4, 32 bits)

  val addressInRange =
    io.cmdPc >= base && io.cmdPc < limit

  val wordIndex =
    ((io.cmdPc - base) >> 2).resize(log2Up(wordCount))

  val instruction = Bits(32 bits)

  instruction := B(0x00000013L, 32 bits)

  when(addressInRange) {
    instruction := rom(wordIndex)
  }

  // ------------------------------------------------------------
  // Synchronous response
  //
  // Command accepted at cycle N.
  // Response valid at cycle N+1.
  // ------------------------------------------------------------

  io.rspValid := RegNext(cmdFire) init(False)

  io.rspInst := RegNextWhen(
    instruction,
    cmdFire
  ) init(B(0x00000013L, 32 bits))

  io.rspError := False
}
```

## 4. `VexRiscvTop.scala`

기존 CPU 설정을 유지하고, SoC Plugin을 마지막에 추가합니다.

```
package myvexsoc

import spinal.core._
import vexriscv._
import vexriscv.plugin._

class VexRiscvTop extends Component {

  // ------------------------------------------------------------
  // CPU configuration
  // ------------------------------------------------------------

  val cpuConfig = CpuConfig.smallest()

  // ------------------------------------------------------------
  // SoC memory plugin

  // IMPORTANT: append AFTER all existing CPU plugins.

    romBaseAddress = BigInt("80000000", 16),

  cpuConfig.plugins += socMemoryPlugin

  // ------------------------------------------------------------
  // CPU
  // ------------------------------------------------------------

  val cpu = new VexRiscv(cpuConfig)
```

## 5. `VexRiscvTopSim.scala`

기존 debug 출력 이름을 유지하되, 이제는 `dut.io`가 아니라 `dut.socMemoryPlugin`을 통해 내부 debug 신호를 관측합니다.

```
package myvexsoc

import spinal.core.sim._

object VexRiscvTopSim extends App {

  SimConfig
    .withWave
    .allOptimisation
    .compile(new VexRiscvTop)
    .doSim { dut =>

      dut.clockDomain.forkStimulus(period = 10)

      // ----------------------------------------------------------
      // Reset
      // ----------------------------------------------------------

      dut.clockDomain.resetSim #= true
      dut.clockDomain.waitSampling(5)
      dut.clockDomain.resetSim #= false

      println()
      println("============================================================")
      println(" VexRiscv + SoCMemoryPlugin + Instruction ROM")
      println("============================================================")
      println()

      val simulationCycles = 80

      for (cycle <- 1 to simulationCycles) {

        dut.clockDomain.waitSampling()

        val soc = dut.socMemoryPlugin

        val iBusValid = soc.debugIbusValid.toBoolean
        val iBusReady = soc.debugIbusReady.toBoolean
        val iBusPc = soc.debugIbusPc.toBigInt

        val rspValid = soc.debugRspValid.toBoolean
        val rspInst = soc.debugRspInst.toBigInt

        val dBusValid = soc.debugDmemValid.toBoolean

        if (iBusValid && iBusReady) {
          println(
            f"Cycle $cycle%3d : IBUS FETCH PC=0x$iBusPc%08X"
          )
        }

        if (rspValid) {
          println(
            f"             IBUS RSP   INST=0x$rspInst%08X"
          )
        }

        if (dBusValid) {
          val wr = soc.debugDmemWr.toBoolean
          val addr = soc.debugDmemAddr.toBigInt
          val data = soc.debugDmemData.toBigInt

          val operation = if (wr) "WRITE" else "READ "

          println(
            f"             DBUS $operation%s " +
              f"ADDR=0x$addr%08X DATA=0x$data%08X"
          )
        }
      }

      println()
      println("============================================================")
      println(s" Simulation finished after $simulationCycles cycles.")
      println("============================================================")
      println()
    }
}
```

## 6. 이번 구현에서 반드시 확인할 사항

Plugin 실행 순서

1. 모든 Plugin의 `setup()`

   IBus 생성, CSR 신호 생성 및 interrupt 처리
2. 모든 Plugin의 `build()`

   기존 IBus Plugin의 build
3. DBusSimplePlugin의 `build()`

   `dBus` 생성
4. SoCMemoryPlugin의 `build()`

   이미 생성된 IBus/DBus 획득 및 ROM 연결

실제 Pipeline.build()의 두 단계 반복 실행과 Plugin 목록 순서에 따른 구조입니다.

이번 단계의 기대 결과는 다음과 같습니다.

- Reset vector `0x80000000`에서 instruction fetch
- ROM이 1-cycle response 제공
- `ADDI x1, x0, 1` 실행
- `ADDI x2, x0, 2` 실행
- `ADD x3, x1, x2` 실행
- `JAL x0, 0`에서 반복 fetch
- DBus는 아직 RAM이 없으므로 사용하지 않음

검증 범위에 관한 주의: 이번 코드는 해당 커밋의 `Pipeline`, `Plugin`, IBus, DBus, CSR 소스와 대조해 lifecycle 및 신호 방향을 확인한 코드입니다. 제가 사용자의 로컬 프로젝트에서 직접 컴파일·시뮬레이션한 것은 아닙니다. 따라서 컴파일 성공이나 실행 성공을 이미 확인했다고 주장하지 않겠습니다.

이제 가장 중요한 것은 `iBus`와 `dBus`를 가져오는 시점이 올바른 위치로 이동했다는 점입니다. 이번 구현에서는 `iBus`뿐 아니라 이전에 놓쳤던 `dBus`의 생성 시점까지 반영했습니다.

---

---

이 오류는 앞서 작성한 `SoCMemoryPlugin`의 IBus/DBus 연결 단계에서 발생한 것이 아닙니다. 로그상 실패 지점은 `CsrPlugin.build()` 내부의 `StreamFifoLowLatency` 초기화입니다.

특히 다음 부분이 핵심입니다.

```
Try to set initial value of a data that is not a register
(toplevel/[VexRiscv]/[StreamFifoLowLatency]/??? : Bits[2 bits])

at vexriscv.plugin.CsrPlugin$$anon$18.<init>(CsrPlugin.scala:980)
```

즉, `CsrPlugin.scala:980`에서 2비트 `Bits` 신호에 초기값을 설정하려 했지만, SpinalHDL은 그 신호를 레지스터가 아닌 일반 조합 신호로 판단했습니다. 이 문제를 ROM이나 버스 연결 수정으로 우회하면 안 됩니다. 먼저 해당 초기화 코드와 FIFO 생성 경로를 확인해야 합니다.

다만, 현재 확인한 upstream `baf7dc82...`의 `CsrPlugin.scala`에는 `StreamFifoLowLatency`라는 이름이 직접 등장하지 않습니다. 따라서 지금 단계에서 “CsrPlugin 코드의 특정 초기화가 잘못됐다”고 단정할 수는 없습니다. 실제 로컬 소스와 컴파일에 사용된 SpinalHDL 라이브러리 조합을 대조해야 합니다.

아래 세 가지 결과를 보내 주세요.

1\. 로컬 `CsrPlugin.scala`의 오류 발생 줄 확인

```
nl -ba ext/VexRiscv/src/main/scala/vexriscv/plugin/CsrPlugin.scala | sed -n '960,990p'
```

2\. `StreamFifoLowLatency`가 어디서 생성되는지 검색

```
grep -R -n "StreamFifoLowLatency" ext/VexRiscv src
```

검색 결과가 없다면 그것도 중요한 단서입니다.

3\. 실제 의존성 버전 확인

```
sbt evicted
```

특히 `spinalhdl-core`와 `spinalhdl-lib`가 모두 같은 버전으로 해석되는지 확인해야 합니다.

현재까지 확인된 사실은 다음과 같습니다.

- 오류는 ROM의 명령어 내용이나 IBus 주소 계산에서 발생한 것이 아닙니다.
- `SoCMemoryPlugin`의 DBus 응답 연결도 이 오류의 직접적인 원인으로 보이지 않습니다.
- 오류 내부의 `Bits[2 bits]`가 어떤 FIFO 신호인지, 그리고 왜 레지스터가 아닌 신호에 초기값이 설정되는지 아직 특정되지 않았습니다.
- upstream 소스의 줄 번호와 로컬 오류의 줄 번호가 일치하는지도 확인해야 합니다.

지금은 코드를 수정하지 말아 주세요. 위 세 가지 결과를 보면 VexRiscv 소스 문제인지, SpinalHDL core/lib 버전 충돌인지, 특정 플러그인의 FIFO 생성 문제인지 범위를 좁혀서 수정할 수 있습니다.

---

---

가능성은 있지만, Scala 2.13 자체가 이번 오류의 직접 원인일 가능성은 낮습니다. 다만 VexRiscv와 SpinalHDL을 어떤 Scala 버전 및 라이브러리 버전 조합으로 빌드했는지는 반드시 확인해야 합니다.

구분해야 할 점이 있습니다.

- `scalaVersion := "2.13.x"`: Scala 컴파일러와 표준 라이브러리 버전
- `spinalhdl-core`, `spinalhdl-lib`: SpinalHDL 구현 버전
- VexRiscv 소스: 특정 SpinalHDL API 및 동작을 전제로 작성된 코드

현재 오류는 Scala 문법이나 타입 호환성 오류가 아니라, SpinalHDL의 elaboration 과정에서 레지스터가 아닌 신호에 초기값을 설정하려 했다는 오류입니다. 따라서 Scala 2.13만 2.12로 바꾸면 해결된다고 볼 근거는 아직 없습니다.

확인해 보니 중요한 근거가 있습니다. 사용 중인 VexRiscv 커밋 `baf7dc82f855eddaf5b0a20a6802c526f127e38`의 `build.sbt`에는 다음과 같이 명시되어 있습니다.

```
crossScalaVersions := Seq("2.12.18", "2.13.18")
scalaVersion       := "2.12.18"
val spinalVersion  = "1.13.0"
```

즉, 이 커밋은 Scala 2.13.18도 공식적인 교차 빌드 대상으로 설정해 놓았습니다. 기본값이 2.12.18일 뿐, 2.13이 지원되지 않는 것은 아닙니다.

또한 SpinalHDL 1.13.0 라이브러리도 Scala 2.13용 아티팩트를 제공합니다.

다만 한 가지는 주목할 만합니다. VexRiscv 저장소의 기본 Scala 버전은 2.12.18입니다. 따라서 2.13.18은 지원 대상이지만, 기본 개발 환경은 2.12.18이라고 볼 수 있습니다.

제안하는 순서는 다음과 같습니다.

1. 현재 `build.sbt`에서 Scala 버전과 SpinalHDL 의존성 버전을 확인합니다.
2. 임시로 Scala 2.12.18로 바꿔 동일한 코드를 실행합니다.
3. 결과를 비교합니다.

- 2.12.18에서 성공한다면 Scala 버전 또는 해당 버전에서 선택된 의존성 조합을 의심할 근거가 생깁니다.
- 똑같은 오류가 발생한다면 Scala 버전보다는 SpinalHDL과 VexRiscv의 elaboration 호환성 또는 플러그인 구성 문제를 더 깊게 조사해야 합니다.

제 판단은 Scala 2.12.18로 비교 테스트는 해볼 가치가 있지만, 지금 당장 2.13을 문제의 원인으로 확정하거나 프로젝트 전체를 변경할 이유는 없다는 것입니다.

현재 사용 중인 `build.sbt`를 보여 주시면, Scala 버전뿐 아니라 SpinalHDL core/lib/compiler plugin까지 서로 일치하는지 먼저 확인하겠습니다.

---

---

확인했습니다. 이 설정을 보면 Scala 2.13.18 자체를 원인으로 지목할 이유는 없습니다. VexRiscv의 해당 커밋은 Scala 2.13.18을 교차 빌드 대상으로 지원합니다.

대신 현재 `build.sbt`에서 한 가지 확인할 부분이 있습니다.

SpinalHDL compiler plugin 의존성이 빠져 있습니다.

현재는 `spinalhdl-core`와 `spinalhdl-lib`만 추가되어 있는데, SpinalHDL 프로젝트에서는 일반적으로 `spinalhdl-idsl-plugin`도 Scala 컴파일러 플러그인으로 함께 설정합니다. 이 부분은 Scala 버전과 별개의 빌드 설정입니다.

다음처럼 수정하는 것을 권합니다.

ThisBuild / scalaVersion := "2.13.18"

val spinalVersion = "1.13.0"

lazy val root = (project in file("."))\
.settings(\
name := "MyVexSoc",

```
libraryDependencies ++= Seq(
  "com.github.spinalhdl" %% "spinalhdl-core" % spinalVersion,
  "com.github.spinalhdl" %% "spinalhdl-lib" % spinalVersion,
  compilerPlugin(
    "com.github.spinalhdl" %% "spinalhdl-idsl-plugin" % spinalVersion
  ),
  "org.yaml" % "snakeyaml" % "1.8"
),

Compile / unmanagedSourceDirectories +=
  baseDirectory.value / "ext" / "VexRiscv" / "src" / "main" / "scala"
```

)

fork := true

SpinalHDL 공식 프로젝트 설정에도 `spinalhdl-idsl-plugin`을 `compilerPlugin(...)`으로 추가하는 방식이 안내되어 있습니다.&


수정 후 실행 순서

```
sbt clean
sbt update
sbt "runMain myvexsoc.VexRiscvTopSim"
```

`fork := true`도 시뮬레이션 실행 환경을 분리하기 위해 함께 넣었습니다.

중요: 이번 수정은 Scala 2.13.18을 유지하면서 SpinalHDL 컴파일 환경을 올바르게 구성하기 위한 것입니다. 이 변경만으로 앞서 발생한 초기값 오류가 반드시 해결된다고 단정하지는 않겠습니다. 실행 결과를 확인해야 합니다. 만약 동일한 오류가 남는다면, 그때는 `CsrPlugin.scala:980`의 실제 로컬 코드와 `StreamFifoLowLatency` 생성 경로를 추적하겠습니다.

다음 단계는 `mcause`를 확인해서 예외 종류에 따라 처리 경로를 나누는 Trap Handler입니다.

이번에는 기존에 무조건 복구하던 Handler에 `BNE` 조건 분기를 추가하겠습니다.

## Project: Trap Handler with Exception Check

목표는 다음과 같습니다.

1. `mcause`를 읽는다.
2. `mcause == 5`인지 확인한다.
3. Load Access Fault(`5`)이면 기존처럼 복구한다.
4. 다른 예외라면 복구하지 않고 오류 처리 루프에 진입한다.

## 1. InstructionRom 수정

기존 Main Program은 그대로 둡니다.

Trap Handler 부분만 아래와 같이 변경합니다.

| 주소           | 명령어                    | 동작                |
| ------------ | ---------------------- | ----------------- |
| `0x80000020` | `CSRRS x6, mcause, x0` | mcause 읽기         |
| `0x80000024` | `ADDI x5, x0, 5`       | 예상 예외 코드 5        |
| `0x80000028` | `BNE x6, x5, +36`      | 다르면 오류 루프로 분기     |
| `0x8000002C` | `CSRRS x7, mepc, x0`   | 원래 mepc 읽기        |
| `0x80000030` | `CSRRS x8, mtval, x0`  | mtval 읽기          |
| `0x80000034` | `SW x6, 16(x0)`        | mcause 저장         |
| `0x80000038` | `SW x7, 20(x0)`        | 원래 mepc 저장        |
| `0x8000003C` | `SW x8, 24(x0)`        | mtval 저장          |
| `0x80000040` | `ADDI x7, x7, 4`       | mepc를 다음 명령어로 변경  |
| `0x80000044` | `CSRRW x0, mepc, x7`   | 변경한 mepc 기록       |
| `0x80000048` | `MRET`                 | 복귀                |
| `0x8000004C` | `JAL x0, 0`            | 예상하지 못한 예외의 정지 루프 |

다음 명령어 인코딩을 사용합니다.

```scala
val CSRRS_X6_MCAUSE = B"x34202373"
val ADDI_X5_X0_5    = B"x00500293"
val BNE_X6_X5_36    = B"x02531263"

val CSRRS_X7_MEPC   = B"x341023F3"
val CSRRS_X8_MTVAL  = B"x34302473"

val SW_X6_16_X0     = B"x00602823"
val SW_X7_20_X0     = B"x00702A23"
val SW_X8_24_X0     = B"x00802C23"

val ADDI_X7_X7_4    = B"x00438393"
val CSRRW_MEPC_X7   = B"x34139073"
val MRET            = B"x30200073"

val JAL_X0_0        = B"x0000006F"
```

`BNE_X6_X5_36`의 분기 주소는 다음과 같습니다.
```
0x80000028 + 0x24 = 0x8000004C, where
0x24 == 36 == 9 steps x 4
```
즉, `mcause`가 5가 아니면 복구 코드에 진입하지 않습니다.

`switch(io.cmd.pc)`에는 다음 항목들을 추가하면 됩니다.

```scala
switch(io.cmd.pc) {
  // 기존 Main Program은 그대로 유지

  is(U"32'h80000020") { instruction := CSRRS_X6_MCAUSE }
  is(U"32'h80000024") { instruction := ADDI_X5_X0_5 }
  is(U"32'h80000028") { instruction := BNE_X6_X5_36 }

  is(U"32'h8000002C") { instruction := CSRRS_X7_MEPC }
  is(U"32'h80000030") { instruction := CSRRS_X8_MTVAL }

  is(U"32'h80000034") { instruction := SW_X6_16_X0 }
  is(U"32'h80000038") { instruction := SW_X7_20_X0 }
  is(U"32'h8000003C") { instruction := SW_X8_24_X0 }

  is(U"32'h80000040") { instruction := ADDI_X7_X7_4 }
  is(U"32'h80000044") { instruction := CSRRW_MEPC_X7 }
  is(U"32'h80000048") { instruction := MRET }

  is(U"32'h8000004C") { instruction := JAL_X0_0 }
}
```

ROM의 나머지 부분, 특히 IBus 응답 로직은 변경하지 마세요.

이번 시험에 맞춰 `VexRiscvTopSim.scala` 전체 코드를 제시하겠습니다.

이번 테스트의 핵심은 `mcause = 5`인데 비교값을 `6`으로 설정하여 BNE 분기를 발생시키고, CPU가 오류 루프 `0x8000004C`에 진입한 뒤 반복하는지 확인하는 것입니다.

기존 시뮬레이션의 중요한 관찰 순서인 `waitFallingEdge()` → 응답 관찰 → 명령 관찰을 유지하겠습니다.

## 1. VexRiscvTopSim.scala 전체 코드

```scala
package myvexsoc

import spinal.core._
import spinal.core.sim._
import vexriscv.plugin._

import scala.collection.mutable

object VexRiscvTopSim {

  def main(args: Array[String]): Unit = {

    SimConfig.withWave.compile(new VexRiscvTop).doSim { dut =>

      dut.clockDomain.forkStimulus(period = 10)

      // --------------------------------------------------
      // Constants
      // --------------------------------------------------

      val RAM0       = BigInt("00000000", 16)
      val RESUME_RAM = BigInt("00000008", 16)

      val MCAUSE_RAM = BigInt("00000010", 16)
      val MEPC_RAM   = BigInt("00000014", 16)
      val MTVAL_RAM  = BigInt("00000018", 16)

      val FAULT_ADDR = BigInt("20000000", 16)

      val HANDLER_BASE = BigInt("80000020", 16)
      val ERROR_LOOP   = BigInt("8000004C", 16)

      val MAX_CYCLES = 160

      // --------------------------------------------------
      // CPU Plugin
      // --------------------------------------------------

      val dbusPlugin = dut.system.cpu.plugins.collectFirst {
        case p: DBusSimplePlugin => p
      }.getOrElse {
        throw new RuntimeException("DBusSimplePlugin not found")
      }

      val rom = dut.system.instructionRom

      // --------------------------------------------------
      // Scoreboard
      // --------------------------------------------------

      val stores = mutable.Map[BigInt, BigInt]()

      var storeCount = 0
      var loadCount = 0
      var errorResponseCount = 0

      val loadAddresses = mutable.ArrayBuffer[BigInt]()

      // Instruction fetch observation
      val handlerPcCounts = mutable.Map[BigInt, Int]()

      var errorLoopFetchCount = 0

      // --------------------------------------------------
      // Simulation
      // --------------------------------------------------

      println("========================================")
      println(" VexRiscv Trap Error Path Verification")
      println("========================================")

      for (cycle <- 0 until MAX_CYCLES) {

        dut.clockDomain.waitFallingEdge()

        // ==============================================
        // 1. DBus Response
        //
        // Observe response before command.
        // DBusSimpleRsp.ready means response-valid.
        // ==============================================

        val rspValid = dbusPlugin.dBus.rsp.ready.toBoolean

        if (rspValid) {

          val rspData  = dbusPlugin.dBus.rsp.data.toBigInt
          val rspError = dbusPlugin.dBus.rsp.error.toBoolean

          if (rspError) {
            errorResponseCount += 1

            println(
              s"Cycle ${cycle + 1}%n".replace("%n", "") +
              s" : LOAD RSP data=0x${rspData.toString(16)} error=true"
            )
          }
        }

        // ==============================================
        // 2. DBus Command
        //
        // At falling edge, valid && ready represents
        // the command accepted at the preceding rising edge.
        // ==============================================

        val cmdValid = dbusPlugin.dBus.cmd.valid.toBoolean
        val cmdReady = dbusPlugin.dBus.cmd.ready.toBoolean

        if (cmdValid && cmdReady) {

          val address = dbusPlugin.dBus.cmd.address.toBigInt
          val isWrite = dbusPlugin.dBus.cmd.wr.toBoolean

          if (isWrite) {

            val data = dbusPlugin.dBus.cmd.payload.data.toBigInt
            val mask = dbusPlugin.dBus.cmd.mask.toBigInt

            storeCount += 1
            stores(address) = data

            println(
              s"Cycle ${cycle + 1} : STORE " +
              s"addr=0x${address.toString(16)} " +
              s"data=0x${data.toString(16)} " +
              s"mask=0x${mask.toString(16)}"
            )

          } else {

            loadCount += 1
            loadAddresses += address

            println(
              s"Cycle ${cycle + 1} : LOAD " +
              s"addr=0x${address.toString(16)}"
            )
          }
        }

        // ==============================================
        // 3. Instruction ROM Request PC
        //
        // Monitor accepted instruction fetch requests.
        // Do not assume sequential fetches are all
        // executed: branch prediction / pipeline
        // redirection may cause speculative fetches.
        // ==============================================

        val romValid = rom.io.cmd.valid.toBoolean
        val romReady = rom.io.cmd.ready.toBoolean

        if (romValid && romReady) {

          val pc = rom.io.cmd.pc.toBigInt

          if (pc >= HANDLER_BASE && pc <= ERROR_LOOP) {

            val count = handlerPcCounts.getOrElse(pc, 0) + 1
            handlerPcCounts(pc) = count

            if (count == 1) {
              println(
                s"Cycle ${cycle + 1} : FETCH PC=0x${pc.toString(16)}"
              )
            }

            if (pc == ERROR_LOOP) {
              errorLoopFetchCount += 1
            }
          }
        }
      }

      // --------------------------------------------------
      // Verification Result
      // --------------------------------------------------

      println()
      println("========================================")
      println(" Trap Error Path Verification Result")
      println("========================================")

      // 1. Initial RAM Store
      assert(
        stores.get(RAM0).contains(BigInt(1)),
        "RAM[0] initial Store failed"
      )

      println("[PASS] RAM[0] = 0x00000001")

      // 2. Load Access Fault
      assert(
        loadCount == 1,
        s"Expected 1 Load, got $loadCount"
      )

      assert(
        loadAddresses.head == FAULT_ADDR,
        s"Unexpected Load address: 0x${loadAddresses.head.toString(16)}"
      )

      assert(
        errorResponseCount == 1,
        s"Expected 1 error response, got $errorResponseCount"
      )

      println("[PASS] Load Access Fault request")
      println("[PASS] Load Access Fault response")

      // 3. Branch target must be fetched
      assert(
        handlerPcCounts.contains(ERROR_LOOP),
        "Error loop address 0x8000004C was not fetched"
      )

      println("[PASS] BNE branch target fetched")

      // 4. JAL x0,0 must keep fetching the same address
      assert(
        errorLoopFetchCount >= 2,
        s"Error loop did not repeat: fetch count=$errorLoopFetchCount"
      )

      println(
        s"[PASS] Error loop repeated ($errorLoopFetchCount fetches)"
      )

      // 5. No recovery-path Stores
      assert(
        !stores.contains(MCAUSE_RAM),
        "Unexpected mcause Store: recovery path may have executed"
      )

      assert(
        !stores.contains(MEPC_RAM),
        "Unexpected mepc Store: recovery path may have executed"
      )

      assert(
        !stores.contains(MTVAL_RAM),
        "Unexpected mtval Store: recovery path may have executed"
      )

      println("[PASS] No recovery CSR Stores")

      // 6. No resumed-program Store
      assert(
        !stores.contains(RESUME_RAM),
        "Unexpected resumed-program Store: CPU may have resumed"
      )

      println("[PASS] No resumed-program Store")

      // 7. Exactly one Store: initial RAM[0]
      assert(
        storeCount == 1,
        s"Expected exactly 1 Store, got $storeCount"
      )

      println("[PASS] Store count = 1")

      println()
      println("========================================")
      println(" Trap Error Path Verification PASS")
      println("========================================")
    }
  }
}
```

## 2. 중요한 수정 사항

위 코드에서 기존 검증과 달라진 점은 세 가지입니다.

① PC를 직접 관찰합니다.

```
val pc = rom.io.cmd.pc.toBigInt
```

오류 루프 주소가 실제 Instruction ROM 요청으로 나타나는지 확인합니다.

② 오류 루프 반복 횟수를 확인합니다.

```
assert(errorLoopFetchCount >= 2)
```

`0x8000004C`에서 `JAL x0, 0`이 반복 실행되는 흐름을 확인합니다.

③ 기존 복구 경로의 Store가 발생하지 않았는지 확인합니다.

```
assert(!stores.contains(MCAUSE_RAM))
assert(!stores.contains(MEPC_RAM))
assert(!stores.contains(MTVAL_RAM))
assert(!stores.contains(RESUME_RAM))
```

단순히 로그에 Store가 없다는 사실만 보는 것이 아니라 Scoreboard에 기록된 Store 주소를 검사합니다.

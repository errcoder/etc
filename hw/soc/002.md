sbt "runMain vexriscv.demo.GenSmallest"   명령어 실행으로 VexRiscv.v 파일이 생성되었다. 첨부한다.

---

첨부된 `VexRiscv.v`를 직접 확인해 보니 중요한 정보가 확인됩니다.

### 현재 상태

```text
Generator : SpinalHDL v1.13.0
Component : VexRiscv
Git hash  : baf7dc82...
```

즉, 현재 우리가 사용한 환경은 실제로:

```text
VexRiscv
   │
   └── SpinalHDL 1.13.0
          │
          └── Verilog 생성 성공
```

입니다. 따라서 **SpinalHDL 1.13.0 + 현재 VexRiscv 조합을 일단 기준 환경으로 유지**하는 것이 좋겠습니다. 굳이 1.15.0으로 바꿀 이유가 없습니다.

또한 생성된 CPU의 인터페이스를 확인하면 다음과 같습니다.

```text
             VexRiscv
                │
       ┌────────┴────────┐
       │                 │
   Instruction Bus     Data Bus
       │                 │
       │                 ├── read
       │                 └── write
       │
       └── PC / instruction
```

실제 포트는:

```text
iBus_cmd_valid
iBus_cmd_ready
iBus_cmd_payload_pc

iBus_rsp_valid
iBus_rsp_payload_error
iBus_rsp_payload_inst

dBus_cmd_valid
dBus_cmd_ready
dBus_cmd_payload_wr
dBus_cmd_payload_mask
dBus_cmd_payload_address
dBus_cmd_payload_data
dBus_cmd_payload_size

dBus_rsp_ready
dBus_rsp_error
dBus_rsp_data
```

그리고 인터럽트:

```text
timerInterrupt
externalInterrupt
softwareInterrupt
```

입니다.

이것이 상당히 중요합니다.

**우리가 이제 직접 구현해야 할 것은 CPU가 아닙니다.**

VexRiscv가 이미 다음을 가지고 있습니다.

```text
                  VexRiscv
                     │
       ┌─────────────┼─────────────┐
       │             │             │
   Instruction    Data Bus      Interrupt
      Bus
```

따라서 다음 단계부터는 이 Bus들을 실제 메모리와 연결해서 **CPU가 프로그램을 실행하도록 만드는 것**이 핵심입니다.

# 다음 단계: Project 1-2

바로 SoC 전체를 만들지는 않겠습니다.

먼저 아주 작은 테스트 환경을 만들겠습니다.

```text
             +-------------+
             |  VexRiscv   |
             +------+------+
                    |
             Instruction Bus
                    |
             +------+------+
             | Instruction |
             |    ROM      |
             +-------------+

                    +

             +-------------+
             | Data Memory |
             |    RAM      |
             +-------------+
                    |
             Data Bus
```

목표는 단 하나입니다.

> **VexRiscv가 실제 RISC-V 명령어를 Fetch하고 실행하는 것을 시뮬레이션으로 확인한다.**

그 다음에야:

```text
VexRiscv
   ↓
Bus Interconnect
   ↓
ROM / RAM
   ↓
APB
   ↓
UART / GPIO / Timer
```

로 확장하겠습니다.

### 특히 중요한 점

이번에는 **VexRiscv의 내부 RTL을 분석하면서 CPU를 다시 공부하지 않겠습니다.**

이미 Mini CPU와 5-stage CPU를 직접 만들어봤기 때문에 다음과 같은 것은 알고 있습니다.

```text
Fetch
Decode
Execute
Memory
WriteBack
Hazard
Forwarding
Branch
Stall
```

이제 그 지식을 **실제 RISC-V CPU를 SoC에 사용하는 쪽으로 전환**합니다.

```text
RiscVSoC/
├── build.sbt
├── src/
│   ├── main/scala/
│   │   └── soc/
│   │       └── VexRiscvSimTop.scala
│   │
│   └── test/scala/
│       └── soc/
│           └── VexRiscvSim.scala
│
└── ext/
    └── VexRiscv/
```

그리고 **현재 생성된 `VexRiscv.v`를 단순히 Verilog simulation으로 돌리는 것이 아니라**, 가능하면 VexRiscv의 SpinalHDL 컴포넌트를 직접 SoC Scala 코드에서 instantiate하는 방향으로 진행하겠습니다.

이렇게 해야 최종적으로

```text
Scala / SpinalHDL
       ↓
VexRiscv
       ↓
SoC
       ↓
Verilog
       ↓
Verilator
       ↓
FPGA
```

라는 하나의 자연스러운 개발 흐름이 만들어집니다.

현재 단계는 **정상 완료**로 기록하고 다음 단계로 넘어가면 됩니다.

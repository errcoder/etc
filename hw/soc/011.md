좋습니다. 이번에는 **코드를 쓰기 전에 실제 `IBusSimplePlugin`을 먼저 확인**했습니다.

현재 확인된 핵심은 다음과 같습니다.

- `IBusSimplePlugin`의 `iBus.cmd`는 `Stream`
- `iBus.rsp`는 `Flow`
- `iBus.cmd.ready`는 메모리 측에서 CPU에 반환
- `iBus.rsp.valid/inst/error`는 메모리 측에서 CPU로 반환
- 기본 `busLatencyMin`은 **1**
- 실제 plugin 내부에서도 `iBus.rsp`를 `Stream`으로 받아 내부 `StreamFifoLowLatency(..., busLatencyMin, ...)`에 넣습니다. [GitHub](https://github.com/SpinalHDL/VexRiscv/blob/master/src/main/scala/vexriscv/plugin/IBusSimplePlugin.scala?utm_source=chatgpt.com)

따라서 우리가 처음 만들 Instruction ROM은 **조합 논리로 `rsp.valid`를 즉시 올리는 방식이 아니라, 최소 1-cycle latency를 갖는 구조**로 만드는 것이 맞습니다.

### 이번 단계

먼저 CPU와 ROM 사이의 관계를 아주 작게 검증합니다.

```text
CPU
 │
 │ iBus.cmd
 │   pc = 0x80000000
 ▼
Instruction ROM
 │
 │ 1 cycle
 ▼
iBus.rsp
 │
 │ inst
 ▼
CPU
```

ROM에는 우선 **한 명령어만** 넣겠습니다.

```text
0x80000000 : ADDI x1, x0, 1
```

그리고 처음부터 `ADD`, `JAL`까지 넣지 않습니다.

**첫 번째 목표는 딱 이것입니다.**

> CPU가 reset 후 `0x80000000`에서 instruction fetch를 발생시키고, ROM이 그 주소에 대응하는 `ADDI x1,x0,1`을 1-cycle latency로 반환하는 것.

이것이 확인된 다음에 두 번째 명령어를 추가하겠습니다.

또한 현재 `DBusSimplePlugin`은 아직 그대로 tie-off 상태로 두겠습니다. 데이터 메모리까지 동시에 넣으면 문제가 발생했을 때 **instruction fetch 문제인지 data bus 문제인지 분리할 수 없기 때문**입니다.

이번에는 이 원칙대로 **Instruction ROM 하나만 먼저 구현**하는 것이 다음 단계입니다.

---

---

좋습니다. 이번 단계에서는 **실제 구현까지 한 단계만 진행**하겠습니다.

앞서 확인한 `IBusSimplePlugin` 소스상 `iBus.cmd`는 `Stream`, `iBus.rsp`는 `Flow`이고, `busLatencyMin = 1`이 기본값입니다. 또한 plugin 내부에서 `iBus.rsp`를 latency에 맞는 FIFO 경로로 처리합니다. [GitHub](https://github.com/SpinalHDL/VexRiscv/blob/master/src/main/scala/vexriscv/plugin/IBusSimplePlugin.scala?utm_source=chatgpt.com)

따라서 지금은 **Instruction ROM을 `RegNextWhen` 기반의 정확한 1-cycle response 모델로 만들겠습니다.**

그리고 CPU가 ROM 밖으로 나갔을 때 illegal instruction을 받지 않도록, 아직 구현하지 않은 영역은 RISC-V canonical NOP인 `ADDI x0,x0,0 = 0x00000013`을 반환시키겠습니다. [RISEV Documentation](https://docs.riscv.org/reference/isa/_attachments/riscv-unprivileged.pdf?utm_source=chatgpt.com)

## 1. `InstructionRom.scala`

```scala
package myvexsoc

import spinal.core._
import spinal.lib._
import vexriscv.plugin._

class InstructionRom extends Component {

  val io = new Bundle {
    val cmd = slave(Stream(IBusSimpleCmd()))
    val rsp = master(Flow(IBusSimpleRsp()))
  }

  /*
   * First test program
   *
   * 0x80000000 : ADDI x1, x0, 1
   * 0x80000004 : JAL  x0, 0
   *
   * JAL x0, 0 keeps the CPU at 0x80000004.
   */
  val ADDI_X1_X0_1 = B"x00100093"
  val JAL_X0_0     = B"x0000006F"
  val NOP           = B"x00000013"

  io.cmd.ready := True

  val instruction = Bits(32 bits)

  instruction := NOP

  switch(io.cmd.pc) {
    is(U"32'h80000000") {
      instruction := ADDI_X1_X0_1
    }

    is(U"32'h80000004") {
      instruction := JAL_X0_0
    }
  }

  /*
   * IBusSimplePlugin has busLatencyMin = 1.
   *
   * Therefore:
   *
   * cycle N     : cmd.fire
   * cycle N + 1 : rsp.valid
   */
  io.rsp.valid := RegNext(io.cmd.fire) init(False)
  io.rsp.inst  := RegNextWhen(instruction, io.cmd.fire) init(NOP)
  io.rsp.error := False
}
```

### 여기서 중요한 점

`io.cmd.ready := True`이므로:

```text
cmd.fire = cmd.valid && cmd.ready
         = cmd.valid
```

입니다.

그리고:

```scala
io.rsp.valid := RegNext(io.cmd.fire)
```

이므로 명확하게

```text
Cycle N
    cmd.valid = 1
    cmd.fire  = 1
    pc        = 0x80000000

Cycle N+1
    rsp.valid = 1
    rsp.inst  = 0x00100093
```

이라는 관계가 됩니다.

즉, 이번에는 **ROM response timing을 추측하지 않고 코드 자체로 1-cycle latency를 명시**했습니다.

# 2. `VexRiscvTop.scala`

기존의 IBus tie-off를 제거하고 ROM을 연결합니다.

```scala
package myvexsoc

import spinal.core._
import vexriscv._
import vexriscv.plugin._

class VexRiscvTop extends Component {

  val cpuConfig = CpuConfig.smallest()

  val system = new ClockingArea(ClockDomain.current) {

    val cpu = new VexRiscv(cpuConfig)

    val instructionRom = new InstructionRom

    val externalInterrupt = False
    val timerInterrupt = False

    for (plugin <- cpu.plugins) {
      plugin match {

        case p: IBusSimplePlugin =>
          instructionRom.io.cmd <> p.iBus.cmd
          p.iBus.rsp <> instructionRom.io.rsp

        case p: DBusSimplePlugin =>
          p.dBus.cmd.ready := False
          p.dBus.rsp.ready := False
          p.dBus.rsp.error := False
          p.dBus.rsp.data := B(0, 32 bits)

        case p: CsrPlugin =>
          p.externalInterrupt := externalInterrupt
          p.timerInterrupt := timerInterrupt

        case _ =>
      }
    }
  }
}
```

여기서 **이전과 달리 중요한 변화는 단 하나**입니다.

기존:

```scala
p.iBus.cmd.ready := False
p.iBus.rsp.valid := False
```

이었던 것을 제거하고,

```scala
instructionRom.io.cmd <> p.iBus.cmd
p.iBus.rsp <> instructionRom.io.rsp
```

으로 실제 instruction memory를 연결합니다.

Murax에서 CPU plugin의 `iBus`를 CPU 바깥의 memory/bus 쪽에 연결하는 방식과 같은 큰 구조입니다.

## `VexRiscvTop.scala`

```scala
package myvexsoc

import spinal.core._
import vexriscv._
import vexriscv.plugin._

class VexRiscvTop extends Component {

  val io = new Bundle {
    val debug = new Bundle {
      val ibusCmdValid = Bool()
      val ibusCmdReady = Bool()
      val ibusCmdFire  = Bool()
      val ibusCmdPc    = UInt(32 bits)

      val ibusRspValid = Bool()
      val ibusRspInst  = Bits(32 bits)
      val ibusRspError = Bool()
    }
  }

  val cpuConfig = CpuConfig.smallest()

  val system = new ClockingArea(ClockDomain.current) {

    val cpu = new VexRiscv(cpuConfig)

    val instructionRom = new InstructionRom

    val externalInterrupt = False
    val timerInterrupt    = False

    for (plugin <- cpu.plugins) {
      plugin match {

        case p: IBusSimplePlugin =>
          instructionRom.io.cmd <> p.iBus.cmd
          p.iBus.rsp <> instructionRom.io.rsp

          io.debug.ibusCmdValid := p.iBus.cmd.valid
          io.debug.ibusCmdReady := p.iBus.cmd.ready
          io.debug.ibusCmdFire  := p.iBus.cmd.fire
          io.debug.ibusCmdPc    := p.iBus.cmd.pc

          io.debug.ibusRspValid := p.iBus.rsp.valid
          io.debug.ibusRspInst  := p.iBus.rsp.inst
          io.debug.ibusRspError := p.iBus.rsp.error

        case p: DBusSimplePlugin =>

          p.dBus.rsp.ready := False

      }
```

즉 우리가 보는 신호가 실제 CPU IBus의 handshake입니다.

# 2. Simulation에서 실제 handshake를 검사

이제 기존 simulation의

```scala
waitSampling(30)
println("[PASS] CPU clocked for 30 additional cycles")
```

를 그대로 두면 안 됩니다.

이번에는 **각 cycle마다 IBus 상태를 읽고**, 실제 fetch가 발생하면 기록하겠습니다.

## `VexRiscvTopSim.scala`

```scala
package myvexsoc

import spinal.core._
import spinal.core.sim._

object VexRiscvTopSim extends App {

  SimConfig
    .withWave
    .compile(new VexRiscvTop)
    .doSim { dut =>

      println("========================================")
      println(" VexRiscvTop IBus Simulation Start")
      println("========================================")

      dut.clockDomain.forkStimulus(period = 10)

      dut.clockDomain.waitSampling(5)

      println("[PASS] Initial reset and clock startup")

      var commandCount  = 0
      var responseCount = 0

      for (cycle <- 1 to 30) {

        dut.clockDomain.waitSampling()

        val cmdValid = dut.io.debug.ibusCmdValid.toBoolean
        val cmdReady = dut.io.debug.ibusCmdReady.toBoolean
        val cmdFire  = dut.io.debug.ibusCmdFire.toBoolean
        val cmdPc    = dut.io.debug.ibusCmdPc.toLong

        val rspValid = dut.io.debug.ibusRspValid.toBoolean
        val rspInst  = dut.io.debug.ibusRspInst.toLong
        val rspError = dut.io.debug.ibusRspError.toBoolean

        if (cmdValid || rspValid) {
          println(
            f"Cycle $cycle%2d : " +
              f"CMD[v=$cmdValid%d r=$cmdReady%d fire=$cmdFire%d pc=0x$cmdPc%08X] " +
              f"RSP[v=$rspValid%d inst=0x$rspInst%08X err=$rspError%d]"
          )
        }

        if (cmdFire) {
          commandCount += 1
        }

        if (rspValid) {
          responseCount += 1
        }
      }

      println()
      println("========================================")
      println(s"IBus command count  = $commandCount")
      println(s"IBus response count = $responseCount")
      println("========================================")

      assert(
        commandCount > 0,
        "FAIL: CPU did not issue any IBus command"
      )

      assert(
        responseCount > 0,
        "FAIL: ROM did not return any IBus response"
      )

      println("[PASS] CPU issued IBus command")
      println("[PASS] Instruction ROM returned IBus response")

      println("========================================")
      println(" VexRiscvTop IBus Simulation Finished")
      println("========================================")
    }
}
```

```scala

val rspError = ...
```

그리고:

```scala
if (rspValid) {
  responseCount += 1
}
```

따라서 ROM이 실제 instruction response를 반환했는지 검사합니다.

입니다.

즉,

까지만 확인합니다.

## 5. 특히 확인할 출력

실행 후에는 이런 형태의 출력이 나오는 것이 중요합니다.

```text
Cycle  1 : CMD[v=1 r=1 fire=1 pc=0x80000000] RSP[v=0 ...]
Cycle  2 : CMD[...]                         RSP[v=1 inst=0x00100093 err=0]
```

**정확한 cycle 번호는 여기서 미리 단정하지 않겠습니다.**  
Reset과 VexRiscv 내부 pipeline 상태에 따라 첫 command가 나오는 시점은 실제 simulation 결과를 기준으로 봐야 합니다.

하지만 최소한 다음 관계는 확인해야 합니다.

```text
cmd.fire = 1
    ↓
instruction request 발생
    ↓
rsp.valid = 1
rsp.inst  = 0x00100093
```

그리고 이 결과를 가지고 다음 단계에서 **실제 1-cycle response 관계가 맞는지 waveform까지 대조**하겠습니다.

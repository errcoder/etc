## 1. 실행 결과

| 검증 항목        | 결과           |
| ------------ | ------------ |
| ADDI 실행      | PASS         |

| SW 실행        | PASS         |
| Store 주소     | `0x00000000` |
| Store 데이터    | `0x00000001` |
| Store 횟수     | 5회           |

특히 이 로그가 핵심입니다.

```
Cycle  5 : STORE address=0x00000000 data=0x00000001
Cycle 15 : STORE address=0x00000000 data=0x00000001
Cycle 25 : STORE address=0x00000000 data=0x00000001
```

`ADDI x1, x0, 1`의 결과가 Register File에 기록되고, 이후 `SW x1, 0(x0)`가 해당 값을 읽어 DBus에 전달했다는 것을 확인했습니다.

## 1. DBus 응답 규칙 확인

프로젝트에서 사용하는 VexRiscv 커밋 `baf7dc82...`의 `DBusSimplePlugin.scala`를 확인했습니다.

중요한 부분은 다음 코드입니다.

```
// Load 요청은 응답이 없으면 CPU가 대기
arbitration.haltItself setWhen(
  arbitration.isValid &&
  input(MEMORY_ENABLE) &&
  !input(MEMORY_STORE) &&
  (!dBus.rsp.ready || ...)
)
```

여기서 주의할 점이 있습니다.

| 신호               | 의미                  |
| ---------------- | ------------------- |
| `dBus.cmd.valid` | 메모리 요청 유효           |
| `dBus.cmd.ready` | 메모리가 요청 수락          |
| `dBus.cmd.wr`    | 1이면 Store, 0이면 Load |
| `dBus.rsp.ready` | Load 응답 데이터 유효      |
| `dBus.rsp.data`  | Load 응답 데이터         |
| `dBus.rsp.error` | 응답 오류               |

특히 `dBus.rsp.ready`는 일반적인 Stream의 ready와 다릅니다. 이 인터페이스에서는 CPU가 Load 응답을 기다리는 데 사용하는 응답 유효 신호입니다. Store는 별도의 응답을 기다리지 않습니다.

현재 두 파일을 확인했습니다. 먼저 중요한 점이 하나 있습니다.

현재 `InstructionRom.scala`는 아직 RAM 테스트용 프로그램으로 변경되지 않았습니다. 지금은 다음 세 명령어만 반복 실행합니다.

```
0x80000000 : ADDI x1, x0, 1
0x80000004 : SW   x1, 0(x0)
0x80000008 : JAL  x0, -8
```

따라서 이전에 제안한 RAM[0], RAM[1] 저장 및 Load 검증을 하려면 ROM 프로그램부터 확장해야 합니다.

또한 현재 `VexRiscvTop.scala`의 DBus는 `cmd.ready := True`로 요청만 수락하고 실제 메모리 동작은 하지 않습니다. Load 응답도 항상 비활성화되어 있습니다.

이번에는 이 구조를 실제 RAM으로 바꾸되, 먼저 DBus의 주소·쓰기 데이터·byte enable·응답 조건을 정확하게 확인하겠습니다.

## 1. DBus 인터페이스에서 확인한 중요한 사항

사용 중인 VexRiscv 커밋의 `DBusSimplePlugin.scala`를 확인했습니다.

- `cmd.ready`가 1일 때 명령이 수락됩니다.
- `cmd.wr`가 1이면 Store, 0이면 Load입니다.
- `cmd.mask`는 byte enable입니다.
- Store 데이터는 `cmd.payload.data`로 전달됩니다.
- Load는 `rsp.ready`가 1이 될 때까지 CPU가 대기합니다.

따라서 RAM은 다음과 같이 동작하도록 만들겠습니다.
```
[Store]
DBus cmd.fire       --->    RAM 쓰기

[Load]
DBus cmd.fire       --->    RAM 동기식 읽기
다음 cycle           --->    rsp.ready = 1
응답 데이터              --->     CPU Register File
```

32-bit `Mem`과 4-bit byte mask를 사용하겠습니다. SpinalHDL의 메모리 API는 32-bit 데이터에 4-bit mask를 지정하면 byte 단위 쓰기를 지원합니다.


## 2. InstructionRom.scala 수정

이번 테스트 프로그램은 총 7개 명령어입니다.

| 주소           | 명령어            | 목적          |
| ------------ | -------------- | ----------- |
| `0x80000000` | ADDI x1, x0, 1 | x1 = 1      |
| `0x80000004` | SW x1, 0(x0)   | RAM[0] = 1  |
| `0x80000008` | ADDI x2, x0, 2 | x2 = 2      |
| `0x8000000C` | SW x2, 4(x0)   | RAM[1] = 2  |
| `0x80000010` | LW x3, 0(x0)   | x3 = RAM[0] |
| `0x80000014` | SW x3, 8(x0)   | RAM[2] = 1  |
| `0x80000018` | JAL x0, 0      | 정지 반복       |

마지막 Store를 추가한 이유는 Load 결과를 다시 RAM에 기록하여 외부 DBus에서 검증하기 위해서입니다.

아래 코드로 파일 전체를 교체하세요.

```
package myvexsoc

import spinal.core._
import spinal.lib._
import vexriscv.plugin._

class InstructionRom extends Component {

  val io = new Bundle {
    val cmd = slave(Stream(IBusSimpleCmd()))
    val rsp = master(Flow(IBusSimpleRsp()))
  }

  val ADDI_X1_X0_1 = B"x00100093"
  val SW_X1_0_X0   = B"x00102023"
  val ADDI_X2_X0_2 = B"x00200113"
  val SW_X2_4_X0   = B"x00202223"
  val LW_X3_0_X0   = B"x00002183"
  val SW_X3_8_X0   = B"x00302423"
  val JAL_X0_0     = B"x0000006F"
  val NOP          = B"x00000013"

  io.cmd.ready := True

  val instruction = Bits(32 bits)
  instruction := NOP

  switch(io.cmd.pc) {
    is(U"32'h80000000") {
      instruction := ADDI_X1_X0_1
    }

    is(U"32'h80000004") {
      instruction := SW_X1_0_X0
    }

    is(U"32'h80000008") {
      instruction := ADDI_X2_X0_2
    }

    is(U"32'h8000000C") {
      instruction := SW_X2_4_X0
    }

    is(U"32'h80000010") {
      instruction := LW_X3_0_X0
    }

    is(U"32'h80000014") {
      instruction := SW_X3_8_X0
    }

    is(U"32'h80000018") {
      instruction := JAL_X0_0
    }
  }

  io.rsp.valid := RegNext(io.cmd.fire) init (False)
  io.rsp.inst  := RegNextWhen(instruction, io.cmd.fire) init (NOP)
  io.rsp.error := False
}
```

## 3. SimpleDataRam.scala 추가

새 파일 `SimpleDataRam.scala`를 생성하세요.

RAM은 256 words × 32 bits, 즉 1 KiB입니다.

주소는 byte address로 받으며, word index는 `address(9 downto 2)`로 계산합니다.

```
package myvexsoc

import spinal.core._
import spinal.lib._
import vexriscv.plugin._

class SimpleDataRam extends Component {

  val io = slave(DBusSimpleBus())

  // 256 words x 32 bits = 1 KiB
  val mem = Mem(Bits(32 bits), wordCount = 256)

  // Byte address -> word address
  val wordAddress = io.cmd.address(9 downto 2)

  // Load request
  val readEnable = io.cmd.fire && !io.cmd.wr

  // Synchronous read
  val readData = mem.readSync(
    address = wordAddress,
    enable = readEnable
  )

  // Store request with byte enable
  mem.write(
    address = wordAddress,
    data = io.cmd.payload.data,
    enable = io.cmd.fire && io.cmd.wr,
    mask = io.cmd.mask
  )

  // Accept every request
  io.cmd.ready := True

  // Load response: one cycle after accepted Load
  io.rsp.ready := RegNext(readEnable) init (False)
  io.rsp.data  := readData
  io.rsp.error := False
}
```

타이밍에서 중요한 점

`readData`와 `rsp.ready`가 모두 동일한 `readEnable`에 의해 같은 클록 에지에서 갱신됩니다.

따라서 Load 요청이 수락된 다음 cycle에:

```
rsp.ready = 1
rsp.data  = RAM read result
```

가 됩니다.

Store에는 응답을 발생시키지 않습니다.

## 4. VexRiscvTop.scala 수정

기존 `VexRiscvTop` 클래스를 다음 코드로 교체하세요. 시뮬레이션 객체는 다음 절에서 별도로 교체합니다.

```
package myvexsoc

import spinal.core._
import spinal.core.sim._
import vexriscv._
import vexriscv.plugin._

class VexRiscvTop extends Component {

  val cpuConfig = CpuConfig.smallest()

  val system = new ClockingArea(ClockDomain.current) {

    val cpu = new VexRiscv(cpuConfig)

    val instructionRom = new InstructionRom
    val dataRam        = new SimpleDataRam

    // IBus simulation visibility
    instructionRom.io.cmd.valid.simPublic()
    instructionRom.io.cmd.ready.simPublic()
    instructionRom.io.cmd.pc.simPublic()

    instructionRom.io.rsp.valid.simPublic()
    instructionRom.io.rsp.inst.simPublic()
    instructionRom.io.rsp.error.simPublic()

    val externalInterrupt = False
    val timerInterrupt    = False

    for (plugin <- cpu.plugins) {
      plugin match {

        case p: IBusSimplePlugin =>
          instructionRom.io.cmd <> p.iBus.cmd
          p.iBus.rsp <> instructionRom.io.rsp

        case p: DBusSimplePlugin =>

          // DBus simulation visibility
          p.dBus.cmd.valid.simPublic()
          p.dBus.cmd.ready.simPublic()
          p.dBus.cmd.wr.simPublic()
          p.dBus.cmd.address.simPublic()
          p.dBus.cmd.payload.data.simPublic()
          p.dBus.cmd.mask.simPublic()

          p.dBus.rsp.ready.simPublic()
          p.dBus.rsp.data.simPublic()
          p.dBus.rsp.error.simPublic()

          // Connect actual Data RAM
          dataRam.io <> p.dBus

        case p: CsrPlugin =>
          p.externalInterrupt := externalInterrupt
          p.timerInterrupt := timerInterrupt

        case _ =>
      }
    }
  }
}
```

여기서 기존의 DBus tie-off 코드는 완전히 제거했습니다.

이제 CPU의 DBus가 `SimpleDataRam`에 직접 연결됩니다.

## 5. VexRiscvTopSim.scala 교체

이제 실제 RAM의 동작을 확인하는 테스트벤치입니다.

검증 항목은 다음과 같습니다.

- Store 주소 `0x0`에 데이터 `1`
- Store 주소 `0x4`에 데이터 `2`
- Load 주소 `0x0`의 응답 데이터 `1`
- Load 결과를 Store 주소 `0x8`에 다시 기록하여 데이터 `1` 확인

기존 `object VexRiscvTopSim` 전체를 다음으로 교체하세요.

```
object VexRiscvTopSim extends App {

  import scala.collection.mutable
  import vexriscv.plugin._

  SimConfig.withWave
    .compile(new VexRiscvTop)
    .doSim { dut =>

      println("========================================")
      println(" VexRiscv Data RAM Test")
      println("========================================")

      dut.clockDomain.forkStimulus(period = 10)
      dut.clockDomain.waitSampling(5)

      println("[INFO] Reset/clock startup complete")

      val dbusPlugin = dut.system.cpu.plugins
        .collectFirst {
          case p: DBusSimplePlugin => p
        }
        .getOrElse(throw new Exception("DBusSimplePlugin not found"))

      val dbus = dbusPlugin.dBus

      val stores = mutable.Map.empty[Long, Long]

      var storeCount = 0
      var loadCount = 0
      var loadResponseCount = 0
      var loadPending = false

      for (cycle <- 1 to 100) {

        dut.clockDomain.waitFallingEdge()

        // --------------------------------
        // 1. Observe Load response
        // --------------------------------

        val rspReady = dbus.rsp.ready.toBoolean

        if (rspReady) {

          assert(
            loadPending,
            s"Unexpected Load response at cycle $cycle"
          )

          val rspData = dbus.rsp.data.toLong

          println(
            f"Cycle $cycle%3d : " +
              f"LOAD RSP data=0x$rspData%08X"
          )

          assert(
            rspData == 0x00000001L,
            f"Unexpected Load data: 0x$rspData%08X"
          )

          loadResponseCount += 1
          loadPending = false
        }

        // --------------------------------
        // 2. Observe DBus command
        // --------------------------------

        val cmdValid = dbus.cmd.valid.toBoolean
        val cmdReady = dbus.cmd.ready.toBoolean

        if (cmdValid && cmdReady) {

          val wr      = dbus.cmd.wr.toBoolean
          val address = dbus.cmd.address.toLong
          val data    = dbus.cmd.payload.data.toLong
          val mask    = dbus.cmd.mask.toInt

          if (wr) {

            storeCount += 1
            stores(address) = data

            println(
              f"Cycle $cycle%3d : " +
                f"STORE addr=0x$address%08X " +
                f"data=0x$data%08X " +
                f"mask=0x$mask%X"
            )

            assert(
              mask == 0xF,
              f"Unexpected SW byte mask: 0x$mask%X"
            )

          } else {

            loadCount += 1
            loadPending = true

            println(
              f"Cycle $cycle%3d : " +
                f"LOAD  addr=0x$address%08X"
            )

            assert(
              address == 0x00000000L,
              f"Unexpected Load address: 0x$address%08X"
            )
          }
        }
      }

      println()
      println("========================================")
      println(" Data RAM Test Result")
      println("========================================")

      assert(
        storeCount == 3,
        s"Expected 3 Stores, observed $storeCount"
      )

      assert(
        loadCount == 1,
        s"Expected 1 Load, observed $loadCount"
      )

      assert(
        loadResponseCount == 1,
        s"Expected 1 Load response, observed $loadResponseCount"
      )

      assert(
        !loadPending,
        "Load response is still pending"
      )

      assert(
        stores.getOrElse(0x00L, -1L) == 0x00000001L,
        "RAM[0] Store verification failed"
      )

      assert(
        stores.getOrElse(0x04L, -1L) == 0x00000002L,
        "RAM[1] Store verification failed"
      )

      assert(
        stores.getOrElse(0x08L, -1L) == 0x00000001L,
        "RAM[2] Store verification failed"
      )

      println("[PASS] RAM[0] = 0x00000001")
      println("[PASS] RAM[1] = 0x00000002")
      println("[PASS] RAM[2] = 0x00000001")
      println("[PASS] Load response = 0x00000001")
      println("[PASS] Store count = 3")
      println("[PASS] Load count = 1")

      println("========================================")
      println(" Data RAM Test finished")
      println("========================================")
    }
}
```

## 7. 이번 단계에서 주의할 점

이번 RAM은 SpinalHDL `Mem`을 이용한 동기식 읽기 메모리입니다. 다만 아직 초기화 파일이나 FPGA Block RAM 매핑까지 검증한 것은 아닙니다.

또한 현재 테스트는 `SW`와 `LW`만 사용합니다. `SB`, `SH`, `LB`, `LH`는 byte mask 및 sign extension을 별도로 검증해야 합니다.

먼저 위 코드를 실행해 주세요. 특히 Load 요청 이후 `rsp.ready`가 정확히 한 cycle 응답으로 발생하는지, 
그리고 `LOAD RSP data=0x00000001`이 출력되는지 확인하겠습니다. 실행 결과를 보기 전에는 RAM 연결을 PASS로 판정하지 않겠습니다.

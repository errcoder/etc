## 현재까지의 SoC 진행 상태

지금까지 상당히 중요한 지점까지 왔습니다.

```text
                 ┌──────────────┐
                 │  VexRiscv    │
                 └──────┬───────┘
                        │
             ┌──────────┴──────────┐
             │                     │
            IBus                  DBus
             │                     │
             ▼                     ▼
       Instruction ROM         Data RAM
             │                     │
             └────── CPU 실행 ───┘
```

현재 확인된 것은:

- ✅ CPU 생성
- ✅ IBus 연결
- ✅ Instruction ROM
- ✅ CPU instruction fetch
- ✅ ADDI 실행
- ✅ DBus Store
- ✅ Data RAM
- ✅ byte mask
- ✅ Sync Read
- ✅ Load response
- ✅ Load → CPU register → Store 데이터 전달

즉, 이제 **"VexRiscv CPU에 ROM/RAM을 붙여서 실제 프로그램을 실행한다"**는 기본 SoC 구조가 검증됐습니다.

```text
                DBus
                 │
                 ▼
          ┌─────────────┐
          │ DBusDecoder │
          └──────┬──────┘
                 │
          ┌──────┴──────┐
          ▼             ▼
        RAM           GPIO
      0x0000...      0x1000...
```

Decoder가 해야 할 일은 딱 세 가지입니다.

1. 주소가 RAM 영역이면 RAM에 command 전달
2. 주소가 GPIO 영역이면 GPIO에 command 전달
3. Load response는 선택된 장치에서 CPU로 되돌려 보내기

다음은 VexRiscv가 실제로 명령어를 실행하는지 검증하는 단계입니다.

이번 목표는 IBus 연결 테스트에서 한 단계 더 나아가 다음 결과를 확인하는 것입니다.

```
Instruction ROM
      |
      v
VexRiscv
      |
      v
ADDI x1, x0, 1
      |
      v
Register File: x1 = 1
```

단순히 ROM에서 `ADDI`가 응답으로 나왔다는 것과 CPU가 실제로 실행했다는 것은 다른 검증입니다. 이번에는 Register File의 실제 쓰기 동작을 확인하는 방향으로 진행하겠습니다.

이번에는 Register File을 직접 들여다보는 대신, CPU가 계산한 값을 데이터 버스로 Store하는 방식으로 검증하겠습니다.

이 방법은 `DebugPlugin`을 추가하지 않아도 CPU의 실제 연산 결과를 외부에서 확인할 수 있습니다.

VexRiscv의 `DBusSimpleCmd`에는 `wr`, `address`, `data`, `size` 필드가 있고, CPU의 Store 명령은 이 인터페이스를 통해 외부 메모리로 전달됩니다.


## 1. 테스트 프로그램 변경

`InstructionRom.scala`의 명령어를 다음과 같이 변경하세요.

테스트 프로그램

| 주소           | 명령어              | 기능             |
| ------------ | ---------------- | -------------- |
| `0x80000000` | `ADDI x1, x0, 1` | x1에 1 저장       |
| `0x80000004` | `SW x1, 0(x0)`   | x1 값을 주소 0에 저장 |
| `0x80000008` | `JAL x0, -8`     | 처음으로 돌아가 반복    |

ROM의 명령어 정의와 주소 분기를 다음처럼 바꿉니다.

```
val ADDI_X1_X0_1 = B"x00100093"
val SW_X1_0_X0   = B"x00102023"
val JAL_X0_M8    = B"xFF9FF06F"
val NOP           = B"x00000013"

io.cmd.ready := True

val instruction = Bits(32 bits)
instruction := NOP

switch(io.cmd.pc) {
  is(U"32'h80000000") {
    instruction := ADDI_X1_X0_1
  }

  is(U"32'h80000004") {
    instruction := SW_X1_0_X0
  }

  is(U"32'h80000008") {
    instruction := JAL_X0_M8
  }
}

io.rsp.valid := RegNext(io.cmd.fire) init (False)
io.rsp.inst  := RegNextWhen(instruction, io.cmd.fire) init (NOP)
io.rsp.error := False
```

반복 실행하도록 만든 이유는 테스트 시작 시점에 첫 번째 Store를 놓치더라도 이후 Store를 관찰할 수 있게 하기 위해서입니다.

## 2. VexRiscvTop의 DBus 연결 변경

기존 `case p: DBusSimplePlugin` 부분을 다음과 같이 변경하세요.

```
case p: DBusSimplePlugin =>

  // DBus 명령 관찰
  p.dBus.cmd.valid.simPublic()
  p.dBus.cmd.ready.simPublic()
  p.dBus.cmd.wr.simPublic()
  p.dBus.cmd.address.simPublic()
  p.dBus.cmd.payload.data.simPublic()

  // 외부 메모리가 모든 요청을 수락
  p.dBus.cmd.ready := True

  // 이번 테스트는 Store만 사용
  p.dBus.rsp.ready := False
  p.dBus.rsp.error := False
  p.dBus.rsp.data := B(0, 32 bits)
```

기존처럼 `cmd.ready := False`로 두면 CPU의 Store 요청이 수락되지 않으므로 반드시 바꿔야 합니다.

## 3. 시뮬레이션 코드

이번에는 DBus의 Store 요청을 관찰합니다.

기존 `VexRiscvTopSim`을 다음 코드로 교체하세요.

```
object VexRiscvTopSim extends App {

  import vexriscv.plugin._

  SimConfig.withWave
    .compile(new VexRiscvTop)
    .doSim { dut =>

      println("========================================")
      println(" VexRiscv Instruction Execution Test")
      println("========================================")

      dut.clockDomain.forkStimulus(period = 10)
      dut.clockDomain.waitSampling(5)

      println("[INFO] Reset/clock startup complete")

      val dbusPlugin = dut.system.cpu.plugins
        .collectFirst {
          case p: DBusSimplePlugin => p
        }
        .getOrElse(throw new Exception("DBusSimplePlugin not found"))

      val dbus = dbusPlugin.dBus

      var storeCount = 0

      for (cycle <- 1 to 50) {

        dut.clockDomain.waitFallingEdge()

        val cmdValid = dbus.cmd.valid.toBoolean
        val cmdReady = dbus.cmd.ready.toBoolean

        if (cmdValid && cmdReady) {

          val wr      = dbus.cmd.wr.toBoolean
          val address = dbus.cmd.address.toLong
          val data    = dbus.cmd.payload.data.toLong

          if (wr) {

            storeCount += 1

            println(
              f"Cycle $cycle%2d : " +
                f"STORE address=0x$address%08X " +
                f"data=0x$data%08X"
            )

            assert(
              address == 0x00000000L,
              f"Unexpected store address: 0x$address%08X"
            )

            assert(
              data == 0x00000001L,
              f"Unexpected store data: 0x$data%08X"
            )
          }
        }
      }

      println()
      println("========================================")
      println(" Instruction Execution Test Result")
      println("========================================")

      assert(
        storeCount > 0,
        "FAIL: No Store command observed"
      )

      println(s"[PASS] Store count = $storeCount")
      println("[PASS] Store address = 0x00000000")
      println("[PASS] Store data = 0x00000001")
      println("[PASS] ADDI result successfully reached DBus")

      println("========================================")
      println(" Test finished")
      println("========================================")
    }
}
```

## 4. 기대 결과

정상 실행되면 다음과 비슷한 결과가 나와야 합니다.

```
[INFO] Reset/clock startup complete

Cycle  5 : STORE address=0x00000000 data=0x00000001
Cycle 14 : STORE address=0x00000000 data=0x00000001
Cycle 23 : STORE address=0x00000000 data=0x00000001

[PASS] Store count = ...
[PASS] Store address = 0x00000000
[PASS] Store data = 0x00000001
[PASS] ADDI result successfully reached DBus
```

위 Cycle 번호와 Store 횟수는 예시이며 실제 결과를 예측한 값은 아닙니다.

이번 테스트의 핵심은 `ADDI` 결과인 1이 Register File에 기록되고, 이후 `SW`가 그 값을 읽어 DBus에 전달하는지 확인하는 것입니다.

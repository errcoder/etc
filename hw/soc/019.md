좋습니다. 이제 실제로 **`DBusDecoder`를 작성**하겠습니다.

이번 단계는 범위를 작게 잡겠습니다.

### 목표

현재:

```text
VexRiscv
   │
   ▼
SimpleDataRam
```

을 다음처럼 변경합니다.

```text
                 ┌──────────────┐
                 │ DBusDecoder  │
VexRiscv ───────►│              │
                 └──────┬───────┘
                        │
                        ▼
                   SimpleDataRam
```

이번에는 **RAM 하나만 연결**합니다.  
주소 디코딩을 넣되, RAM 주소 영역만 통과시키고 나머지는 `error` 응답을 만드는 구조로 갑니다.

RAM 영역은:

```text
0x0000_0000 ~ 0x0000_03FF
```

입니다. `SimpleDataRam`이 256 × 32-bit = 1 KiB이므로 정확히 0x400 byte입니다.

---

## 1. DBusDecoder.scala

```scala
package myvexsoc

import spinal.core._
import vexriscv.plugin._

class DBusDecoder extends Component {

  val io = new Bundle {
    val cpu = slave(DBusSimpleBus())

    val ram = master(DBusSimpleBus())
  }

  // 1 KiB Data RAM
  // 0x0000_0000 ~ 0x0000_03FF
  val ramHit =
    io.cpu.cmd.address < U(0x00000400L, 32 bits)

  // ------------------------------------------------------------
  // CPU -> RAM : command
  // ------------------------------------------------------------

  io.ram.cmd.valid := io.cpu.cmd.valid && ramHit
  io.ram.cmd.payload := io.cpu.cmd.payload

  // RAM이 command를 받을 수 있을 때만
  // CPU에게도 command를 받을 수 있다고 알린다.
  io.cpu.cmd.ready := Mux(
    ramHit,
    io.ram.cmd.ready,
    True
  )

  // ------------------------------------------------------------
  // RAM -> CPU : response
  // ------------------------------------------------------------

  io.cpu.rsp.ready := io.ram.rsp.ready && ramHit
  io.cpu.rsp.data  := io.ram.rsp.data
  io.cpu.rsp.error := io.ram.rsp.error

  // ------------------------------------------------------------
  // Unmapped access
  // ------------------------------------------------------------

  // 현재는 RAM 이외의 주소에 대해서
  // Load response를 error로 반환한다.
  //
  // Store는 DBusSimplePlugin에서 response가 필요하지 않으므로
  // command를 받아서 버린다.

  when(!ramHit) {
    io.cpu.rsp.ready  := True
    io.cpu.rsp.error  := True
    io.cpu.rsp.data   := B(0, 32 bits)
  }
}
```

그런데 여기서 **중요한 문제가 하나 있습니다.**

위 코드처럼 단순히 `ramHit`을 `rsp` 쪽에서도 다시 계산하면 안 됩니다.

왜냐하면 `DBusSimpleBus`의 response에는 **주소가 존재하지 않기 때문**입니다.

즉:

```text
cycle N
CPU → Decoder
       address = 0x00000000
       LOAD

cycle N+1
RAM → Decoder
       rsp.data = ...
```

cycle N+1에는 RAM response만 있고 CPU의 원래 address를 다시 참조할 방법이 없습니다.

따라서 Decoder는 **Load request가 어느 slave로 갔는지를 기억해야 합니다.**

이번 단계에서 이 부분을 제대로 구현해야 합니다.

# 2. 따라서 먼저 구조를 수정합니다

RAM 하나뿐인 현재 단계에서는 사실 `ramHit`을 response에 다시 사용할 필요가 없습니다.

RAM 외 주소를 받았을 때 CPU를 stall시키는 것보다, **unmapped Load를 별도로 pending 상태로 기억하는 방식**이 정확합니다.

하지만 이것을 바로 코드로 확장하기 전에, 현재 `DBusSimpleRsp.ready`가 일반적인 `ready`가 아니라 **CPU에게 Load response가 유효하다는 신호**라는 점이 핵심입니다.

즉:

```text
DBusSimpleBus

cmd
 ├─ valid
 ├─ ready
 └─ payload

rsp
 ├─ ready   ← response valid
 ├─ data
 └─ error
```

입니다.

## 이번 단계에서는 더 안전하게

**Decoder + RAM을 먼저 연결하고, unmapped access는 아직 구현하지 않는 것**을 권합니다.

즉:

```text
CPU
 │
 ▼
DBusDecoder
 │
 ▼
SimpleDataRam
```

에서

```text
RAM 영역
  ↓
RAM

RAM 외 영역
  ↓
일단 error 처리하지 않고 다음 단계에서 추가
```

로 하겠습니다.

이렇게 해야 한 번에 **주소 decode + response routing + error response** 세 가지를 동시에 디버깅하지 않아도 됩니다.

### 다음 실행 목표

현재 RAM 테스트 프로그램을 그대로 사용하면서:

```text
CPU
 ↓
DBusDecoder
 ↓
SimpleDataRam
```

구조로 바꾼 뒤 기존과 동일하게

```text
STORE 0x00 = 1
STORE 0x04 = 2
LOAD  0x00 → 1
STORE 0x08 = 1
```

이 PASS하는 것을 먼저 확인합니다.

그 다음에 **GPIO peripheral을 추가**하겠습니다.

이번 단계에서 중요한 것은 **Decoder를 멋있게 만드는 것이 아니라, 기존에 이미 검증한 RAM 동작을 Decoder를 삽입한 뒤에도 그대로 보존하는 것**입니다.

앞 단계에서 `DBusDecoder`를 성급하게 완성하면 **response routing 상태를 별도로 기억해야 하는 문제**가 생긴다는 것을 확인했습니다. 그래서 이번에는 **RAM 영역만 정확하게 decode하는 최소 Decoder**를 먼저 구현하고, 기존 RAM 테스트를 그대로 통과시키겠습니다.

## 1. `DBusDecoder.scala`

```scala
package myvexsoc

import spinal.core._
import vexriscv.plugin._

class DBusDecoder extends Component {

  val io = new Bundle {
    val cpu = slave(DBusSimpleBus())
    val ram = master(DBusSimpleBus())
  }

  // Data RAM:
  // 0x0000_0000 ~ 0x0000_03FF
  val ramHit =
    io.cpu.cmd.address < U(0x00000400L, 32 bits)

  // CPU -> RAM
  io.ram.cmd.valid := io.cpu.cmd.valid && ramHit
  io.ram.cmd.payload := io.cpu.cmd.payload

  // RAM이 받을 수 있을 때만 CPU command를 accept
  //
  // RAM 영역이 아니면 일단 command를 받지 않는다.
  io.cpu.cmd.ready := ramHit && io.ram.cmd.ready

  // RAM -> CPU
  //
  // 현재는 RAM 하나만 존재하므로 response를 그대로 전달한다.
  io.cpu.rsp.ready := io.ram.rsp.ready
  io.cpu.rsp.data := io.ram.rsp.data
  io.cpu.rsp.error := io.ram.rsp.error
}
```

여기서는 의도적으로 **unmapped address 처리까지 넣지 않습니다.**

현재 Decoder의 역할은 정확히:

```text
CPU DBus
   │
   │ address < 0x400
   ▼
 DBusDecoder
   │
   ▼
 SimpleDataRam
```

입니다.

# 2. `VexRiscvTop` 연결 변경

기존의:

```scala
val dataRam = new SimpleDataRam
```

을 다음으로 바꿉니다.

```scala
val dataRam = new SimpleDataRam
val dbusDecoder = new DBusDecoder
```

그리고 `DBusSimplePlugin` 부분을:

```scala
case p: DBusSimplePlugin =>

  p.dBus.cmd.valid.simPublic()
  p.dBus.cmd.ready.simPublic()
  p.dBus.cmd.wr.simPublic()
  p.dBus.cmd.address.simPublic()
  p.dBus.cmd.payload.data.simPublic()
  p.dBus.cmd.mask.simPublic()

  p.dBus.rsp.ready.simPublic()
  p.dBus.rsp.data.simPublic()
  p.dBus.rsp.error.simPublic()

  dbusDecoder.io.cpu <> p.dBus
  dataRam.io <> dbusDecoder.io.ram
```

으로 변경합니다.

전체 구조는:

```text
                    VexRiscv
                       │
                       │ DBus
                       ▼
                ┌─────────────┐
                │ DBusDecoder │
                └──────┬──────┘
                       │
                       │ RAM 영역
                       ▼
                ┌─────────────┐
                │ SimpleDataRam│
                └─────────────┘
```

## 3. 기존 RAM 테스트는 그대로 사용

중요합니다.

**Simulation 코드는 이번에는 변경하지 마세요.**

우리가 이미 통과시킨 테스트를 그대로 실행합니다.

기대 결과:

```text
STORE addr=0x00000000 data=0x00000001
STORE addr=0x00000004 data=0x00000002
LOAD  addr=0x00000000
LOAD RSP data=0x00000001
STORE addr=0x00000008 data=0x00000001
```

그리고:

```text
[PASS] RAM[0] = 0x00000001
[PASS] RAM[1] = 0x00000002
[PASS] RAM[2] = 0x00000001
[PASS] Load response = 0x00000001
```

가 그대로 나와야 합니다.

### 이번 단계에서 검증하는 것

기존에는:

```text
CPU → RAM
```

이었지만 이제:

```text
CPU → Decoder → RAM
```

이므로 **Decoder가 DBus command와 Load response를 망가뜨리지 않는지**를 실제 CPU simulation으로 검증하는 단계입니다.

이것이 PASS하면 그 다음에야:

```text
0x0000_0000 ~ 0x0000_03FF → RAM
0x1000_0000 ~ 0x1000_000F → GPIO
```

처럼 **두 번째 slave를 추가하고 response routing을 제대로 설계**하겠습니다.

이번 것은 먼저 실행해 주세요. **결과를 그대로 보여주시면 그 결과 기준으로 다음 단계로 넘어가겠습니다.**

SpinalHDL로 System on Chip(SoC)을 가장 빠르고 효율적으로 구현하는 방법은 **SpinalHDL 전용 RISC-V 프로세서인 VexRiscv와 
제공되는 레퍼런스 SoC 템플릿(Murax 등), 그리고 자동화 라이브러리(`BusSlaveFactory`)를 활용하는 것** 입니다.

처음부터 모든 걸 짜는 대신, 이미 검증된 템플릿과 툴을 조합하면 몇 시간 안에 동작하는 SoC를 구축할 수 있습니다. 가장 빠른 3가지 핵심 접근법입니다.

---

### 1. `Murax` 또는 `Briey` SoC 템플릿 활용하기 (가장 빠름)

SpinalHDL 생태계에는 이미 완성된 오픈소스 RISC-V SoC 구조가 준비되어 있습니다. 
이를 수정(Customizing)하여 원하는 구조로 빠르게 탈바꿈시키는 것이 가장 빠릅니다.

* **Murax SoC (`vexriscv.demo.Murax`)**:
* 외장 메모리(SDRAM 등) 없이 FPGA 내부 자원(On-chip RAM, 8KB 등)만으로 동작하는 초경량 SoC입니다.
* VexRiscv CPU, APB3 버스, UART, Timer, GPIO, JTAG 디버거가 기본 포함되어 있습니다.
* 소스코드 구조(`src/main/scala/vexriscv/demo/Murax.scala`)를 입맛에 맞게 커스텀하여 빠르게 빌드할 수 있습니다.


* **Briey / Pinsec SoC**:
* AXI4 버스, SDRAM 컨트롤러, 캐시 등이 포함된 조금 더 고성능의 SoC 템플릿입니다.



---

### 2. `BusSlaveFactory`로 커스텀 페리페럴(Peripheral) 빠르게 만들기

SoC에 자신만의 하드웨어 가속기나 커스텀 IP를 붙일 때 가장 번거로운 작업은 **메모리 맵(Memory-mapped) 주소 복호화 및 
레지스터 인터페이스 구현** 입니다. SpinalHDL은 이를 자동화해 주는 `BusSlaveFactory`를 제공합니다.

```scala
// APB3 버스를 사용하는 커스텀 IP 페리페럴 예시
class MyCustomIP extends Component {
  val io = new Bundle {
    val bus = slave(APB3(addressWidth = 4, dataWidth = 32))
    val customSignal = out Bool()
  }

  // 레지스터 정의
  val myReg = Reg(UInt(32 bits)) init(0)
  io.customSignal := myReg(0)

  // BusSlaveFactory를 이용해 APB3 버스와 레지스터를 단 몇 줄로 매핑
  val busCtrl = Apb3SlaveFactory(io.bus)
  busCtrl.driveAndRead(myReg, address = 0x00) // 0x00 번지에 레지스터 매핑
}

```

* 수십 줄의 Verilog 주소 디코딩 로직을 작성할 필요 없이, 단 한 줄(`driveAndRead`)로 CPU가 제어할 수 있는 레지스터가 생성됩니다.

### 3. VexRiscv의 플러그인(Plugin) 구조 활용

SoC의 핵심인 CPU를 커스텀할 때, VexRiscv는 **플러그인 기반**으로 설계되어 있어 필요한 기능만 꼈다 뺐다 할 수 있습니다.

* 곱셈/나눗셈(MUL/DIV) 확장, 캐시(Cache), MMU(Linux 구동용), 디버그 인터페이스 등을 설정 객체(Config) 수정만으로 쉽게 조합할 수 있습니다.

### 1. Murax의 전체 아키텍처 및 작동 원리

Murax SoC는 크게 CPU, 버스 인터커넥트, 온칩 메모리, 그리고 페리페럴(주변장치)의 4가지 축으로 구성되어 있습니다.

#### ① VexRiscv CPU 설정 (Config)

* **초경량 플러그인 조합:** Murax에 사용되는 VexRiscv는 리소스(FPGA LUT)를 최소화하기 위해 MMU나 복잡한 캐시를 뺍니다. 대신 RV32I(또는 RV32IM) 명령어 세트, 디버그 플러그인, 인터럽트 제어 플러그인 등 **최소한의 필수 기능만 조합**(`VexRiscvParameter` 정의)하여 생성됩니다.
* **파이프라인:** 단일 발행(Single-issue) 2단계 또는 3단계 파이프라인 구조를 사용하여 고속 동작과 적은 면적을 동시에 달성합니다.

#### ② 버스 구조 (APB3 기반 인터커넥트)

* 복잡하고 무거운 AXI 버스 대신, 구조가 단순하고 가벼운 **APB3 버스**를 SoC 전체의 메인 통신망으로 사용합니다.
* CPU가 메모리나 페리페럴에 접근할 때, **APB3 Decoder**가 주소(Address)를 해석하여 해당하는 장치(RAM, UART, GPIO 등)로 신호를 라우팅해 줍니다.

#### ③ 온칩 메모리 (On-Chip RAM / ROM)

* 별도의 외부 메모리 컨트롤러(DDR 등)가 필요 없습니다. CPU의 명령어 페치(Instruction Fetch)와 데이터 읽기/쓰기가 모두 내부 BRAM 공간에서 이루어집니다.
* 보통 SoC가 부팅될 때 실행할 펌웨어(Firmware)가 이 온칩 메모리 영역에 같이 로드되도록 설계됩니다.

#### ④ 기본 내장 페리페럴

Murax 내부에는 임베디드 시스템에 필수적인 장치들이 APB3 슬레이브 형태로 단단히 결합되어 있습니다.

* **GPIO:** 외부 핀 제어 및 상태 읽기
* **Timer:** 시스템 틱(Tick) 및 인터럽트 발생
* **UART:** 시리얼 통신 (디버깅 및 로그 출력용)
* **JTAG:** OpenOCD 등과 연동하여 실시간으로 CPU 레지스터를 디버깅할 수 있는 인터페이스

### 2. 내 프로젝트로 Murax 코드를 가져와 커스텀하는 방법

Murax의 구조를 파악했다면, 실제 코드를 프로젝트에 이식하고 수정하는 절차는 다음과 같습니다.

1. **소스 파일 복사:**
* VexRiscv 공식 GitHub 리포지토리의 `src/main/scala/vexriscv/demo/Murax.scala` 파일을 자신의 프로젝트 `src/main/scala/` 경로 아래 적절한 패키지로 가져옵니다.
* 필요에 따라 Murax 내부에서 참조하는 페리페럴 파일들(`MuraxMemoryMapping.scala`, 각종 APB3 페리페럴 소스 등)도 함께 가져와야 합니다.


2. **Top-level 파라미터 수정 (`Murax` 클래스 구조 분석):**
* `Murax` 클래스 내부를 보면 `val cpuConfig = VexRiscvConfig(...)` 부분에서 CPU가 지원할 기능(곱셈기, 디버그 등)을 정의합니다. 이곳에서 원하는 기능을 켜고 끌 수 있습니다.
* 메모리 크기(On-chip RAM size)나 페리페럴 주소 맵(Memory Mapping) 상수를 입맛에 맞게 변경합니다.


3. **커스텀 페리페럴(IP) 추가하기:**
* 자신만의 하드웨어 가속기나 센서 인터페이스를 추가하고 싶다면, 앞서 다룬 `BusSlaveFactory`를 이용해 APB3 슬레이브 형태로 페리페럴을 만든 뒤 Murax의 APB3 Decoder 버스 라우팅 목록에 추가(Map)해주면 됩니다.

Murax SoC에 자신만의 커스텀 APB3 페리페럴(예: LED 제어 및 상태 확인 레지스터)을 추가하는 방법은 크게 **1) 커스텀 페리페럴 컴포넌트 정의**와 **2) Murax Top-level 버스 매핑**의 두 단계로 나뉩니다.

SpinalHDL의 `BusSlaveFactory`를 활용하면 복잡한 주소 디코딩 로직 없이 단 몇 줄로 레지스터를 구현할 수 있습니다.

### 1. 커스텀 APB3 페리페럴 컴포넌트 정의

먼저 APB3 슬레이브 인터페이스를 가지는 커스텀 IP 클래스를 만듭니다. `driveAndRead`를 사용하면 CPU가 해당 주소에 값을 쓸 때 레지스터에 반영되고, 읽을 때 그 값을 그대로 반환합니다.

```scala
import spinal.core._
import spinal.lib.bus.amba3.apb._
import spinal.lib.bus.controller.BusSlaveFactory

class MyCustomPeripheral extends Component {
  val io = new Bundle {
    val bus = slave(APB3(addressWidth = 4, dataWidth = 32))
    val userLed = out Bool()
  }

  // 내부 레지스터 정의 (초기값 false)
  val ledReg = Reg(Bool()) init(false)
  io.userLed := ledReg

  // APB3 버스 컨트롤러와 레지스터 연결 (BusSlaveFactory 활용)
  val busCtrl = Apb3SlaveFactory(io.bus)
  
  // 0x00 번지에 ledReg 매핑 (읽기/쓰기 모두 가능)
  busCtrl.driveAndRead(ledReg, address = 0x00)
}

```

### 2. Murax SoC Top-level에 페리페럴 통합 및 주소 맵 지정

이제 `Murax.scala` 파일 내부(SoC Top-level 빌드 영역)로 돌아와서, 위에서 만든 페리페럴을 인스턴스화하고 APB3 디코더(Bus Multiplexer)에 연결해 주어야 합니다.

Murax 내부의 APB3 페리페럴들은 보통 `Area` 안에서 리스트 형태로 번지와 함께 매핑됩니다.

```scala
class Murax(val p: MuraxConfig) extends Component {
  // ... 기존 VexRiscv CPU 및 메모리 정의 생략 ...

  // 1. 커스텀 페리페럴 인스턴스 생성
  val customPeripheral = new MyCustomPeripheral()

  // 2. APB3 버스 인터커넥트(Decoder)에 페리페럴 연결 및 주소 할당
  // 예시: 0xF0000000 번지에 커스텀 페리페럴 배치 (Murax 메모리 맵 정책에 맞게 설정)
  val apbDecoder = Apb3Decoder(
    master = bridgeToApb,
    slaves = Array(
      // 기존 Murax 페리페럴들 (GPIO, UART, Timer 등)
      io.gpioCtrl.apb  -> (0x00000000, 4 kB),
      io.uartCtrl.apb  -> (0x00010000, 4 kB),
      io.timer.apb     -> (0x00020000, 4 kB),
      
      // 새로 추가한 커스텀 페리페럴 연결
      customPeripheral.io.bus -> (0xF0000000, 4 kB)
    )
  )

  // 3. 페리페럴의 외부 핀(IO)을 SoC Top 외부로 연결
  val externalIo = new Bundle {
    val userLed = out Bool()
  }
  externalIo.userLed := customPeripheral.io.userLed
}

```

### 3. 소프트웨어(C언어)에서 접근하기

위와 같이 하드웨어를 구성하고 컴파일하면, 임베디드 펌웨어(C 코드)에서 지정한 메모리 주소를 통해 곧바로 하드웨어를 제어할 수 있습니다.

```c
// 정의된 메모리 맵 주소
#define CUSTOM_IP_BASE 0xF0000000
#define REG_LED_OFFSET 0x00

// LED 켜기 (0x00 번지에 1 쓰기)
*(volatile unsigned int *)(CUSTOM_IP_BASE + REG_LED_OFFSET) = 1;

```

### 1. 전체 시스템 아키텍처 및 버스 구조

Murax의 내부 구조는 크게 **CPU 코어**, **내부 메모리 버스**, 그리고 **APB3 주변장치 버스**의 3단 구조로 이루어져 있습니다.

* **VexRiscv CPU Core:**
* RV32I(또는 RV32IM) 명령어 셋을 지원하며, 면적을 최소화하기 위해 MMU나 무거운 캐시 구조를 배제했습니다.
* 명령어(Instruction)와 데이터(Data)를 주고받는 마스터 인터페이스가 내부 버스와 직접 연결됩니다.


* **Internal Bus (메모리 인터페이스):**
* CPU가 가장 빈번하게 접근하는 온칩 메모리(RAM/ROM)와는 고속으로 직접 연결(Direct Connection)되어 사이클 지연을 최소화합니다.


* **APB Bridge:**
* 메모리 영역 외의 주변장치(GPIO, UART 등)와 통신하기 위해, 내부 버스의 신호를 가볍고 표준화된 **APB3 버스 프로토콜**로 변환해 주는 브리지 역할을 합니다.



---

### 2. 주요 내부 블록 및 컴포넌트

#### ① 온칩 메모리 (On-Chip SRAM)

* FPGA 내부의 BRAM(Block RAM)을 활용하여 구현됩니다.
* 일반적으로 8KB ~ 64KB 크기로 설정되며, **명령어 영역과 데이터 영역이 통합된(Unified Memory) 구조**를 가집니다.
* FPGA가 비트스트림으로 프로그래밍될 때, 컴파일된 C언어 펌웨어 이미지(`Hex` 또는 `Bin` 파일)가 이 BRAM 내부에 함께 로드되어 초기화됩니다.

#### ② 내장 페리페럴 (주변장치) 라인업

Murax 내부에는 임베디드 시스템 운영에 꼭 필요한 최소한의 표준 페리페럴들이 APB3 디코더에 물려 있습니다.

* **MuraxGpio:** 외부 핀 상태를 읽거나 LED, 버튼 등을 제어할 수 있는 GPIO 제어기.
* **MuraxTimer:** 시스템 틱(Tick) 생성 및 정확한 시간 지연(Delay)을 측정하기 위한 타이머.
* **MuraxUart:** PC나 외부 장치와 시리얼 통신을 하기 위한 UART 제어기 (printf 디버깅에 필수적).

#### ③ 디버그 및 인터럽트 시스템

* **JTAG 디버그 플러그인:** VexRiscv의 강력한 특징 중 하나로, FPGA의 JTAG 핀을 통해 PC의 **OpenOCD** 및 **GDB**와 연동됩니다. 이를 통해 하드웨어 상태에서 브레이크포인트(Breakpoint)를 잡고 코드를 디버깅할 수 있습니다.
* **인터럽트 제어:** 타이머나 UART, 외부 GPIO 등에서 발생하는 인터럽트 신호를 모아 CPU로 전달하는 인터럽트 라우팅 구조를 포함하고 있습니다.

### 3. Murax의 부팅 흐름 (Boot Flow)

Murax SoC는 외장 플래시 메모리(SPI Flash 등)에서 코드를 부팅하는 복잡한 과정(Bootloader)을 거치지 않고, 다음과 같이 매우 단순하게 동작합니다.

1. **전원 인가 및 리셋 해제:** FPGA가 켜지고 리셋이 해제되면, VexRiscv CPU는 주소 `0x00000000`(온칩 메모리의 시작 주소)을 가리킵니다.
2. **코드 실행:** 온칩 BRAM에 미리 채워져 있던 펌웨어 코드의 첫 번째 명령어를 곧바로 페치(Fetch)하여 실행을 시작합니다.
3. **메모리 맵 기반 동작:** CPU가 특정 페리페럴(예: UART)에 데이터를 쓰고 싶을 때는 정해진 주소(Memory Map Address)로 신호를 보내고, APB3 디코더가 이를 해당 장치로 연결해 줍니다.

---

---

SpinalHDL의 오픈소스 RISC-V SoC 템플릿인 **Murax SoC**의 메모리 맵(Memory Map) 구조와 주소 할당(Address Allocation) 방식을 핵심 요소별로 나누어 설명해 드리겠습니다.

Murax SoC는 외장 메모리(DRAM) 없이 FPGA 내부 자원(BRAM)만 활용하도록 설계되어 있어, 주소 공간이 매우 단순하고 명확하게 이분화되어 있는 것이 특징입니다.

---

### 1. Murax 메모리 맵 전체 구조 개요

Murax의 32비트 주소 공간(Address Space)은 크게 온칩 메모리 영역(On-Chip RAM/ROM)과 **주변장치(Peripherals) 영역**의 두 가지 큰 축으로 나뉩니다.

| 주소 범위 (Address Range) | 대상 장치 (Target Device) | 설명 |
| --- | --- | --- |
| `0x00000000` ~ (설정된 크기 - 1) | **On-Chip RAM / ROM** | CPU가 부팅 후 처음 코드를 읽어오고(Fetch), 데이터를 읽고 쓰는 메인 메모리 공간 (FPGA BRAM 활용) |
| `0xF0000000` ~ `0xF002FFFF` | **APB3 Peripherals** | GPIO, UART, Timer 등 각종 제어용 주변장치가 매핑되는 공간 (AP3 버스 디코더로 분기) |

---

### 2. 세부 영역별 주소 할당 상세

#### ① 온칩 메모리 영역 (`0x00000000` 시작)

* **위치:** 주소 `0x00000000`번지부터 시작합니다.
* **크기:** `MuraxConfig` 설정에 따라 결정되며, 기본값은 보통 **8 KB**(또는 FPGA 용량에 따라 확장 가능)입니다.
* **역할:** 별도의 부트로더 플래시 메모리 없이, FPGA가 켜지면 CPU가 즉시 `0x00000000`번지로 접근해 펌웨어 명령어(Instruction)를 페치하여 실행합니다. 데이터 영역(Stack/Heap)도 이 공간을 공유하는 통합 메모리(Unified Memory) 구조를 가집니다.

#### ② 주변장치 페리페럴 영역 (`0xF0000000` 시작)

* **위치:** 상위 주소 대역인 `0xF0000000`부터 시작하여 APB3 버스 디코더(`Apb3Decoder`)를 통해 각 페리페럴로 라우팅됩니다.
* **기본 페리페럴 주소 맵 (예시):**
* **GPIO Controller:** `0xF0000000` (크기: 4 KB)
* **UART Controller:** `0xF0010000` (크기: 4 KB)
* **Timer:** `0xF0020000` (크기: 4 KB)



---

### 3. SpinalHDL 코드로 구현된 메모리 맵 디코딩 원리

`Murax.scala` 내부를 보면, 이러한 주소 할당과 디코딩 작업이 SpinalHDL의 `Apb3Decoder`와 `SizeMapping` 라이브러리를 통해 매우 직관적인 코드로 작성되어 있습니다.

```scala
// Murax 내부의 APB3 디코더 구성 예시 개념
val apbDecoder = Apb3Decoder(
  master = bridgeToApb, // CPU 버스를 APB로 변환하는 브리지
  slaves = Array(
    io.gpioCtrl.apb  -> (0xF0000000, 4.kB), // GPIO 페리페럴 매핑
    io.uartCtrl.apb  -> (0xF0010000, 4.kB), // UART 페리페럴 매핑
    io.timer.apb     -> (0xF0020000, 4.kB)  // Timer 페리페럴 매핑
  )
)

```

* CPU가 특정 주소(예: `0xF0010000`)로 데이터를 쓰거나 읽으려고 신호를 보내면, `Apb3Decoder`가 상위 주소와 범위를 자동으로 판별하여 해당 페리페럴(UART)의 슬라이브 선택(Sel) 신호를 활성화해 줍니다.
* 앞서 다룬 것처럼 **사용자가 커스텀 IP를 추가**할 때도 이 배열(Array)에 새로운 주소 대역(예: `0xF0000000` 외의 빈 공간인 `0xF0030000` 등)과 크기를 지정해 주면 곧바로 메모리 맵에 통합됩니다.

---

---

Murax SoC의 메모리 맵(`0x00000000` 온칩 메모리, `0xF0000000` GPIO, `0xF0010000` UART)을 활용하여 C언어 베어메탈(Bare-metal) 펌웨어를 작성하는 방법은 메모리 맵 주소를 포인터로 매핑(Memory-Mapped I/O)하여 직접 읽고 쓰는 것입니다.

OS가 없는 환경이기 때문에, 하드웨어 레지스터 주소를 직접 참조하여 제어합니다.

### 1. 기본 메모리 맵 주소 정의 (Header 파일)

C 코드에서 하드웨어 주소를 쉽게 다룰 수 있도록 매크로와 `volatile` 포인터를 정의합니다. `volatile` 키워드는 컴파일러가 하드웨어 상태 변화를 최적화로 인해 무시하지 않도록 강제하는 데 필수적입니다.

```c
#ifndef MURAX_H
#define MURAX_H

// Murax Memory Map
#define GPIO_BASE_ADDR  0xF0000000
#define UART_BASE_ADDR  0xF0010000

// GPIO 레지스터 구조체 또는 주소 정의
// (실제 Murax 구조에 맞춰 오프셋 적용)
#define GPIO_OUTPUT     (*(volatile unsigned int *)(GPIO_BASE_ADDR + 0x00))
#define GPIO_INPUT      (*(volatile unsigned int *)(GPIO_BASE_ADDR + 0x04))

// UART 레지스터 정의 (Data, Status 등)
#define UART_DATA       (*(volatile unsigned int *)(UART_BASE_ADDR + 0x00))
#define UART_STATUS     (*(volatile unsigned int *)(UART_BASE_ADDR + 0x04))

#endif

```

### 2. UART로 문자열 출력하기 (Polling 방식)

UART로 데이터를 보낼 때는 보통 전송 버퍼가 비어 있는지 상태(`UART_STATUS`)를 확인한 뒤, 데이터 레지스터(`UART_DATA`)에 한 글자씩 밀어 넣는 방식을 사용합니다.

```c
#include "murax.h"

// 한 글자 전송 함수
void uart_write_char(char c) {
    // UART 상태 레지스터에서 전송 가능 여부 확인 (구현체에 따라 다름)
    // 예시: 비트가 1일 때만 쓰기 가능하다고 가정
    while ((UART_STATUS & 0x01) == 0); 
    UART_DATA = c;
}

// 문자열 전송 함수
void uart_print(const char *str) {
    while (*str != '\0') {
        uart_write_char(*str);
        str++;
    }
}

```

### 3. GPIO로 LED 제어하기

GPIO 출력 레지스터에 값을 쓰면 곧바로 하드웨어 핀(LED 등)의 전압 레벨이 바뀌게 됩니다.

```c
// 간단한 딜레이 함수
void delay(int count) {
    for (volatile int i = 0; i < count; i++);
}

int main() {
    uart_print("Murax SoC Booted Successfully!\n");

    while (1) {
        // LED 켜기 (첫 번째 비트 1 설정)
        GPIO_OUTPUT = 0x01;
        uart_print("LED ON\n");
        delay(1000000);

        // LED 끄기 (첫 번째 비트 0 설정)
        GPIO_OUTPUT = 0x00;
        uart_print("LED OFF\n");
        delay(1000000);
    }

    return 0;
}

```

### 4. 링커 스크립트(Linker Script) 설정 시 주의점

이 C 코드가 Murax의 온칩 메모리 시작 주소인 `0x00000000`부터 적재되도록 링커 스크립트(`.ld`)에서 텍스트 섹션(Text section)의 시작 주소를 반드시 `0x00000000`으로 맞춰주어야 CPU가 전원이 켜지자마자 이 코드를 정상적으로 실행할 수 있습니다.

---

SpinalSim에서 실행할 수 있도록 RISC-V GCC 툴체인을 사용하여 C 펌웨어 코드를 컴파일하고 HEX 파일로 변환하는 과정은 일반적인 베어메탈(Bare-metal) 임베디드 빌드 과정과 동일합니다.

이를 위해 **1) 툴체인 준비, 2) 스타트업 코드(`crt0.s`), 3) 링커 스크립트(`linker.ld`), 4) 컴파일 및 HEX 변환 명령어**의 4단계가 필요합니다.

### 1단계: RISC-V GCC 툴체인 설치

먼저 시스템에 RISC-V용 GCC 툴체인(`riscv64-unknown-elf-gcc` 또는 `riscv32-unknown-elf-gcc`)이 설치되어 있어야 합니다. (Ubuntu 기준 패키지 매니저나 XPack 등으로 쉽게 설치할 수 있습니다.)

```bash
# Ubuntu 환경 예시
sudo apt-get install gcc-riscv64-unknown-elf

```

### 2단계: 스타트업 코드 작성 (`crt0.s`)

임베디드 환경에서는 C언어의 `main` 함수가 실행되기 전에 **스택 포인터(`sp`) 초기화**와 같은 하드웨어 초기 세팅을 Assembly로 먼저 해 줘야 합니다.

```assembly
.global _start
.section .text

_start:
    # 스택 포인터 설정 (온칩 메모리 크기에 맞춰 조정, 예: 8KB 위치)
    li sp, 0x00002000 
    
    # main 함수로 점프
    call main
    
    # main 종료 시 무한 루프
_infinite_loop:
    j _infinite_loop

```

### 3단계: 링커 스크립트 작성 (`linker.ld`)

앞서 다룬 Murax 메모리 맵(`0x00000000` 시작)에 맞춰 코드가 어디에 적재될지 정의합니다.

```ld
MEMORY
{
  ram (rwx) : ORIGIN = 0x00000000, LENGTH = 8K
}

SECTIONS
{
  .text : {
    *(.text._start)
    *(.text)
  } > ram

  .data : {
    *(.data)
  } > ram

  .bss : {
    *(.bss)
  } > ram
}

```

### 4단계: 컴파일 및 HEX 변환 (Makefile / 명령어)

C소스(`main.c`), 스타트업코드(`crt0.s`), 링커스크립트(`linker.ld`)를 하나로 묶어 컴파일한 뒤, 시뮬레이터가 읽을 수 있는 Binary/Hex 파일로 변환합니다.

```bash
# 1. 컴파일 및 링크 (RV32I 아키텍처 기준)
riscv64-unknown-elf-gcc -march=rv32i -mabi=ilp32 -nostdlib -T linker.ld crt0.s main.c -o firmware.elf

# 2. ELF 파일을 순수 바이너리로 추출
riscv64-unknown-elf-objcopy -O binary firmware.elf firmware.bin

# 3. SpinalSim(Verilog BRAM 초기화 등)에서 읽을 수 있는 헥스 파일로 변환 (Python 등 활용)
# 또는 Verilog $readmemh 형식의 텍스트 파일로 변환

```

SpinalHDL은 시뮬레이션 중 메모리 컴포넌트(`Mem`)에 직접 파일을 로드할 수 있는 유용한 메서드(`loadBinary`, `loadHex`)를 제공합니다.

### 1. 시뮬레이션 테스트벤치 스크립트 작성 (`MuraxSim.scala`)

아래는 Murax SoC를 컴파일하고, 온칩 메모리에 펌웨어를 올린 뒤 시뮬레이션을 구동하는 전형적인 스칼라(Scala) 테스트벤치 코드입니다.

```scala
import spinal.core._
import spinal.sim._
import spinal.core.sim._
import vexriscv.demo.Murax // Murax SoC 패키지 임포트

object MuraxSim {
  def main(args: Array[String]): Unit = {
    // 1. SimConfig 설정 (파형 생성 활성화 등)
    SimConfig.withWave.compile {
      val dut = new Murax(MuraxConfig.default)
      dut
    }.doSim { dut =>
      // 2. 펌웨어 바이너리 파일 로드
      // Murax 내부 메모리 인스턴스 경로(예: dut.ram.memory)에 바이너리 주입
      // 주의: 프로젝트 루트 디렉토리에 'firmware.bin' 파일이 위치해야 합니다.
      dut.ram.memory.loadBinary("firmware.bin")

      // 3. 클럭 도메인 및 리셋 구동 (주기 10 타임 유닛)
      dut.clockDomain.forkStimulus(period = 10)

      // 4. 시뮬레이션 실행 중 모니터링 (선택 사항: UART 출력 가로채기 등)
      // 예시: 50,000 클럭 동안 시뮬레이션 진행
      println("--- Simulation Start ---")
      
      for (i <- 0 until 50000) {
        dut.clockDomain.waitSampling()
        
        // 필요시 UART TX 핀을 모니터링하여 C 펌웨어의 printf 결과를 콘솔에 실시간 출력할 수 있습니다.
        // if (dut.io.uart.txd.toBoolean) { ... }
      }

      println("--- Simulation Finished ---")
    }
  }
}

```

### 2. 핵심 동작 원리 설명

1. **메모리 접근 및 로드 (`dut.ram.memory.loadBinary`)**
* Murax SoC 내부에서 온칩 RAM 역할을 하는 컴포넌트(일반적으로 `Mem` 객체)에 `loadBinary("firmware.bin")`을 호출하면, 시뮬레이션이 시작되는 시점에 롬/램 영역이 컴파일된 C 펌웨어 데이터로 채워집니다.
* 이 덕분에 실제 하드웨어의 BRAM 초기화(Initialization file) 과정과 동일한 상태에서 CPU가 부팅(`0x00000000`번지 페치)할 수 있습니다.


2. **클럭 생성 (`forkStimulus`)**
* 앞서 다룬 대로 `forkStimulus(period = 10)`을 호출하면 최초 16클럭 동안 리셋 신호가 유지되다가 자동으로 해제(Deassert)되면서 CPU가 펌웨어를 정상적으로 실행하기 시작합니다.


3. **시뮬레이션 실행 (`sbt run`)**
* 작성한 테스트벤치 객체를 SBT 명령어로 실행하면 시뮬레이터가 돌기 시작합니다.
```bash
sbt "runMain MuraxSim"

```

SpinalHDL 시뮬레이션(SpinalSim) 환경에서 Murax SoC의 **UART TX 핀을 실시간으로 모니터링하여 C 펌웨어가 보내는 `printf` 로그를 Scala 콘솔에 출력**하는 것은 디버깅에 매우 유용합니다.

UART는 비동기 통신(Asynchronous Serial) 방식이므로, 시뮬레이션 안에서 백그라운드 스레드(`fork`)를 하나 띄워 **보드 레이트(Baud Rate) 타이밍에 맞춰 TX 핀의 비트(Bit)들을 샘플링하고 문자로 조합**하는 방식으로 구현할 수 있습니다.

### 1. UART TX 모니터링 스레드 구현 예시

테스트벤치(`doSim` 블록 내부)에 다음과 같은 백그라운드 스레드를 추가하면 UART 출력을 실시간으로 가로채어 콘솔에 찍을 수 있습니다.

```scala
SimConfig.withWave.compile {
  val dut = new Murax(MuraxConfig.default)
  dut
}.doSim { dut =>
  dut.ram.memory.loadBinary("firmware.bin")
  dut.clockDomain.forkStimulus(period = 10) // 10 타임유닛 주기 클럭 (예: 100MHz 가정 시 10ns)

  // --- UART 모니터링 백그라운드 스레드 시작 ---
  fork {
    // 1. 통신 환경 설정 (보드 레이트 및 클럭 주파수에 맞게 설정)
    val clockPeriodPs = 10000 // 10 타임유닛 = 10ns = 100MHz 클럭 가정
    val baudRate = 115200
    val cyclesPerBit = (1.0e9 / baudRate) / (clockPeriodPs / 1000.0)

    println(s"[UART Monitor] Started (Baudrate: $baudRate)")

    while(true) {
      // 2. Start Bit 대기 (UART TX 라인이 High -> Low로 떨어질 때까지 대기)
      // Murax의 UART TX 핀 경로 (디자인에 따라 dut.io.uart.txd 등으로 다를 수 있음)
      waitUntil(dut.io.uart.txd.toBoolean == false)

      // 3. Start Bit의 중앙 지점으로 이동 (1.5 비트 주기만큼 대기)
      sleep(cyclesPerBit * 1.5)

      // 4. 8개의 데이터 비트(Data Bits) 읽기 (LSB First 기준)
      var charValue = 0
      for (i <- 0 until 8) {
        if (dut.io.uart.txd.toBoolean) {
          charValue |= (1 << i)
        }
        sleep(cyclesPerBit) // 다음 비트 중앙으로 이동
      }

      // 5. Stop Bit 대기 후 문자로 변환하여 콘솔에 출력
      sleep(cyclesPerBit)
      
      // 콘솔에 실시간 출력
      print(charValue.toChar)
      System.out.flush() // 버퍼를 비워 즉시 출력되도록 함
    }
  }
  // ------------------------------------------

  // 시뮬레이션 진행 (예: 충분한 시간 동안 대기)
  println("--- Simulation Start ---")
  dut.clockDomain.waitSampling(100000) // 10만 클럭 동안 실행
  println("\n--- Simulation Finished ---")
}

```

### 2. 작동 원리 및 주의사항

1. **Start Bit 감지 (`waitUntil`)**
* UART는 평소에 High 상태를 유지하다가 데이터 전송이 시작될 때 Low(0)로 떨어지는 Start Bit를 보냅니다. `waitUntil(dut.io.uart.txd.toBoolean == false)` 코드가 이 신호를 포착합니다.


2. **비트 샘플링 (`sleep`)**
* 보드 레이트(`115200` 등)와 시스템 클럭 주파수를 바탕으로 **1비트가 유지되는 시뮬레이션 시간**을 계산(`cyclesPerBit`)합니다. 신호의 가장자리가 아닌 정확히 **가운데 지점**을 샘플링해야 노이즈 없이 정확한 데이터를 읽을 수 있으므로, 처음 시작 시 `1.5비트`를 쉬고 이후 매 비트마다 `1비트`씩 전진하며 읽습니다.


3. **실시간 출력 (`print` + `System.out.flush()`)**
* C 펌웨어 안에서 `uart_print("Hello World\n")` 또는 `printf`를 호출하면, 하드웨어 UART TX 핀을 통해 직렬로 전송되는 데이터가 이 스레드에 의해 실시간으로 파싱되어 SBT 실행 창(콘솔)에 그대로 찍히게 됩니다.

Murax 시뮬레이션에서 UART 모니터링 스레드가 정확한 타이밍으로 비트를 샘플링하려면, **시스템 클럭 주파수**와 **보드 레이트(Baud Rate)** 사이의 비율을 정확히 계산해야 합니다.

---

### 1. 기본 계산 공식

1비트(Bit)를 전송하는 데 소요되는 클럭 사이클 수(Cycles per Bit)는 다음과 같이 간단한 나눗셈으로 구할 수 있습니다:

$$\text{Cycles per Bit} = \frac{\text{System Clock Frequency (Hz)}}{\text{Baud Rate (bps)}}$$

* **System Clock Frequency:** Murax SoC가 동작하는 클럭 주파수 (예: 50 MHz = $50,000,000\text{ Hz}$)
* **Baud Rate:** UART 통신 속도 (예: 115200 bps)

---

### 2. 구체적인 계산 예시

만약 Murax 시스템 클럭을 **50 MHz**로 설정하고, UART 보드 레이트를 **115200**으로 설정했다면:

$$\text{Cycles per Bit} = \frac{50,000,000}{115200} \approx 434.027 \text{ clock cycles}$$

즉, UART 데이터 스트림에서 1비트의 길이는 **약 434개의 클럭 사이클**에 해당합니다.

---

### 3. SpinalSim 코드에 적용하는 방법 (클럭 사이클 기반)

시간 단위(`sleep`) 대신 SpinalSim의 클럭 샘플링 기능(`waitSampling`)을 활용하면 소수점 오차 없이 훨씬 깔끔하고 정확하게 구현할 수 있습니다.

```scala
// 50 MHz 클럭, 115200 Baud 기준 1비트당 클럭 사이클 수 (반올림 또는 정수 변환)
val cyclesPerBit = 50000000 / 115200 // 약 434 사이클

fork {
  println(s"[UART Monitor] Started. Cycles per bit: $cyclesPerBit")

  while(true) {
    // 1. Start Bit 대기 (라인이 Low로 떨어질 때)
    waitUntil(dut.io.uart.txd.toBoolean == false)

    // 2. Start Bit 중앙으로 이동 (1.5 비트 주기만큼 클럭 대기)
    // waitSampling(n)을 사용하면 클럭 에지 기준으로 정확하게 대기할 수 있습니다.
    dut.clockDomain.waitSampling((cyclesPerBit * 1.5).toInt)

    // 3. 8개의 데이터 비트 읽기 (LSB First)
    var charValue = 0
    for (i <- 0 until 8) {
      if (dut.io.uart.txd.toBoolean) {
        charValue |= (1 << i)
      }
      // 다음 비트 중앙으로 이동
      dut.clockDomain.waitSampling(cyclesPerBit)
    }

    // 4. Stop Bit 대기 후 출력
    dut.clockDomain.waitSampling(cyclesPerBit)
    
    print(charValue.toChar)
    System.out.flush()
  }
}

```

SpinalHDL에서 Murax SoC의 시스템 클럭 주파수를 변경하거나 설정하는 방법은 **Murax 자체의 코드 내부**가 아니라, **SoC를 생성하고 클럭 도메인(ClockDomain)을 구동하는 탑레벨(Top-level) 또는 시뮬레이션(Sim) 코드**에서 결정됩니다.

Murax SoC는 내부적으로 클럭 생성기를 직접 내장하기보다 외부에서 공급되는 클럭 신호(`io.asyncReset` 및 클럭 소스)에 의존하는 구조이기 때문입니다.

### 1. 시뮬레이션(Sim) 환경에서 클럭 주파수 변경하기

시뮬레이션 단계에서는 `forkStimulus`에 전달하는 **주기(Period)** 값으로 클럭 주파수가 결정됩니다. 타임유닛(Time Unit) 설정에 따라 달라지지만, 일반적으로 1 타임유닛이 1 나노초(ns)라고 가정할 때 주기를 조절합니다.

* **예시: 50 MHz 클럭 설정 (주기 20ns)**
```scala
// 20ns 주기 = 50 MHz
dut.clockDomain.forkStimulus(period = 20) 

```


* **예시: 100 MHz 클럭 설정 (주기 10ns)**
```scala
// 10ns 주기 = 100 MHz
dut.clockDomain.forkStimulus(period = 10) 

```

### 2. 하드웨어(FPGA 합성) 환경에서 클럭 주파수 변경하기

실제 FPGA(예: Xilinx/Intel) 보드에 올릴 때는 보드에 장착된 실제 오실레이터(Crystal Oscillator, 예: 12MHz, 27MHz, 50MHz 등)의 주파수에 맞춰 탑레벨 래퍼(Top-level Wrapper)를 작성해야 합니다.

FPGA 내부의 **PLL(Phase-Locked Loop) IP**를 인스턴스화하여 원하는 시스템 클럭(예: 50MHz)으로 스케일링한 뒤 Murax에 공급합니다.

```scala
import spinal.core._
import vexriscv.demo.Murax

class MySoCTop extends Component {
  val io = new Bundle {
    val mainClk = in Bool()  // 보드의 실제 입력 클럭 (예: 12MHz)
    val asyncReset = in Bool()
    val uart = cloneOf(new Murax(MuraxConfig.default).io.uart)
    val gpio = cloneOf(new Murax(MuraxConfig.default).io.gpio)
  }

  // 1. 클럭 도메인 생성 (입력 클럭과 리셋 매핑)
  val systemClockDomain = ClockDomain(
    clock = io.mainClk,
    reset = io.asyncReset,
    config = ClockDomainConfig(
      resetActiveLevel = HIGH // 보드 사양에 따라 설정
    )
  )

  // 2. Murax SoC 인스턴스화 및 클럭 영역 할당
  val system = new ClockingArea(systemClockDomain) {
    val murax = new Murax(MuraxConfig.default)
    
    // 외장 핀 연결
    io.uart <> murax.io.uart
    io.gpio <> murax.io.gpio
  }
}

```

> **💡 핵심 요약:**
> * **UART 보드레이트 계산(`cyclesPerBit`)**에서 사용되는 주파수 값은 위에서 설정한 **실제 클럭 주파수(예: 50MHz)**와 일치해야 UART 모니터가 깨지지 않고 정확한 문자를 디코딩할 수 있습니다.
> * FPGA 합성 시에는 내부 페리페럴(특히 UART 브레이트 제네레이터)이 올바른 타이밍을 맞출 수 있도록 시스템 클럭 주파수 정보를 페리페럴 설정 객체(Config)에 정확히 넘겨주어야 합니다.
> 
>

Murax SoC에서 UART의 통신 속도(Baud Rate)는 하드웨어 단에서 고정된 값을 갖는 것이 아니라, **소프트웨어(C 펌웨어) 영역에서 하드웨어 레지스터에 클럭 디바이더(Clock Divider) 값을 계산해 써넣음으로써 동적으로 결정**됩니다.

즉, 시스템 클럭 주파수가 바뀌더라도 하드웨어 자체를 재설계할 필요 없이, 펌웨어 코드 내에서 계산식을 맞춰주면 됩니다.

### 1. 하드웨어 측면 (`MuraxConfig`)

SpinalHDL의 `MuraxConfig`에서는 UART 페리페럴이 사용할 수 있는 클럭 디바이더의 비트 폭(`clockDividerWidth` 등)을 정의합니다. 기본 설정으로도 충분히 넓은 대역폭을 지원하므로, 하드웨어 설정 구조체 자체에서 보드레이트를 직접 상수로 박아넣지 않습니다. 대신 전체 시스템의 기준 주파수(`coreFrequency`)를 명시합니다.

```scala
val config = MuraxConfig.default.copy(
  coreFrequency = 50 MHz // 시스템 클럭 주파수 정의
)

```

### 2. 소프트웨어(C 펌웨어) 측면에서 Baud Rate 설정 방법

실제 C 펌웨어가 부팅될 때 UART 레지스터에 클럭 디바이더 값(Clock Divider)을 계산해서 설정해 주어야 합니다.

SpinalHDL의 표준 UART 컨트롤러 계산 공식은 다음과 같습니다:

$$\text{Clock Divider} = \frac{\text{System Clock Frequency}}{\text{Baud Rate} \times \text{rxSamplePerBit}} - 1$$

* 여기서 `rxSamplePerBit`는 보통 기본값으로 **8** 또는 **5** 등이 사용됩니다 (Murax 기본 UART 설정 기준에 따름).

C 코드에서는 이를 다음과 같이 구현하여 시스템 클럭에 맞춰 Baud Rate를 일치시킵니다:

```c
#define SYSTEM_CLOCK_HZ  50000000 // 예: 50 MHz 시스템 클럭
#define TARGET_BAUD_RATE 115200   // 원하는 목표 보드레이트
#define RX_SAMPLE_PER_BIT 8       // 일반적인 샘플링 횟수 (설정에 따라 다름)

void uart_init() {
    // 클럭 디바이더 값 계산 및 레지스터 설정
    unsigned int divider = (SYSTEM_CLOCK_HZ / (TARGET_BAUD_RATE * RX_SAMPLE_PER_BIT)) - 1;
    
    // Murax UART 설정 레지스터에 디바이더 값 주입
    // (실제 Murax 16550 호환 혹은 커스텀 UART 레지스터 맵에 맞게 작성)
    UART_CLOCK_DIVIDER_REG = divider;
}

```

### 요약

1. **시스템 클럭 변경:** Murax를 구성할 때 `coreFrequency`나 탑레벨의 클럭 주파수를 변경합니다.
2. **펌웨어 반영:** C 펌웨어의 초기화 함수(`uart_init`)에서 변경된 `SYSTEM_CLOCK_HZ` 값을 바탕으로 클럭 디바이더를 다시 계산해 UART 레지스터에 설정해 주면, 시뮬레이션 및 실제 보드상에서 UART 통신이 정확한 보드레이트로 동기화됩니다.

Murax SoC의 표준 UART 페리페럴(`Apb3UartCtrl`)은 메모리 맵(Memory-Mapped I/O) 방식을 사용하여 레지스터에 접근합니다. 일반적으로 클럭 디바이더, 프레임 설정, 데이터 송수신 레지스터로 구성됩니다.

다음은 시스템 클럭 주파수와 보드레이트(Baud Rate)를 계산하여 초기화하고 문자를 송신하는 **전체 C 베어메탈 초기화 코드**입니다.

### Murax UART C 초기화 및 드라이버 코드 (`uart.h`)

```c
#ifndef UART_H
#define UART_H

// Murax UART Base Address (메모리 맵 기준)
#define UART_BASE_ADDR   0xF0010000

// UART Register Offsets (SpinalHDL UartCtrl 표준 기준)
#define UART_REG_CLK_DIV  0x00  // Clock Divider 레지스터 (RW)
#define UART_REG_FRAME    0x04  // Frame 설정 레지스터 (데이터 비트, 패리티 등) (RW)
#define UART_REG_DATA     0x08  // TX/RX Data / FIFO 레지스터
#define UART_REG_STATUS   0x0C  // 상태 및 가용 여부 확인 레지스터

// Pointer Macros for Register Access
#define UART_WRITE(offset, val) (*(volatile unsigned int *)(UART_BASE_ADDR + (offset)) = (val))
#define UART_READ(offset)       (*(volatile unsigned int *)(UART_BASE_ADDR + (offset)))

// 시스템 환경 설정값 (시뮬레이션 또는 보드 사양에 맞게 수정)
#define SYSTEM_CLOCK_HZ         50000000  // 예: 50 MHz 시스템 클럭
#define TARGET_BAUD_RATE        115200    // 목표 보드레이트

/**
 * UART 초기화 및 보드레이트 설정 함수
 */
void uart_init() {
    // 1. 클럭 디바이더 값 계산
    // 공식: Divider = (System Clock / (Baudrate * SamplePerBit)) - 1
    // (Murax 기본 UartCtrl은 샘플링 레이트로 보통 5 또는 8을 사용합니다.)
    unsigned int samplePerBit = 5; 
    unsigned int divider = (SYSTEM_CLOCK_HZ / (TARGET_BAUD_RATE * samplePerBit)) - 1;

    // 2. Clock Divider 레지스터에 값 반영
    UART_WRITE(UART_REG_CLK_DIV, divider);

    // 3. Frame 설정 (8 data bits, No parity, 1 stop bit)
    // 데이터 길이나 패리티 옵션을 지정하는 레지스터 설정
    UART_WRITE(UART_REG_FRAME, 0x07); // 8비트 데이터 프레임 기본 설정 예시
}

/**
 * 한 글자(1 Byte)를 UART로 전송하는 함수
 */
void uart_write_char(char c) {
    // (선택 사항) TX FIFO나 전송 버퍼가 빌 때까지 상태 레지스터 대기 로직 추가 가능
    // 여기서는 간단하게 Data 레지스터에 바로 밀어 넣는 방식을 사용합니다.
    UART_WRITE(UART_REG_DATA, c);
}

/**
 * 문자열을 순차적으로 전송하는 함수 (printf 및 로그 출력용)
 */
void uart_print(const char *str) {
    while (*str != '\0') {
        uart_write_char(*str);
        str++;
    }
}

#endif // UART_H

```

---

### 주요 코드 설명

1. **메모리 맵 레지스터 오프셋 (`UART_BASE_ADDR + Offset`)**
* `0x00 (Clock Divider)`: 보드레이트를 결정하는 클럭 분주비를 설정합니다.
* `0x04 (Frame Config)`: 데이터 비트 수(예: 8비트), 정지 비트(Stop bit), 패리티(Parity) 모드를 설정합니다.
* `0x08 (Data / FIFO)`: 데이터를 쓰면 TX 핀을 통해 송신되고, 읽으면 RX 핀으로 들어온 데이터를 가져옵니다.


2. **보드레이트 동적 계산 (`divider` 공식)**
* 시스템 클럭(`SYSTEM_CLOCK_HZ`)과 목표 보드레이트(`TARGET_BAUD_RATE`)를 나누어 하드웨어가 비트 타이밍을 정확히 맞추도록 분주비(`divider`)를 구한 뒤 `UART_REG_CLK_DIV`에 기록합니다.

앞서 작성한 UART 드라이버(`uart.h`)를 활용하여, 시뮬레이션 환경에서 부팅 로그와 주기적인 메시지를 출력하는 **C언어 `main.c` 펌웨어 예시**입니다.

이 코드는 온칩 메모리(`0x00000000`)에 적재되어 CPU가 켜지자마자 실행되며, 초기화 직후 UART를 통해 콘솔로 문자열을 송신합니다.

---

### `main.c` 구현 예시

```c
#include "uart.h"

// 간단한 지연(Delay) 함수 (루프를 돌며 시간 소모)
void delay(int count) {
    for (volatile int i = 0; i < count; i++);
}

int main() {
    // 1. UART 컨트롤러 및 보드레이트 초기화
    uart_init();

    // 2. 부팅 완료 메시지 출력
    uart_print("\r\n=== Murax SoC Simulation Started ===\r\n");

    int counter = 0;

    // 3. 메인 루프 (주기적인 로그 출력)
    while (1) {
        uart_print("Heartbeat: Alive in SpinalSim!\r\n");
        
        // 시뮬레이션 상에서 눈으로 확인할 수 있도록 충분한 간격 주기
        delay(100000); 
    }

    return 0;
}

```

---

### 작동 흐름 요약

1. **초기화 (`uart_init()`)**:
* `SYSTEM_CLOCK_HZ`와 `TARGET_BAUD_RATE`를 바탕으로 클럭 분주비를 계산해 Murax의 UART 레지스터에 기록합니다.


2. **로그 전송 (`uart_print()`)**:
* 문자열의 각 문자를 차례대로 UART 데이터 레지스터에 써 넣습니다.


3. **SpinalSim 연동**:
* 앞서 구성한 UART 모니터링 스레드가 이 전송 신호(TX 핀의 파형 변화)를 실시간으로 캐치하여, SBT(Scala) 실행 콘솔창에 `"Heartbeat: Alive in SpinalSim!"` 문구를 그대로 띄워주게 됩니다.

`main.c`, `uart.h`, 스타트업 코드(`crt0.s`), 그리고 링커 스크립트(`linker.ld`)를 준비했다면, RISC-V GCC 툴체인을 사용하여 SpinalSim에서 로드할 수 있는 최종 바이너리(`firmware.bin`)를 생성할 수 있습니다.

다음은 터미널에서 실행하여 바이너리를 빌드하는 표준 과정입니다.

### 1단계: 필수 파일 준비 확인

프로젝트 디렉토리(또는 시뮬레이션 폴더)에 다음 4개의 파일이 모두 위치해 있는지 확인합니다.

* `main.c` (메인 루프 및 UART 로그 출력)
* `uart.h` (UART 드라이버 및 레지스터 맵)
* `crt0.s` (스택포인터 설정 및 `main` 진입 어셈블리 코드)
* `linker.ld` (온칩 메모리 주소 맵 설정 링커 스크립트)

---

### 2단계: 컴파일 및 링크 (ELF 파일 생성)

터미널을 열고 아래 명령어를 실행하여 32비트 RISC-V 아키텍처(`rv32i`) 기준으로 소스코드를 컴파일하고 링크합니다.

```bash
riscv64-unknown-elf-gcc -march=rv32i -mabi=ilp32 -nostdlib -T linker.ld crt0.s main.c -o firmware.elf

```

* **`-march=rv32i -mabi=ilp32`**: Murax SoC의 VexRiscv 코어가 지원하는 32비트 기본 정수 명령어 세트(RV32I)와 표준 32비트 ABI를 지정합니다.
* **`-nostdlib`**: OS나 표준 라이브러리(libc) 없이 베어메탈 환경에서 구동되도록 표준 라이브러리 링크를 제외합니다.
* **`-T linker.ld`**: 앞서 정의한 메모리 맵(`0x00000000`)에 맞게 주소를 배치하도록 링커 스크립트를 적용합니다.
* **Verification:** 오류 메시지 없이 `firmware.elf` 파일이 성공적으로 생성되는지 확인합니다.

---

### 3단계: 순수 바이너리 파일 추출 (`firmware.bin`)

생성된 ELF 파일에서 실제 하드웨어 메모리에 올라갈 순수 기계어 데이터만 추출하여 `.bin` 파일로 변환합니다.

```bash
riscv64-unknown-elf-objcopy -O binary firmware.elf firmware.bin

```

* **Verification:** 생성된 `firmware.bin` 파일의 용량이 온칩 메모리 크기(예: 몇 킬로바이트 내외) 이내로 정상 생성되었는지 파일 크기를 확인합니다.

이제 이 `firmware.bin` 파일을 SpinalHDL 시뮬레이션 디렉토리에 두고 `dut.ram.memory.loadBinary("firmware.bin")`을 통해 불러오면, 시뮬레이션 구동 시 CPU가 펌웨어를 실행하게 됩니다.

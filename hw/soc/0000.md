SpinalHDL로 System on Chip(SoC)을 가장 빠르고 효율적으로 구현하는 방법은 **SpinalHDL 전용 RISC-V 프로세서인 VexRiscv와 
제공되는 레퍼런스 SoC 템플릿(Murax 등), 그리고 자동화 라이브러리(`BusSlaveFactory`)를 활용하는 것** 입니다.

처음부터 모든 걸 짜는 대신, 이미 검증된 템플릿과 툴을 조합하면 몇 시간 안에 동작하는 SoC를 구축할 수 있습니다. 가장 빠른 3가지 핵심 접근법입니다.

---

### 1. `Murax` 또는 `Briey` SoC 템플릿 활용하기 (가장 빠름)

SpinalHDL 생태계에는 이미 완성된 오픈소스 RISC-V SoC 구조가 준비되어 있습니다. 
이를 수정(Customizing)하여 원하는 구조로 빠르게 탈바꿈시키는 것이 가장 빠릅니다.

* **Murax SoC (`vexriscv.demo.Murax`)**:
* 외장 메모리(SDRAM 등) 없이 FPGA 내부 자원(On-chip RAM, 8KB 등)만으로 동작하는 초경량 SoC입니다.
* VexRiscv CPU, APB3 버스, UART, Timer, GPIO, JTAG 디버거가 기본 포함되어 있습니다.
* 소스코드 구조(`src/main/scala/vexriscv/demo/Murax.scala`)를 입맛에 맞게 커스텀하여 빠르게 빌드할 수 있습니다.


* **Briey / Pinsec SoC**:
* AXI4 버스, SDRAM 컨트롤러, 캐시 등이 포함된 조금 더 고성능의 SoC 템플릿입니다.



---

### 2. `BusSlaveFactory`로 커스텀 페리페럴(Peripheral) 빠르게 만들기

SoC에 자신만의 하드웨어 가속기나 커스텀 IP를 붙일 때 가장 번거로운 작업은 **메모리 맵(Memory-mapped) 주소 복호화 및 
레지스터 인터페이스 구현** 입니다. SpinalHDL은 이를 자동화해 주는 `BusSlaveFactory`를 제공합니다.

```scala
// APB3 버스를 사용하는 커스텀 IP 페리페럴 예시
class MyCustomIP extends Component {
  val io = new Bundle {
    val bus = slave(APB3(addressWidth = 4, dataWidth = 32))
    val customSignal = out Bool()
  }

  // 레지스터 정의
  val myReg = Reg(UInt(32 bits)) init(0)
  io.customSignal := myReg(0)

  // BusSlaveFactory를 이용해 APB3 버스와 레지스터를 단 몇 줄로 매핑
  val busCtrl = Apb3SlaveFactory(io.bus)
  busCtrl.driveAndRead(myReg, address = 0x00) // 0x00 번지에 레지스터 매핑
}

```

* 수십 줄의 Verilog 주소 디코딩 로직을 작성할 필요 없이, 단 한 줄(`driveAndRead`)로 CPU가 제어할 수 있는 레지스터가 생성됩니다.

---

### 3. VexRiscv의 플러그인(Plugin) 구조 활용

SoC의 핵심인 CPU를 커스텀할 때, VexRiscv는 **플러그인 기반**으로 설계되어 있어 필요한 기능만 꼈다 뺐다 할 수 있습니다.

* 곱셈/나눗셈(MUL/DIV) 확장, 캐시(Cache), MMU(Linux 구동용), 디버그 인터페이스 등을 설정 객체(Config) 수정만으로 쉽게 조합할 수 있습니다.

### 🚀 추천 개발 순서 (Quick Start)

1. **SpinalTemplateSbt** 공식 템플릿 프로젝트를 클론하여 기본 개발 환경을 세팅합니다.
2. `VexRiscv` 레포지토리의 `vexriscv.demo.Murax` 코드를 참고하여 프로젝트에 SoC Top-level을 가져옵니다.
3. 필요한 자신만의 하드웨어 로직을 추가하고 `BusSlaveFactory`로 SoC 버스에 연결합니다.
4. SpinalSim을 통해 시뮬레이션 검증 후 Verilog를 생성(`sbt run`)하여 FPGA에 올립니다.

`vexriscv.demo.Murax`는 외장 메모리(DRAM) 없이 **FPGA 내부의 온칩 메모리(BRAM)만으로 동작하는 초경량 RISC-V SoC(System on Chip) 템플릿**입니다. 베어메탈(Bare-metal) 임베디드 소프트웨어를 돌리거나 가벼운 제어용 SoC를 만들 때 가장 이상적인 구조를 가지고 있습니다.

Murax SoC의 핵심 작동 원리와 구조를 파악하면, 자신의 프로젝트로 코드를 가져와 커스텀하는 데 큰 도움이 됩니다.

### 1. Murax의 전체 아키텍처 및 작동 원리

Murax SoC는 크게 CPU, 버스 인터커넥트, 온칩 메모리, 그리고 페리페럴(주변장치)의 4가지 축으로 구성되어 있습니다.

#### ① VexRiscv CPU 설정 (Config)

* **초경량 플러그인 조합:** Murax에 사용되는 VexRiscv는 리소스(FPGA LUT)를 최소화하기 위해 MMU나 복잡한 캐시를 뺍니다. 대신 RV32I(또는 RV32IM) 명령어 세트, 디버그 플러그인, 인터럽트 제어 플러그인 등 **최소한의 필수 기능만 조합**(`VexRiscvParameter` 정의)하여 생성됩니다.
* **파이프라인:** 단일 발행(Single-issue) 2단계 또는 3단계 파이프라인 구조를 사용하여 고속 동작과 적은 면적을 동시에 달성합니다.

#### ② 버스 구조 (APB3 기반 인터커넥트)

* 복잡하고 무거운 AXI 버스 대신, 구조가 단순하고 가벼운 **APB3 버스**를 SoC 전체의 메인 통신망으로 사용합니다.
* CPU가 메모리나 페리페럴에 접근할 때, **APB3 Decoder**가 주소(Address)를 해석하여 해당하는 장치(RAM, UART, GPIO 등)로 신호를 라우팅해 줍니다.

#### ③ 온칩 메모리 (On-Chip RAM / ROM)

* 별도의 외부 메모리 컨트롤러(DDR 등)가 필요 없습니다. CPU의 명령어 페치(Instruction Fetch)와 데이터 읽기/쓰기가 모두 내부 BRAM 공간에서 이루어집니다.
* 보통 SoC가 부팅될 때 실행할 펌웨어(Firmware)가 이 온칩 메모리 영역에 같이 로드되도록 설계됩니다.

#### ④ 기본 내장 페리페럴

Murax 내부에는 임베디드 시스템에 필수적인 장치들이 APB3 슬레이브 형태로 단단히 결합되어 있습니다.

* **GPIO:** 외부 핀 제어 및 상태 읽기
* **Timer:** 시스템 틱(Tick) 및 인터럽트 발생
* **UART:** 시리얼 통신 (디버깅 및 로그 출력용)
* **JTAG:** OpenOCD 등과 연동하여 실시간으로 CPU 레지스터를 디버깅할 수 있는 인터페이스

### 2. 내 프로젝트로 Murax 코드를 가져와 커스텀하는 방법

Murax의 구조를 파악했다면, 실제 코드를 프로젝트에 이식하고 수정하는 절차는 다음과 같습니다.

1. **소스 파일 복사:**
* VexRiscv 공식 GitHub 리포지토리의 `src/main/scala/vexriscv/demo/Murax.scala` 파일을 자신의 프로젝트 `src/main/scala/` 경로 아래 적절한 패키지로 가져옵니다.
* 필요에 따라 Murax 내부에서 참조하는 페리페럴 파일들(`MuraxMemoryMapping.scala`, 각종 APB3 페리페럴 소스 등)도 함께 가져와야 합니다.


2. **Top-level 파라미터 수정 (`Murax` 클래스 구조 분석):**
* `Murax` 클래스 내부를 보면 `val cpuConfig = VexRiscvConfig(...)` 부분에서 CPU가 지원할 기능(곱셈기, 디버그 등)을 정의합니다. 이곳에서 원하는 기능을 켜고 끌 수 있습니다.
* 메모리 크기(On-chip RAM size)나 페리페럴 주소 맵(Memory Mapping) 상수를 입맛에 맞게 변경합니다.


3. **커스텀 페리페럴(IP) 추가하기:**
* 자신만의 하드웨어 가속기나 센서 인터페이스를 추가하고 싶다면, 앞서 다룬 `BusSlaveFactory`를 이용해 APB3 슬레이브 형태로 페리페럴을 만든 뒤 Murax의 APB3 Decoder 버스 라우팅 목록에 추가(Map)해주면 됩니다.

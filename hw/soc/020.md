# 다음 단계: 두 번째 Slave 추가

이제부터가 진짜 **Bus/SoC 학습**입니다.

현재:

```text
0x0000_0000 ~ 0x0000_03FF
        │
        ▼
      RAM
```

여기에 아주 작은 GPIO peripheral을 추가하겠습니다.

```text
                 ┌── 0x0000_0000 ~ 0x0000_03FF → RAM
                 │
VexRiscv → DBus ─┤
                 │
                 └── 0x1000_0000 ~ 0x1000_000F → GPIO
```

GPIO는 우선 아주 단순하게:

```text
WRITE 0x10000000
        │
        ▼
     gpioValue
```

형태로 만들겠습니다.

그리고 CPU 프로그램을:

```text
ADDI x1, x0, 1
SW   x1, 0(x0)          // RAM

ADDI x2, x0, 2
SW   x2, 4(x0)          // RAM

ADDI x4, x0, 0x55
SW   x4, 0x10000000     // GPIO

LW   x3, 0(x0)          // RAM read
SW   x3, 8(x0)           // RAM
```

처럼 구성해서 **RAM과 GPIO가 서로 다른 주소로 실제 분리되는 것**을 검증하는 것이 다음 목표입니다.

다만 여기서 중요한 차이가 하나 있습니다.

RAM은 Load response를 발생시키지만 GPIO의 Store는 response가 필요 없습니다. 따라서 이제 `DBusDecoder`가 단순히 command를 전달하는 수준을 넘어,

```text
어느 slave가 command를 받았는가?
        ↓
그 slave의 Load response를 CPU에 돌려줘야 하는가?
```

를 정확하게 처리해야 합니다.

**다음 단계에서는 이 response routing을 상태 없이 안전하게 구현하는 구조부터 만들겠습니다.**

좋습니다. 이제 **두 번째 Slave인 GPIO를 추가**하겠습니다.

이번 단계의 핵심은 단순히 GPIO를 붙이는 것이 아니라, **DBus Decoder가 Store와 Load의 response 경로를 올바르게 구분하는 것**입니다.

현재까지 확인된 DBus 특성상 CPU는 Load에서 response가 올 때까지 기다리므로, 동시에 여러 Load를 outstanding으로 만들 필요가 없습니다. 따라서 Decoder가 **현재 진행 중인 Load가 RAM 대상인지 기억하는 1-bit 상태**만 가지면 됩니다.

## 1. GPIO 추가

먼저 아주 단순한 **write-only GPIO**를 만듭니다.

주소:

```text
0x1000_0000
```

CPU가 여기에 Store하면 `gpioValue`가 변경됩니다.

```scala
package myvexsoc

import spinal.core._
import vexriscv.plugin._

class SimpleGpio extends Component {

  val io = new Bundle {
    val bus = slave(DBusSimpleBus())

    val value = out Bits(32 bits)
  }

  val gpioValue = Reg(Bits(32 bits)) init (0)

  io.bus.cmd.ready := True

  when(io.bus.cmd.fire && io.bus.cmd.wr) {
    gpioValue := io.bus.cmd.payload.data
  }

  io.value := gpioValue

  // GPIO는 이번 단계에서 write-only
  io.bus.rsp.ready := False
  io.bus.rsp.error := False
  io.bus.rsp.data := B(0, 32 bits)
}
```

여기서는 GPIO Load를 지원하지 않습니다.

즉:

```text
SW → GPIO     지원
LW ← GPIO     아직 지원하지 않음
```

# 2. DBusDecoder 수정

이번에는 RAM + GPIO를 동시에 처리합니다.

```scala
package myvexsoc

import spinal.core._
import vexriscv.plugin._

class DBusDecoder extends Component {

  val io = new Bundle {
    val cpu = slave(DBusSimpleBus())

    val ram = master(DBusSimpleBus())
    val gpio = master(DBusSimpleBus())
  }

  // ------------------------------------------------------------
  // Address decode
  // ------------------------------------------------------------

  val ramHit =
    io.cpu.cmd.address < U(0x00000400L, 32 bits)

  val gpioHit =
    io.cpu.cmd.address === U(0x10000000L, 32 bits)

  // ------------------------------------------------------------
  // CPU -> RAM
  // ------------------------------------------------------------

  io.ram.cmd.valid := io.cpu.cmd.valid && ramHit
  io.ram.cmd.payload := io.cpu.cmd.payload

  // ------------------------------------------------------------
  // CPU -> GPIO
  // ------------------------------------------------------------

  io.gpio.cmd.valid := io.cpu.cmd.valid && gpioHit
  io.gpio.cmd.payload := io.cpu.cmd.payload

  // ------------------------------------------------------------
  // CPU command ready
  // ------------------------------------------------------------

  io.cpu.cmd.ready := Mux(
    ramHit,
    io.ram.cmd.ready,
    Mux(
      gpioHit,
      io.gpio.cmd.ready,
      False
    )
  )

  // ------------------------------------------------------------
  // Remember which device owns a Load
  // ------------------------------------------------------------

  val ramLoadPending = Reg(Bool()) init (False)

  when(io.cpu.cmd.fire) {
    ramLoadPending := ramHit && !io.cpu.cmd.wr
  }

  when(io.cpu.rsp.ready) {
    ramLoadPending := False
  }

  // ------------------------------------------------------------
  // RAM response -> CPU
  // ------------------------------------------------------------

  io.cpu.rsp.ready := ramLoadPending && io.ram.rsp.ready
  io.cpu.rsp.data := io.ram.rsp.data
  io.cpu.rsp.error := io.ram.rsp.error
}
```

### 여기서 중요한 부분

```scala
val ramLoadPending = Reg(Bool()) init (False)
```

입니다.

예를 들어:

```text
Cycle N

CPU
  LOAD 0x00000000
       │
       ▼
    Decoder
       │
       ▼
     RAM
```

command가 받아들여지면:

```text
ramLoadPending = 1
```

이 됩니다.

다음 cycle:

```text
Cycle N+1

RAM
  rsp.ready = 1
  rsp.data  = 0x00000001
       │
       ▼
    Decoder
       │
       ▼
     CPU
```

Decoder는 `ramLoadPending`을 보고 이 response가 CPU로 전달되어야 한다는 것을 압니다.

# 4. 이번 테스트 프로그램

GPIO에 `0x55`를 쓰려면 RISC-V `ADDI`만으로는 충분하지만, **주소 `0x10000000`은 `LUI`를 사용해야 합니다.**

프로그램을 다음처럼 바꿉니다.

```text
ADDI x1, x0, 1
SW   x1, 0(x0)

ADDI x2, x0, 2
SW   x2, 4(x0)

LUI  x4, 0x10000
ADDI x4, x4, 0x55
SW   x4, 0(x4)

LW   x3, 0(x0)
SW   x3, 8(x0)

JAL  x0, 0
```

다만 여기에는 **한 가지 수정이 필요합니다.**

`SW x4, 0(x4)`는 주소도 `x4`이고 데이터도 `x4`이므로 `0x10000055`에 쓰게 됩니다.

따라서 GPIO 주소와 GPIO 데이터를 분리해야 합니다.

```text
LUI  x4, 0x10000      // x4 = 0x10000000
ADDI x5, x0, 0x55     // x5 = 0x55
SW   x5, 0(x4)        // GPIO[0] = 0x55
```

이것이 정확한 프로그램입니다.

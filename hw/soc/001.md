나의 SoC 구현 목표: 실제 RISC-V CPU를 사용한 SoC를 빠르게 구현하고 싶다. 개발 환경: 시뮬레이션부터 시작하고 나중에 FPGA. 이 목표에 맞춰 SpinalHDL 1.15.0 기준으로 구체적인 구현 계획을 세워줘.

좋습니다. 그러면 목표를 SpinalHDL 1.15.0 기반의 RISC-V SoC를 시뮬레이션으로 완성하고, 이후 FPGA에서 실제 구동하는 것으로 정하겠습니다.

이 프로젝트에서는 CPU 자체를 처음부터 구현하지 않습니다. 검증된 SpinalHDL 기반 RISC-V CPU인 VexRiscv를 사용하고, SoC의 나머지 부분을 직접 구성하는 전략을 추천합니다.

핵심은 다음과 같습니다.

- CPU: VexRiscv
- SoC 구성: 직접 설계
- Bus: Wishbone 또는 APB3부터 시작
- Memory: ROM / RAM
- Peripheral: UART / GPIO / Timer
- Simulation: SpinalSim
- FPGA: Verilog 생성 후 FPGA 합성 및 구현
- Software: RISC-V GCC로 C 프로그램 빌드

최종 목표는 PC에서 C 프로그램을 컴파일한 후, 우리가 만든 SoC의 RAM/ROM에 넣어 실제 RISC-V CPU가 실행하는 것입니다.

# 2. 구현 전략: Murax를 출발점으로 사용

여기서 중요한 선택이 하나 있습니다.

VexRiscv를 직접 인스턴스화하는 것보다 Murax를 먼저 실행해 보는 것이 훨씬 빠릅니다.

Murax는 이미 VexRiscv, RAM, APB Peripheral, UART, GPIO, Timer, Interrupt 기능을 통합한 작은 SoC입니다.

공식 프로젝트에서 제공하는 기능은 다음과 같습니다.

| 구성             | Murax                |
| -------------- | -------------------- |
| CPU            | VexRiscv RV32I[M]    |
| On-chip RAM    | 8 KB                 |
| Peripheral Bus | APB                  |
| UART           | TX/RX FIFO 포함        |
| GPIO           | 32 bit               |
| Timer          | Prescaler 및 2개 Timer |
| Interrupt      | 지원                   |
| Debug          | JTAG / GDB / OpenOCD |

Murax는 iCE40 FPGA까지 고려한 경량 SoC이며, UART Echo와 LED Blink 예제도 제공합니다.

따라서 다음 두 가지를 병행하지 않고 순서대로 진행하겠습니다.

1. 기존 Murax를 실행해 RISC-V SoC 전체 구조를 확인합니다.
2. Murax 구조를 참고하여 필요한 부분을 우리 프로젝트에 통합합니다.

이렇게 하면 CPU 내부 구현에 시간을 낭비하지 않으면서 SoC 설계 방법을 익힐 수 있습니다.

# 5. SpinalHDL 1.15.0 호환성 전략 — 중요

이 부분은 시작할 때 반드시 확인해야 합니다.

VexRiscv 공식 README에는 일부 버전에서 SpinalHDL의 unreleased master 버전이 필요할 수 있다고 명시되어 있습니다. 
따라서 현재 프로젝트의 SpinalHDL 1.15.0과 바로 호환된다고 가정하면 안 됩니다.

다음 순서로 처리하겠습니다.

| 단계 | 작업                            |
| -- | ----------------------------- |
| 1  | 기존 SpinalHDL 1.15.0 환경 보존     |
| 2  | VexRiscv 소스의 특정 commit 고정     |
| 3  | 의존성 및 Scala 버전 확인             |
| 4  | VexRiscv 단독 RTL 생성            |
| 5  | 1.15.0에서 컴파일 및 시뮬레이션 검증       |
| 6  | 호환성 문제가 있으면 별도 수정 또는 독립 빌드 검토 |

중요한 원칙: SpinalHDL 1.15.0을 무작정 업그레이드하지 않겠습니다. 기존 학습 프로젝트의 환경도 그대로 유지하겠습니다.

# 6. 시뮬레이션 검증 전략

| 검증 항목       | 확인 내용                         |
| ----------- | ----------------------------- |
| CPU Boot    | Reset 해제 후 정상적인 명령어 Fetch     |
| Instruction | ADD, SUB, LOAD, STORE, BRANCH |
| Memory      | 주소 및 데이터 정합성                  |
| Bus         | 요청과 응답 타이밍                    |
| Peripheral  | Register Read / Write         |
| UART        | 송수신 데이터 일치                    |
| Interrupt   | Interrupt 발생 및 처리             |
| Firmware    | C 프로그램 정상 실행                  |

추가로 다음 원칙을 적용합니다.

- 모든 시뮬레이션에 Timeout 적용
- Clock Edge 기준으로 정확하게 동기화
- Handshake의 `valid`, `ready`, `fire` 확인
- CPU 명령어 실행 결과를 Reference와 비교
- 필요 신호만 `simPublic()`으로 노출
- VCD 파형으로 실제 실행 흐름 확인
- 성공한 테스트는 회귀 테스트로 유지

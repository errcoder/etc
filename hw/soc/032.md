`DBusDecoder.scala`와 업로드한 `CpuConfig.scala`를 확인했습니다. 현재 설정에서 중요한 점은 다음과 같습니다.

- `DBusSimplePlugin(catchAccessFault = true)`가 이미 활성화되어 있어 기존 Load Access Fault 처리는 유지할 수 있습니다.
- `mtvec`는 `0x80000120`으로 설정되어 있습니다.
- DBusDecoder는 RAM과 GPIO의 정상 명령을 각 장치로 전달하고, Unmapped Load에는 한 사이클 뒤 오류 응답을 생성합니다.
- Unmapped Store는 현재 `ready = False`이므로 CPU가 해당 명령에서 정지합니다.

Store 오류를 추가하려면 DBusDecoder에 `storeFault` 신호를 추가하고, 이를 CPU 파이프라인의 올바른 명령에 연결해야 합니다. 아직은 그 연결 코드를 확정하지 않겠습니다. 특히 Store 명령의 PC와 주소가 Execute stage에서 정확히 일치하는지가 핵심입니다.

## 2. Execute stage에서 예외를 발생시키는 근거

정확한 커밋의 `DBusSimplePlugin.scala`를 확인했습니다.

현재 DBusSimplePlugin은 Execute stage에서 다음 신호를 생성합니다.

```scala
dBus.cmd.valid := arbitration.isValid &&
                  input(MEMORY_ENABLE) &&
                  !arbitration.isStuckByOthers &&
                  !arbitration.isFlushed &&
                  !skipCmd &&
                  !cmdSent

dBus.cmd.address := input(SRC_ADD).asUInt
```

따라서 DBusDecoder의 Store handshake와 Execute stage의 Store 명령은 같은 사이클에 대응합니다.

또한 CsrPlugin의 예외 처리기는 Execute stage에 등록된 예외 포트도 지원합니다. 해당 stage에서 예외가 발생하면 명령을 제거하고 이후 stage로 예외 상태를 전달합니다. 최종 Trap 처리에서는 해당 명령의 PC를 `mepc`에, 예외 포트의 `badAddr`를 `mtval`에 기록합니다.

따라서 신규 플러그인은 다음 형태로 구현할 수 있습니다.

- 예외 포트: `pipeline.execute`
- 예외 코드: `7`
- 예외 주소: `execute.input(SRC_ADD)`
- 예외 발생 조건: DBusDecoder가 전달하는 `storeFault` 입력

이 방식은 기존 DBusSimplePlugin의 Load 응답 처리 코드를 건드리지 않습니다.

## 3. 이제 필요한 파일은 하나입니다

`CpuConfig.scala`와 `DBusDecoder.scala`는 확인했습니다. `VexRiscvTop.scala` 전체 코드를 보내주세요.

이 파일이 필요한 이유는 다음과 같습니다.

1. `StoreAccessFaultPlugin` 인스턴스를 CPU 플러그인 목록에 추가해야 합니다.
2. 신규 플러그인의 입력과 `DBusDecoder.io.storeFault`를 연결해야 합니다.
3. CPU 내부 플러그인과 DBusDecoder 사이의 실제 연결 구조를 확인해야 합니다.

Top까지 확인하면 세 파일의 변경 내용을 서로 일치하도록 작성하겠습니다. 아직 검증하지 않은 코드를 완성본이라고 제시하지 않겠습니다.

`VexRiscvTop.scala`까지 확인했습니다. 이제 세 파일의 연결 구조가 모두 드러났습니다.

현재 Top에서는 CPU 플러그인 목록을 순회하면서 `DBusSimplePlugin`의 `dBus`를 `DBusDecoder`에 연결하고 있습니다. 
따라서 신규 플러그인도 같은 방식으로 `cpu.plugins`에서 찾아 DBusDecoder의 Store fault 신호를 연결하면 됩니다.

다만 한 가지는 설계상 중요합니다. 신규 플러그인은 단순히 `DBusDecoder`의 출력 신호만 보는 것이 아니라, Execute stage의 유효한 Store 명령과 
해당 handshake가 동시에 성립했을 때만 예외를 발생시켜야 합니다. 그래야 stall이나 flush 상황에서 엉뚱한 명령에 예외가 붙지 않습니다.

이제 실제 구현으로 넘어가겠습니다. 기존 Load 오류 경로와 GPIO/RAM 동작은 유지하고, Store 오류에만 신규 예외 포트를 추가합니다.

구현은 다음 세 가지 수정과 신규 파일 하나로 구성합니다.

## 1. 신규 파일: `StoreAccessFaultPlugin.scala`

프로젝트의 `src/main/scala/myvexsoc/`에 추가하세요.

```scala
package myvexsoc

import spinal.core._
import spinal.lib._
import vexriscv._
import vexriscv.plugin._

class StoreAccessFaultPlugin(
    dbusPlugin: DBusSimplePlugin
) extends Plugin[VexRiscv] {

  // DBusDecoder에서 전달받는 Store fault 입력
  var storeFault: Bool = null

  // CsrPlugin에 등록할 예외 포트
  private var exceptionPort: Flow[ExceptionCause] = null

  override def setup(pipeline: VexRiscv): Unit = {

    val exceptionService =
      pipeline.service(classOf[ExceptionService])

    // Execute stage에서 Store Access Fault 발생
    exceptionPort =
      exceptionService.newExceptionPort(
        pipeline.execute
      )
  }

  override def build(pipeline: VexRiscv): Unit = {

    import pipeline._

    // VexRiscv CPU의 외부 입력 포트
    storeFault =
      in Bool().setName("storeFault")

    execute plug new Area {

      import execute._

      // DBusDecoder가 같은 사이클에 발생시킨
      // Store Access Fault를 그대로 전달한다.
      exceptionPort.valid := storeFault

      // RISC-V Store/AMO Access Fault
      exceptionPort.code := 7

      // DBusSimplePlugin이 실제 발행한 Store 주소
      exceptionPort.badAddr :=
        dbusPlugin.dBus.cmd.address
    }
  }
}
```

### 이 코드에서 중요한 부분

`storeFault`는 별도의 레지스터를 통과하지 않습니다.

```scala
exceptionPort.valid := storeFault
```

DBusDecoder의 Store handshake가 발생한 바로 그 사이클에 Execute stage의 예외 포트가 활성화됩니다.

주소도 별도로 재계산하지 않고 실제 DBus 명령의 주소를 사용합니다.

```scala
exceptionPort.badAddr := dbusPlugin.dBus.cmd.address
```

현재 CPU 설정에는 MMU가 없으므로 DBus 명령 주소가 실제 접근 주소입니다.

CsrPlugin은 이 예외 포트를 기존 예외 포트들과 통합하며, 해당 stage의 명령을 제거하고 예외 정보를 전달합니다. 
따라서 기존 CsrPlugin의 Trap 처리 코드는 변경하지 않습니다.

## 2. 수정 파일: `DBusDecoder.scala`

기존 코드를 최대한 유지하면서 다음 두 부분만 변경합니다.

1. `io.storeFault` 출력 추가
2. Unmapped Store도 명령을 받아들이도록 변경

전체 코드는 다음과 같습니다.

```scala
package myvexsoc

import spinal.core._
import spinal.lib.{master, slave}
import vexriscv.plugin._

class DBusDecoder extends Component {

  val io = new Bundle {
    val cpu = slave(DBusSimpleBus())
    val ram = master(DBusSimpleBus())
    val gpio = master(DBusSimpleBus())

    // Unmapped Store Access Fault
    val storeFault = out Bool()
  }

  // ------------------------------------------------------------
  // Address decoding
  // ------------------------------------------------------------

  // RAM:
  // 0x00000000 ~ 0x000003FF
  val ramHit =
    io.cpu.cmd.address < U(0x00000400L, 32 bits)

  // GPIO:
  // 0x10000000 ~ 0x1000000F
  val gpioHit =
    io.cpu.cmd.address(31 downto 4) === U(0x01000000, 28 bits)

  // ------------------------------------------------------------
  // Command forwarding
  // ------------------------------------------------------------

  io.ram.cmd.valid :=
    io.cpu.cmd.valid && ramHit

  io.ram.cmd.payload :=
    io.cpu.cmd.payload

  io.gpio.cmd.valid :=
    io.cpu.cmd.valid && gpioHit

  io.gpio.cmd.payload :=
    io.cpu.cmd.payload

  // ------------------------------------------------------------
  // CPU command acceptance
  //
  // RAM/GPIO:
  //   Target peripheral controls ready.
  //
  // Unmapped Load:
  //   Accept immediately and generate Error Response.
  //
  // Unmapped Store:
  //   Accept immediately and generate Store Access Fault.
  // ------------------------------------------------------------

  io.cpu.cmd.ready := Mux(
    ramHit,
    io.ram.cmd.ready,
    Mux(
      gpioHit,
      io.gpio.cmd.ready,
      True
    )
  )

  // ------------------------------------------------------------
  // Store Access Fault
  // ------------------------------------------------------------

  io.storeFault :=
    io.cpu.cmd.fire &&
    io.cpu.cmd.wr &&
    !ramHit &&
    !gpioHit

  // ------------------------------------------------------------
  // Load command detection
  // ------------------------------------------------------------

  val loadFire =
    io.cpu.cmd.fire && !io.cpu.cmd.wr

  val unmappedLoadFire =
    loadFire && !ramHit && !gpioHit

  // ------------------------------------------------------------
  // Load response ownership
  // ------------------------------------------------------------

  val OWNER_NONE = U(0, 2 bits)
  val OWNER_RAM = U(1, 2 bits)
  val OWNER_GPIO = U(2, 2 bits)
  val OWNER_ERROR = U(3, 2 bits)

  val loadOwner =
    Reg(UInt(2 bits)) init (OWNER_NONE)

  // Unmapped Load Error Response:
  // one cycle after the command is accepted.
  val errorPending =
    RegNext(unmappedLoadFire) init (False)

  // A newly accepted Load takes priority over clearing
  // the previous response owner.
  when(loadFire) {
    when(ramHit) {
      loadOwner := OWNER_RAM
    } elsewhen (gpioHit) {
      loadOwner := OWNER_GPIO
    } otherwise {
      loadOwner := OWNER_ERROR
    }
  } elsewhen (io.cpu.rsp.ready) {
    loadOwner := OWNER_NONE
  }

  // ------------------------------------------------------------
  // Response valid
  // ------------------------------------------------------------

  io.cpu.rsp.ready :=
    (loadOwner === OWNER_RAM && io.ram.rsp.ready) ||
      (loadOwner === OWNER_GPIO && io.gpio.rsp.ready) ||
      (loadOwner === OWNER_ERROR && errorPending)

  // ------------------------------------------------------------
  // Response data
  // ------------------------------------------------------------

  io.cpu.rsp.data :=
    Mux(
      loadOwner === OWNER_RAM,
      io.ram.rsp.data,
      Mux(
        loadOwner === OWNER_GPIO,
        io.gpio.rsp.data,
        B(0, 32 bits)
      )
    )

  // ------------------------------------------------------------
  // Response error
  // ------------------------------------------------------------

  io.cpu.rsp.error :=
    Mux(
      loadOwner === OWNER_RAM,
      io.ram.rsp.error,
      Mux(
        loadOwner === OWNER_GPIO,
        io.gpio.rsp.error,
        loadOwner === OWNER_ERROR && errorPending
      )
    )
}
```

여기서 주의할 점은 Unmapped Store에 대해 `rsp.error`를 발생시키지 않는다는 것입니다.

Store 예외는 `storeFault`를 통해 Execute stage로 직접 전달합니다. Load 응답 소유권 관리에는 Store가 개입하지 않습니다.

## 3. 수정 파일: `CpuConfig.scala`

기존 DBusSimplePlugin 인스턴스를 변수로 분리하고, 그 인스턴스를 신규 플러그인에 전달합니다.

```scala
package myvexsoc

import spinal.core._
import vexriscv._
import vexriscv.plugin._
import vexriscv.{plugin => vexPlugin}

object CpuConfig {

  val csrConfig =
    CsrPluginConfig
      .smallest(BigInt("80000120", 16))
      .copy(
        mepcAccess = CsrAccess.READ_WRITE,
        mbadaddrAccess = CsrAccess.READ_ONLY
      )

  def smallest(): VexRiscvConfig = {

    // DBusSimplePlugin instance
    val dbusPlugin =
      new DBusSimplePlugin(
        catchAddressMisaligned = false,
        catchAccessFault = true
      )

    // Store Access Fault plugin
    val storeFaultPlugin =
      new StoreAccessFaultPlugin(dbusPlugin)

    VexRiscvConfig(
      plugins = List(

        new IBusSimplePlugin(
          resetVector = 0x80000000L,
          cmdForkOnSecondStage = false,
          cmdForkPersistence = false,
          prediction = NONE,
          catchAccessFault = false,
          compressedGen = false
        ),

        dbusPlugin,

        storeFaultPlugin,

        new CsrPlugin(
          csrConfig
        ),

        new DecoderSimplePlugin(
          catchIllegalInstruction = false
        ),

        new RegFilePlugin(
          regFileReadyKind = vexPlugin.SYNC,
          zeroBoot = false
        ),

        new IntAluPlugin,

        new SrcPlugin(
          separatedAddSub = false,
          executeInsertion = false
        ),

        new LightShifterPlugin,

        new HazardSimplePlugin(
          bypassExecute = false,
          bypassMemory = false,
          bypassWriteBack = false,
          pessimisticUseSrc = false,
          pessimisticWriteRegFile = false,
          pessimisticAddressMatch = false

        new YamlPlugin("cpu0.yaml")

    )
```

## 4. 수정 파일: `VexRiscvTop.scala`

기존 Top의 플러그인 연결 부분에 신규 플러그인 연결만 추가합니다.

먼저 DBusDecoder의 Store fault 신호를 시뮬레이션에서 확인할 수 있도록 설정합니다.

```scala
dbusDecoder.io.storeFault.simPublic()
```

그리고 기존 `for (plugin <- cpu.plugins)`의 `match`에 다음 case를 추가합니다.

```scala
case p: StoreAccessFaultPlugin =>
  p.storeFault := dbusDecoder.io.storeFault
```

위 case는 `DBusSimplePlugin` case와 별개의 case입니다. 나머지 Top 코드는 그대로 유지하면 됩니다.

## 5. 첫 번째 검증: 컴파일과 Elaboration

아직 ROM이나 시뮬레이션 코드는 변경하지 마세요.

먼저 신규 플러그인이 기존 CPU에 정상적으로 등록되고, DBusDecoder와 연결되는지만 확인합니다.

프로젝트 루트에서:

```
sbt compile
```

그다음 기존 시뮬레이션을 실행합니다.

```
sbt "runMain myvexsoc.VexRiscvTopSim"
```

아직 통과를 확인한 코드는 아닙니다

제가 현재 환경에서 사용자의 로컬 SBT 프로젝트를 직접 컴파일하거나 실행할 수는 없습니다. 
특히 SpinalHDL 플러그인의 포트 생성과 VexRiscv 파이프라인 연결은 실제 Elaboration까지 확인해야 합니다.

이번 단계에서는 컴파일 로그를 먼저 보내주세요. 오류가 있다면 그 오류를 해결한 뒤 다음 단계로 넘어가겠습니다.

컴파일과 기존 GPIO 통합 시뮬레이션이 통과하면, 다음에는 Unmapped Store 전용 ROM 테스트를 추가하겠습니다. 그 테스트에서는 다음을 검증합니다.

- `mcause = 7`
- `mepc = Unmapped Store 명령의 PC`
- `mtval = Unmapped Store 주소`
- Unmapped Store가 RAM/GPIO에 기록되지 않음
- 그 뒤의 명령이 실행되지 않음
- 기존 Unmapped Load의 `mcause = 5` 동작 유지

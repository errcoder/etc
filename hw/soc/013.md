좋습니다. 이제 실제 소스에서 필요한 부분을 확인했습니다. [GitHub](https://raw.githubusercontent.com/SpinalHDL/VexRiscv/baf7dc82f855eddaf5b0a20a6802c526f127e38/src/main/scala/vexriscv/plugin/IBusSimplePlugin.scala)

핵심은 **제가 앞에서 ROM을 직접 `iBus.rsp.valid := cmd.fire`로 만들자고 한 것도 성급했다는 것**입니다.

실제 소스를 보면:

```scala
iBus.cmd << cmd
```

이고,

```scala
c.io.push << iBus.rsp.toStream
```

이며 `c`는:

```scala
new StreamFifoLowLatency(
  IBusSimpleRsp(),
  busLatencyMin + ...
)
```

입니다. 기본 `busLatencyMin`은 1입니다. [GitHub](https://raw.githubusercontent.com/SpinalHDL/VexRiscv/baf7dc82f855eddaf5b0a20a6802c526f127e38/src/main/scala/vexriscv/plugin/IBusSimplePlugin.scala)

그리고 실제 fetch join은:

```scala
join.valid := stages.last.output.valid && rspBuffer.output.valid
```

입니다. [GitHub](https://raw.githubusercontent.com/SpinalHDL/VexRiscv/baf7dc82f855eddaf5b0a20a6802c526f127e38/src/main/scala/vexriscv/plugin/IBusSimplePlugin.scala)

### 따라서 다음 단계

**ROM의 latency를 우리가 임의로 결정하지 말고, 먼저 가장 단순한 response를 연결해서 VexRiscv 내부 FIFO가 실제로 어떻게 받아들이는지 확인하겠습니다.**

그리고 이번에는 debug IO를 새로 만들지 않겠습니다.

현재 Top에서 이미 `InstructionRom`을 연결하고 있으므로, **ROM 자체의 `cmd.fire`와 `rsp.valid`를 simulation에서 관찰하는 것**부터 하겠습니다. 이 신호들은 ROM 자신의 IO이므로 Top-level direction 문제도 없습니다.

즉 다음 단계의 검증 대상은:

```text
InstructionRom.io.cmd.valid
InstructionRom.io.cmd.ready
InstructionRom.io.cmd.pc
InstructionRom.io.rsp.valid
InstructionRom.io.rsp.inst
```

입니다.

이것으로 먼저:

```text
CPU
 ↓
ROM cmd.fire
 ↓
ROM rsp.valid
```

가 실제로 발생하는지를 확인합니다.

**여기서 CPU 내부 신호를 건드리지 않고 ROM 경계만 검사하는 것이 현재 단계에서 가장 안전한 방법입니다.**

다음 답변에서는 이 목적에 맞는 `VexRiscvTopSim`의 **최소 수정본만** 제시하겠습니다.

좋습니다. 이번 단계에서는 **Top-level debug IO를 다시 만들지 않고**, 이미 연결된 `InstructionRom`의 IO만 직접 관찰하겠습니다.

현재 목적은 정확히 이것입니다.

```text
CPU → InstructionRom.cmd.fire
                 ↓
        InstructionRom.rsp
```

그리고 **50 cycle timeout**을 둡니다. 무한 `while`은 사용하지 않습니다.

### `VexRiscvTopSim.scala`

```scala
package myvexsoc

import spinal.core._
import spinal.core.sim._

object VexRiscvTopSim extends App {

  SimConfig
    .withWave
    .compile(new VexRiscvTop)
    .doSim { dut =>

      println("========================================")
      println(" VexRiscvTop IBus Boundary Test")
      println("========================================")

      dut.clockDomain.forkStimulus(period = 10)

      dut.clockDomain.waitSampling(5)

      println("[INFO] Reset/clock startup complete")

      var cmdFireSeen  = false
      var rspValidSeen = false

      for (cycle <- 1 to 50) {

        dut.clockDomain.waitSampling()

        val rom = dut.system.instructionRom

        val cmdValid = rom.io.cmd.valid.toBoolean
        val cmdReady = rom.io.cmd.ready.toBoolean
        val cmdFire  = rom.io.cmd.fire
        val cmdPc    = rom.io.cmd.pc.toLong

        val rspValid = rom.io.rsp.valid.toBoolean
        val rspInst  = rom.io.rsp.inst.toLong
        val rspError = rom.io.rsp.error.toBoolean

        if (cmdValid || rspValid) {
          println(
            f"Cycle $cycle%2d : " +
              f"CMD valid=$cmdValid%-5s " +
              f"ready=$cmdReady%-5s " +
              f"fire=$cmdFire%-5s " +
              f"pc=0x$cmdPc%08X  " +
              f"RSP valid=$rspValid%-5s " +
              f"inst=0x$rspInst%08X " +
              f"error=$rspError%-5s"
          )
        }

        if (cmdFire) {
          cmdFireSeen = true

          assert(
            cmdPc == 0x80000000L,
            f"Unexpected first instruction PC: 0x$cmdPc%08X"
          )
        }

        if (rspValid) {
          rspValidSeen = true

          assert(
            rspInst == 0x00100093L,
            f"Unexpected instruction: 0x$rspInst%08X"
          )

          assert(
            !rspError,
            "Instruction ROM returned an error"
          )
        }

        if (cmdFireSeen && rspValidSeen) {
          println()
          println("[PASS] CPU -> ROM command observed")
          println("[PASS] ROM -> CPU instruction response observed")
          println("========================================")
          println(" IBus boundary test finished")
          println("========================================")
          return
        }
      }

      assert(
        cmdFireSeen,
        "FAIL: No IBus command fire observed within 50 cycles"
      )

      assert(
        rspValidSeen,
        "FAIL: No IBus response observed within 50 cycles"
      )
    }
}
```

### 이 코드에서 실제 검증하는 부분

`cmdFire`가 발생하면:

```scala
assert(
  cmdPc == 0x80000000L,
  ...
)
```

따라서 CPU가 ROM에 첫 instruction을 요청했는지 확인합니다.

그리고 response가 발생하면:

```scala
assert(
  rspInst == 0x00100093L,
  ...
)
```

으로 ROM이 정확히

```text
ADDI x1, x0, 1
```

을 반환했는지 확인합니다.

마지막으로 둘 다 실제 발생해야:

```text
[PASS] CPU -> ROM command observed
[PASS] ROM -> CPU instruction response observed
```

가 출력됩니다.

### 중요한 점

이 테스트는 아직 **CPU가 `ADDI`를 실행해서 `x1=1`이 되었는지 검사하지 않습니다.**

현재 검증 범위는 오직:

```text
CPU
 │
 │ IBus cmd
 ▼
InstructionRom
 │
 │ IBus rsp
 ▼
CPU
```

의 **경계 통신이 실제로 발생하는가**입니다.

그리고 `cmdFireSeen && rspValidSeen`이 되면 즉시 종료하므로, 불필요하게 50 cycle을 계속 돌지도 않습니다.

**이 코드를 실행한 결과를 보여주세요.** 그 결과가 정상인지 먼저 판단한 뒤 다음 단계로 넘어가겠습니다.

좋습니다. 이번에는 **`return` 없이**, 현재 단계에서 필요한 검증만 하는 **전체 `VexRiscvTopSim.scala`**를 제시합니다.

```scala
package myvexsoc

import spinal.core._
import spinal.core.sim._

object VexRiscvTopSim extends App {

  SimConfig
    .withWave
    .compile(new VexRiscvTop)
    .doSim { dut =>

      println("========================================")
      println(" VexRiscvTop IBus Boundary Test")
      println("========================================")

      dut.clockDomain.forkStimulus(period = 10)

      // Reset 후 안정화
      dut.clockDomain.waitSampling(5)

      println("[INFO] Reset/clock startup complete")

      var cmdFireSeen  = false
      var rspValidSeen = false

      // 최대 50 cycle 동안 CPU <-> ROM 통신 관찰
      for (cycle <- 1 to 50) {

        dut.clockDomain.waitSampling()

        val rom = dut.system.instructionRom

        val cmdValid = rom.io.cmd.valid.toBoolean
        val cmdReady = rom.io.cmd.ready.toBoolean
        val cmdFire  = rom.io.cmd.fire
        val cmdPc    = rom.io.cmd.pc.toLong

        val rspValid = rom.io.rsp.valid.toBoolean
        val rspInst  = rom.io.rsp.inst.toLong
        val rspError = rom.io.rsp.error.toBoolean

        // Command 또는 Response가 발생한 cycle만 출력
        if (cmdValid || rspValid) {
          println(
            f"Cycle $cycle%2d : " +
              f"CMD valid=$cmdValid%-5s " +
              f"ready=$cmdReady%-5s " +
              f"fire=$cmdFire%-5s " +
              f"pc=0x$cmdPc%08X  " +
              f"RSP valid=$rspValid%-5s " +
              f"inst=0x$rspInst%08X " +
              f"error=$rspError%-5s"
          )
        }

        // CPU -> ROM command handshake 확인
        if (cmdFire) {
          cmdFireSeen = true

          assert(
            cmdPc == 0x80000000L,
            f"Unexpected instruction PC: 0x$cmdPc%08X"
          )
        }

        // ROM -> CPU instruction response 확인
        if (rspValid) {
          rspValidSeen = true

          assert(
            rspInst == 0x00100093L,
            f"Unexpected instruction: 0x$rspInst%08X"
          )

          assert(
            !rspError,
            "Instruction ROM returned an error"
          )
        }
      }

      println()
      println("========================================")
      println(" IBus Boundary Test Result")
      println("========================================")

      assert(
        cmdFireSeen,
        "FAIL: No IBus command fire observed within 50 cycles"
      )

      assert(
        rspValidSeen,
        "FAIL: No IBus response observed within 50 cycles"
      )

      println("[PASS] CPU -> ROM command observed")
      println("[PASS] ROM -> CPU instruction response observed")

      println("========================================")
      println(" IBus boundary test finished")
      println("========================================")
    }
}
```

### 이번 코드의 검증 범위

50 cycle 동안 매 cycle:

```text
InstructionRom.io.cmd
    valid
    ready
    fire
    pc

InstructionRom.io.rsp
    valid
    inst
    error
```

를 관찰합니다.

그리고 마지막에:

```scala
assert(cmdFireSeen, ...)
assert(rspValidSeen, ...)
```

으로 실제 handshake가 한 번이라도 발생했는지 검사합니다.

또한 `cmd.fire`가 발생한 주소가:

```text
0x80000000
```

인지 검사하고, `rsp.valid`가 발생하면 instruction이:

```text
0x00100093
```

인지 검사합니다.

**이번 코드에는 `return`이 없습니다.**

첨부한 두 파일을 확인했습니다. 기존 코드를 최대한 유지하면서 GPIO 통합 테스트 프로그램으로 교체하겠습니다.

현재 `InstructionRom.scala`는 RAM에 접근한 뒤 Unmapped Load Error를 발생시키고 Trap Error 경로를 검사하는 프로그램입니다. `VexRiscvTopSim.scala` 역시 해당 Trap 테스트에 맞춰져 있습니다. 따라서 ROM 프로그램뿐 아니라 테스트벤치의 예상 주소, Store 개수, Load 개수도 함께 변경해야 합니다.&#x20;

# 1. InstructionRom.scala 교체

새 프로그램은 총 14개 명령어입니다.

| PC           | 명령어               | 기능           |
| ------------ | ----------------- | ------------ |
| `0x80000000` | LUI x10, 0x10000  | GPIO Base 설정 |
| `0x80000004` | ADDI x1, x0, 0x5A | 출력 데이터 준비    |
| `0x80000008` | SW x1, 0(x10)     | GPIO_OUT 쓰기  |
| `0x8000000C` | LW x2, 0(x10)     | GPIO_OUT 읽기  |
| `0x80000010` | SW x2, 0(x0)      | RAM[0]에 저장   |
| `0x80000014` | ADDI x3, x0, 1    | OE 데이터 준비    |
| `0x80000018` | SW x3, 8(x10)     | GPIO_OE 쓰기   |
| `0x8000001C` | LW x4, 4(x10)     | GPIO_IN 읽기   |
| `0x80000020` | SW x4, 4(x0)      | RAM[1]에 저장   |
| `0x80000024` | ADDI x5, x0, 0x33 | RAM 테스트 데이터  |
| `0x80000028` | SW x5, 12(x0)     | RAM[3] 쓰기    |
| `0x8000002C` | LW x6, 12(x0)     | RAM[3] 읽기    |
| `0x80000030` | SW x6, 16(x0)     | RAM[4]에 저장   |
| `0x80000034` | JAL x0, 0         | 무한 루프        |

다음 코드로 교체하세요.

```

package myvexsoc

import spinal.core._
import spinal.lib._
import vexriscv.plugin._

class InstructionRom extends Component {

  val io = new Bundle {
    val cmd = slave(Stream(IBusSimpleCmd()))
    val rsp = master(Flow(IBusSimpleRsp()))
  }

  // ------------------------------------------------------------
  // GPIO test program
  // ------------------------------------------------------------

  val LUI_X10_10000 = B"x10000537"

  val ADDI_X1_X0_5A = B"x05A00093"
  val SW_X1_0_X10   = B"x00152023"
  val LW_X2_0_X10   = B"x00052103"
  val SW_X2_0_X0    = B"x00202023"

  val ADDI_X3_X0_1  = B"x00100193"
  val SW_X3_8_X10   = B"x00352423"

  val LW_X4_4_X10   = B"x00452203"
  val SW_X4_4_X0    = B"x00402223"

  val ADDI_X5_X0_33 = B"x03300293"
  val SW_X5_12_X0   = B"x00502623"

  val LW_X6_12_X0   = B"x00C02303"
  val SW_X6_16_X0   = B"x00602823"

  val JAL_X0_0 = B"x0000006F"

  val NOP = B"x00000013"

  // ------------------------------------------------------------
  // Instruction selection
  // ------------------------------------------------------------

  io.cmd.ready := True

  val instruction = Bits(32 bits)
  instruction := NOP

  switch(io.cmd.pc) {

    is(U"32'h80000000") { instruction := LUI_X10_10000 }

    is(U"32'h80000004") { instruction := ADDI_X1_X0_5A }
    is(U"32'h80000008") { instruction := SW_X1_0_X10 }
    is(U"32'h8000000C") { instruction := LW_X2_0_X10 }
    is(U"32'h80000010") { instruction := SW_X2_0_X0 }

    is(U"32'h80000014") { instruction := ADDI_X3_X0_1 }
    is(U"32'h80000018") { instruction := SW_X3_8_X10 }

    is(U"32'h8000001C") { instruction := LW_X4_4_X10 }
    is(U"32'h80000020") { instruction := SW_X4_4_X0 }

    is(U"32'h80000024") { instruction := ADDI_X5_X0_33 }
    is(U"32'h80000028") { instruction := SW_X5_12_X0 }

    is(U"32'h8000002C") { instruction := LW_X6_12_X0 }
    is(U"32'h80000030") { instruction := SW_X6_16_X0 }

    is(U"32'h80000034") { instruction := JAL_X0_0 }
  }

  // ------------------------------------------------------------
  // One-cycle instruction response
  // ------------------------------------------------------------

  io.rsp.valid := RegNext(io.cmd.fire) init (False)

  io.rsp.inst :=
    RegNextWhen(instruction, io.cmd.fire) init (NOP)

  io.rsp.error := False
}

```

중요: 기존의 IBus 응답 로직은 변경하지 않았습니다. 기존 파일의 one-cycle 응답 구조를 그대로 유지한 것입니다.&#x20;

# 2. VexRiscvTopSim.scala 교체

기존 테스트벤치의 중요한 구조는 유지합니다.

- `waitFallingEdge()`에서 DBus 관찰
- 응답을 명령보다 먼저 관찰
- `valid && ready`로 명령 수락 확인
- CPU 내부 `fire` 신호를 직접 사용하지 않음

기존 코드가 사용하던 DBus 모니터링 방식입니다.&#x20;

VexRiscvTopSim.scala



다음 코드로 교체하세요.

```

package myvexsoc

import spinal.core.sim._
import vexriscv.plugin._

import scala.collection.mutable

object VexRiscvTopSim {

  def main(args: Array[String]): Unit = {

    SimConfig.withWave.compile(new VexRiscvTop).doSim { dut =>

      dut.clockDomain.forkStimulus(period = 10)

      // --------------------------------------------------
      // Constants
      // --------------------------------------------------

      val GPIO_OUT_ADDR = BigInt("10000000", 16)
      val GPIO_IN_ADDR  = BigInt("10000004", 16)
      val GPIO_OE_ADDR  = BigInt("10000008", 16)

      val RAM0 = BigInt("00000000", 16)
      val RAM1 = BigInt("00000004", 16)
      val RAM3 = BigInt("0000000C", 16)
      val RAM4 = BigInt("00000010", 16)

      val GPIO_OUT_EXPECTED = BigInt("0000005A", 16)
      val GPIO_OE_EXPECTED  = BigInt("00000001", 16)
      val GPIO_IN_EXPECTED  = BigInt("A5C369F0", 16)

      val RAM3_EXPECTED = BigInt("00000033", 16)

      val LOOP_PC = BigInt("80000034", 16)

      val MAX_CYCLES = 160

      // --------------------------------------------------
      // External GPIO input
      // --------------------------------------------------

      dut.io.gpioIn #= GPIO_IN_EXPECTED

      // --------------------------------------------------
      // CPU Plugin
      // --------------------------------------------------

      val dbusPlugin = dut.system.cpu.plugins
        .collectFirst { case p: DBusSimplePlugin =>
          p
        }
        .getOrElse {
          throw new RuntimeException("DBusSimplePlugin not found")
        }

      val rom = dut.system.instructionRom

      // --------------------------------------------------
      // Scoreboard
      // --------------------------------------------------

      val stores = mutable.Map[BigInt, BigInt]()

      val loadAddresses = mutable.ArrayBuffer[BigInt]()

      var storeCount = 0
      var loadCount = 0
      var responseCount = 0
      var errorResponseCount = 0

      var loopFetchCount = 0

      // --------------------------------------------------
      // Simulation
      // --------------------------------------------------

      println("========================================")
      println(" VexRiscv GPIO Integration Test")
      println("========================================")

      for (cycle <- 0 until MAX_CYCLES) {

        dut.clockDomain.waitFallingEdge()

        // ==============================================
        // 1. DBus Response
        //
        // Observe response before command.
        // DBusSimpleRsp.ready means response-valid.
        // ==============================================

        val rspValid = dbusPlugin.dBus.rsp.ready.toBoolean

        if (rspValid) {

          val rspData = dbusPlugin.dBus.rsp.data.toBigInt
          val rspError = dbusPlugin.dBus.rsp.error.toBoolean

          responseCount += 1

          if (rspError) {
            errorResponseCount += 1
          }

          println(
            f"Cycle ${cycle + 1}%3d : LOAD RSP " +
              f"data=0x$rspData%08X error=$rspError"
          )
        }

        // ==============================================
        // 2. DBus Command
        //
        // At falling edge, valid && ready represents
        // the command accepted at the preceding rising edge.
        // ==============================================

        val cmdValid = dbusPlugin.dBus.cmd.valid.toBoolean
        val cmdReady = dbusPlugin.dBus.cmd.ready.toBoolean

        if (cmdValid && cmdReady) {

          val address = dbusPlugin.dBus.cmd.address.toBigInt
          val isWrite = dbusPlugin.dBus.cmd.wr.toBoolean

          if (isWrite) {

            val data = dbusPlugin.dBus.cmd.payload.data.toBigInt
            val mask = dbusPlugin.dBus.cmd.mask.toBigInt

            storeCount += 1
            stores(address) = data

            println(
              f"Cycle ${cycle + 1}%3d : STORE " +
                f"addr=0x$address%08X " +
                f"data=0x$data%08X " +
                f"mask=0x$mask%X"
            )

          } else {

            loadCount += 1
            loadAddresses += address

            println(
              f"Cycle ${cycle + 1}%3d : LOAD " +
                f"addr=0x$address%08X"
            )
          }
        }

        // ==============================================
        // 3. Instruction ROM Request PC
        // ==============================================

        val romValid = rom.io.cmd.valid.toBoolean
        val romReady = rom.io.cmd.ready.toBoolean

        if (romValid && romReady) {

          val pc = rom.io.cmd.pc.toBigInt

          if (pc == LOOP_PC) {
            loopFetchCount += 1
          }
        }
      }

      // --------------------------------------------------
      // Verification Result
      // --------------------------------------------------

      println()
      println("========================================")
      println(" GPIO Integration Verification Result")
      println("========================================")

      // 1. GPIO output

      assert(
        dut.io.gpioOut.toBigInt == GPIO_OUT_EXPECTED,
        f"GPIO_OUT expected 0x$GPIO_OUT_EXPECTED%08X, " +
          f"got 0x${dut.io.gpioOut.toBigInt}%08X"
      )

      println(f"[PASS] GPIO_OUT = 0x$GPIO_OUT_EXPECTED%08X")

      // 2. GPIO output enable

      assert(
        dut.io.gpioOe.toBigInt == GPIO_OE_EXPECTED,
        f"GPIO_OE expected 0x$GPIO_OE_EXPECTED%08X, " +
          f"got 0x${dut.io.gpioOe.toBigInt}%08X"
      )

      println(f"[PASS] GPIO_OE = 0x$GPIO_OE_EXPECTED%08X")

      // 3. RAM values

      assert(
        stores.get(RAM0).contains(GPIO_OUT_EXPECTED),
        "RAM[0] did not receive GPIO_OUT value"
      )

      assert(
        stores.get(RAM1).contains(GPIO_IN_EXPECTED),
        "RAM[1] did not receive GPIO_IN value"
      )

      assert(
        stores.get(RAM3).contains(RAM3_EXPECTED),
        "RAM[3] initial Store failed"
      )

      assert(
        stores.get(RAM4).contains(RAM3_EXPECTED),
        "RAM[4] did not receive RAM[3] Load value"
      )

      println("[PASS] RAM[0] = GPIO_OUT value")
      println("[PASS] RAM[1] = GPIO_IN value")
      println("[PASS] RAM[3] = 0x00000033")
      println("[PASS] RAM[4] = RAM[3] Load value")

      // 4. Load addresses

      val expectedLoads = Seq(
        GPIO_OUT_ADDR,
        GPIO_IN_ADDR,
        RAM3
      )

      assert(
        loadAddresses.toSeq == expectedLoads,
        s"Unexpected Load sequence: " +
          loadAddresses.map(a => f"0x$a%08X").mkString(", ")
      )

      println("[PASS] Load address sequence")

      // 5. Response count

      assert(
        loadCount == 3,
        s"Expected 3 Loads, got $loadCount"
      )

      assert(
        responseCount == 3,
        s"Expected 3 Load responses, got $responseCount"
      )

      assert(
        errorResponseCount == 0,
        s"Unexpected Error Responses: $errorResponseCount"
      )

      println("[PASS] Load count = 3")
      println("[PASS] Response count = 3")
      println("[PASS] No Error Response")

      // 6. Store count

      assert(
        storeCount == 6,
        s"Expected 6 Stores, got $storeCount"
      )

      println("[PASS] Store count = 6")

      // 7. Program loop

      assert(
        loopFetchCount >= 2,
        s"Program did not reach/repeat loop: fetch count=$loopFetchCount"
      )

      println(
        s"[PASS] Program loop repeated ($loopFetchCount fetches)"
      )

      println()
      println("========================================")
      println(" GPIO Integration Verification PASS")
      println("========================================")
    }
  }
}

```

# 3. 실행 전 확인

기존 `VexRiscvTop`에 다음 외부 IO가 선언되어 있어야 합니다.

```
val gpioIn  = in Bits (32 bits)
val gpioOut = out Bits (32 bits)
val gpioOe  = out Bits (32 bits)
```

그리고 기존 ClockingArea 연결도 다음과 같아야 합니다.

```
system.gpio.io.gpioIn := io.gpioIn
io.gpioOut := system.gpio.io.gpioOut
io.gpioOe  := system.gpio.io.gpioOe
```

이미 컴파일에 성공한 Top이라면 이 부분은 다시 변경할 필요가 없습니다.

Trap 테스트 보존에 관한 주의: 첨부한 기존 ROM과 시뮬레이션 파일은 별도로 백업해 두세요. 이번 ROM은 GPIO 통합 테스트용이므로 기존 Trap Error 테스트 프로그램을 대체합니다. Trap/MRET 기능 자체를 삭제하는 것은 아니지만, 이번 프로그램은 Trap/MRET 경로를 실행하지 않습니다.

---

제시한 DBusDecoder.scala 코드에서 errorPending 값이 초기화만 되어있고 적절한 시점에 값을 세팅하는 코드는 없는 것 같은데?

---

맞습니다. 다만 코드에 `errorPending`을 설정하는 부분이 있기는 합니다.

```
val errorPending =
  RegNext(unmappedLoadFire) init (False)
```

`RegNext()`는 입력 신호를 한 클럭 지연시켜 레지스터에 저장합니다. 따라서 이 코드는 다음과 같은 동작을 합니다.

1. `unmappedLoadFire`가 `True`가 된 클럭에서 Load 명령이 수락됩니다.
2. 다음 클럭에 `errorPending`이 `True`가 됩니다.
3. 그 시점에 `loadOwner`는 `OWNER_ERROR`가 되어 있습니다.
4. 따라서 다음 조건이 성립하면서 CPU에 에러 응답을 전달합니다.

```
(loadOwner === OWNER_ERROR && errorPending)
```

즉, `errorPending`에 대한 별도의 `:=` 대입문이 없는 것은 의도된 것입니다. `RegNext()` 자체가 레지스터의 다음 값을 결정하기 때문입니다.

다만 이 구현에는 확인해야 할 중요한 부분이 하나 있습니다.

```
val errorPending =
  RegNext(unmappedLoadFire) init (False)
```

이 방식은 `unmappedLoadFire`가 한 사이클 펄스라는 전제에서 동작합니다. 현재 `loadFire`가 `io.cpu.cmd.fire && !io.cpu.cmd.wr`이므로, 명령이 실제로 수락된 순간에만 발생합니다.

따라서 현재 구조에서는 다음과 같이 동작합니다.

| 시점         | unmappedLoadFire | loadOwner    | errorPending | CPU rsp.ready |
| ---------- | ---------------- | ------------ | ------------ | ------------- |
| Load 수락 전  | 0                | NONE         | 0            | 0             |
| Load 수락 클럭 | 1                | ERROR로 갱신 예정 | 0            | 0             |
| 다음 클럭      | 0                | ERROR        | 1            | 1             |
| 응답 수락 후    | 0                | NONE으로 갱신 예정 | 0            | 0             |

결론: 질문하신 부분은 코드 누락이 아닙니다. `RegNext()`가 `errorPending`의 값을 갱신합니다.

다만 실제로는 RAM/GPIO 응답과 에러 응답이 같은 사이클에 겹치지 않는지, 그리고 `loadOwner`가 응답 수락 시점에 올바르게 해제되는지까지 통합 시뮬레이션에서 확인해야 합니다. 특히 이 부분은 CPU의 DBus 명령 수락과 응답 타이밍을 함께 검증하는 것이 중요합니다.

기존 VexRiscv Trap Error Path 검증이 정상적으로 통과했습니다.
로그를 보면 핵심 동작이 모두 확인됩니다.

### 주요 실행 흐름

| Cycle  | 동작                 | 결과                |
| ------ | ------------------ | ----------------- |
| 9      | STORE `0x00000000` | RAM[0] = 1        |
| 15     | LOAD `0x20000000`  | 잘못된 주소 접근         |
| 16     | LOAD RSP           | `error=true`      |
| 19\~28 | Trap Handler FETCH | `0x80000020`부터 실행 |
| 30     | BNE 분기             | `0x8000004C` 진입   |

특히 다음 부분이 중요합니다.

```
Cycle 15 : LOAD addr=0x20000000
Cycle 16 : LOAD RSP data=0x0 error=true
```

잘못된 주소의 Load 요청이 수락된 후 다음 사이클에 에러 응답이 발생했습니다. 
기존 DBusDecoder의 Unmapped Load 에러 응답 경로가 정상적으로 동작하고 있음을 보여줍니다.

### 검증 결과

- RAM 쓰기 정상
- Load Access Fault 요청 정상
- Load Access Fault 응답 정상
- Trap Handler 진입 정상
- BNE 분기 및 Error Loop 진입 정상
- Error Loop 반복 정상 (33회)
- 예상하지 않은 CSR Store 없음
- Trap 이후 원래 프로그램으로 복귀하지 않음

### 다음 단계에서 주의할 점

이 결과는 기존 Trap Error Path가 유지되고 있음을 확인한 것입니다. 다만 새 GPIO 프로그램으로 ROM을 교체하면 이 테스트를 다시 실행할 수 없으므로, 기존 `InstructionRom.scala`와 `VexRiscvTopSim.scala`는 별도로 보관하는 것이 좋겠습니다.

이제 GPIO 통합 테스트에서는 다음을 검증하면 됩니다.

1. CPU의 GPIO_OUT Store 및 Load
2. CPU의 GPIO_OE Store 및 Load
3. 외부 GPIO 입력의 2단 동기화 및 Load
4. GPIO 예약 주소의 Load Access Fault
5. RAM 접근과 GPIO 접근 간 응답 라우팅

앞서 통과한 Trap Error Path는 회귀 테스트 기준으로 남겨 두겠습니다.
